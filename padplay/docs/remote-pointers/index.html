Remote Pointers

日本語

Players point their phone at the screen and a cursor follows; pressing A on the phone clicks the uGUI under the cursor. One cursor per connected player, in the player's color. Your UI code does not change: buttons, toggles, sliders and scroll views get the normal OnPointerEnter / OnPointerDown / OnPointerClick / OnDrag events, the same way the mouse and phone touches reach them (Concepts: Touch).

Use it for menus on the big screen, "point at the screen" mini-games, or any scene where the phone is a remote rather than a touch screen. The Sample Hub and its Target Pop mini-game use it (Quick Start §12).

Minimal steps

  1. Add the component. GameObject → PadPlay → Remote Pointers (or Add Component → PadPlay → Remote Pointers). It finds the scene's PadPlayHost and adds a host, a QR code and an EventSystem if the scene has none.
  2. Choose the layout. Layout is already set to the bundled PadPlayRemoteLayout (Recenter, A, B, −, +, Menu). Keep it, or put your own button layout there. Turn off the host's Video module in this scene: the layout is made for a phone held upright without a picture. Its Orientation is Portrait, so the phone app locks the screen upright and places the buttons on the whole screen.
  3. Done. Press Play and join with a phone (or Window → PadPlay → Virtual Phones: drag the tilt ball and click A).

When a phone joins, the screen and the phone ask the player once to point at the center of the screen and press Recenter. Recenter makes the current direction the center, so the cursor jumps to the middle. It works at any time, e.g. when the cursor has drifted.

The bundled layout

  • A (large) — Press = Gamepad buttonSouth. Presses the UI under the cursor; hold to drag.
  • B — Back = buttonEast. Nothing by itself: read it for "back" (pad.buttonEast).
  • Recenter — Recenter = custom14, Role Recenter. Makes the current direction the center (no code needed).
  • Menu — Menu = startButton. Nothing by itself: read it to return to your menu.
  • − / + — Minus / Plus = leftShoulder / rightShoulder. Nothing by itself: page, zoom, volume…

Because the ids are Gamepad buttons, <Gamepad>/buttonSouth and other existing bindings see them too. PadPlayRemoteLayout.Create() builds the same layout from code.

Knowing who pointed

public void OnPointerClick(PointerEventData eventData)
{
    if (eventData is PadPlayPointerEventData p && p.FingerId == PadPlayRemotePointers.FingerId)
        Debug.Log($"P{p.PlayerSlot + 1} clicked with the remote pointer");
}

Each player's cursor has its own pointerId (PadPlayRemotePointers.GetPointerId(slot)), separate from the mouse and from phone fingers, so two players and the mouse can press different buttons at the same time. From code: remote.GetHovered(slot), remote.IsPressing(slot), remote.TryGetScreenPosition(slot, out pos), remote.TryGetPointer(slot, out gyroPointer) (the PadPlayGyroPointer behind the cursor) and remote.ShowRecenterHint(slot).

Behavior worth knowing

  • Disabled UI. A Selectable with Interactable off stays in its disabled color under a cursor and cannot be clicked (standard uGUI behavior).
  • Selection. A is also the Gamepad's Submit. So that a button is not pressed twice (once by the cursor, once by the input module's Submit), a press clears the EventSystem selection (Clear Ui Selection). Turn it off only if your UI needs the selection.
  • Touches. While the component is enabled, phone touches outside the buttons do not reach uGUI (Block Touch Ui); otherwise a finger beside A would click the game's UI on the screen at the finger's position. TouchReceived still fires.
  • Not pointing. While the phone's direction is unknown (no attitude yet, reconnecting) the cursor is dimmed and presses are cancelled.
  • Screen. Cursors move over the whole Display 1, or over Target Camera's area. Only UI on that screen is hit.
  • Time. Cursors use unscaled time, so they keep working in a paused menu (Time.timeScale = 0).
  • Across scenes. The layout is set per player while the component is enabled and removed when it is disabled; with Keep Across Scenes each scene can have its own Remote Pointers (or none). The direction a player recentered on is kept by the Host, so after a scene change (or when the phone's display rotates) the cursor stays where the phone points instead of jumping to the center.

Tuning

Settings → Pointer is the shared PadPlayGyroPointerSettings: Horizontal / Vertical Range Degrees (how far to swing from edge to edge), Smoothing, Recenter Blend Ms. Cursor Size, Dimmed Alpha, Hint Seconds change the look. All can be changed while playing; the defaults are starting points.

How to hold the phone

Hold the phone like a remote control: flat, with its top edge pointing at the screen. Point at the middle of the screen and press Recenter. With Axis = Auto (default) the pointer aims with the top edge when the phone is held flat and with the back when it is held upright like a window. Twisting your wrist does not move the cursor. By default a swing of about ±20° left/right and ±15° up/down reaches the screen edges (HorizontalRangeDegrees 40, VerticalRangeDegrees 30). Phones have no sensor bar, so the heading slowly drifts over minutes; press Recenter again when the cursor is off. In Virtual Phones, Pitch 90 is the flat (remote) grip.
