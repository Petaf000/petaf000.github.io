PadPlay SDK documentation

日本語

PadPlay SDK turns a phone into a second-screen controller for a Unity game: touch screen, gyro, on-screen buttons, vibration and its own view of the game. Start with the Quick Start; come back here to find a topic.

These pages are inside the package (Packages/dev.petaf.padplay/Documentation~) and online at petaf.dev/padplay/docs. In the Editor, Window → PadPlay → Welcome (it opens once by itself after you import the package) shows the first steps, imports the samples with one click and links to these pages.

You need the separate PadPlay phone app on every player's phone, and the PC and the phones on the same Wi-Fi / LAN (no internet play). See Quick Start §1 for the requirements and the tested setup.

Pages

  • Quick Start — You set PadPlay up for the first time: import, add the Host, connect a phone, read input, samples, troubleshooting.
  • Concepts — You want to know how it works: slots, tokens, encryption, state and reliable messages, touch injection, attitude, video, scenes.
  • Debugging — Something does not arrive, or you want to see what each phone shows.
  • Pose Camera — You want to look around by pointing the phone: the PC renders for the phone's orientation and the phone corrects the remaining turn on screen.
  • Remote Pointers — Players point the phone at the screen to move a cursor and press the UI with A.
  • API Reference — You look for a type, property, method or event.
  • 用語集 / Glossary (Japanese) — You use the Editor in Japanese (Preferences → PadPlay) and want the English term.
  • Changelog — CHANGELOG.md in the package folder: what changed in each version.

Main types

  • PadPlayHost — Add Component → PadPlay → Host. One per scene: connections, players, settings (host.Settings). Keep Across Scenes keeps the phones connected through scene loads.
  • PadPlayQrView, PadPlayStatusView — PadPlay → QR View on a Raw Image, Status View on a Text or a TextMeshPro text.
  • PadPlayPointerEventData — The PointerEventData of phone touches (PlayerSlot, FingerId, PhonePosition).
  • PadPlayPad — The Input System device of each phone (Gamepad + attitude, angularVelocity, custom14…custom31).
  • PadPlayGyroCamera, PadPlayGyroPointer — PadPlay → Gyro Camera / Gyro Pointer.
  • PadPlayPoseCamera — PadPlay → Pose Camera: a camera that follows the phone; the phone hides the video delay.
  • PadPlayRemotePointers, PadPlayRemoteLayout — GameObject → PadPlay → Remote Pointers: a cursor per player that clicks uGUI; the bundled phone layout.
  • PadPlayView — PadPlay → View: stream a camera or RenderTexture to a phone.
  • PadPlayPhoneOverlay — PadPlay → Phone Overlay: uGUI Text, TextMeshPro text and Image that the phone draws over the video, fixed to its screen.
  • PadPlayButtonLayout — Assets → Create → PadPlay → Button Layout: the buttons and sticks on the phone.
  • PadPlayRaycaster — PadPlay → Raycaster: a GraphicRaycaster that ignores transparent pixels.
  • PadPlayDebugOverlay, host.Diagnostics — PadPlay → Debug Overlay; diagnostics from code.

Members of each type: API Reference.

Phone app

Players install the free PadPlay app from Google Play (Android 7.0 or newer). One app works with every PadPlay game. The iPhone version is in preparation. PadPlay SDK (not Lite) also includes the app's source code in the PhoneApp~ folder of the package, so you can build the app yourself or publish it under your own name and icon. See Quick Start §5.
