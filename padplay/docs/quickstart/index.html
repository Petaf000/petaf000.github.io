Quick Start

日本語

Get from an empty Unity project to "my phone controls the game" in about ten minutes, once the PadPlay app is on your phone (step 5).

You will: import the package → add a PadPlayHost → show a QR code → connect the phone app → receive touch, gamepad and gyro input → (optionally) stream a second screen, place on-screen buttons and rumble the phone.

For the ideas behind the design, see Concepts; for the Editor tools, Debugging. All pages: Documentation index.

Window → PadPlay → Welcome (it opens once by itself after you import the package) has the same first steps, imports every sample and opens the Sample Hub with one click, and links to the phone app and these pages.

1. Requirements

  • Unity — Unity 2022.3 LTS (2022.3.62f3) or newer, including Unity 6. See Tested setup.
  • Packages — Installed automatically as dependencies: Input System (com.unity.inputsystem 1.11.2+), uGUI (com.unity.ugui). Nothing else: the connection is the SDK's own PadPlay Link over UDP.
  • Active Input Handling — Project Settings → Player → Active Input Handling = Input System Package (New) or Both.
  • PC (the host) — Windows 10 / 11, in the Editor or a Windows x64 standalone build. macOS and Linux hosts are not tested yet (and send video as JPEG only, see below).
  • GPU (second-screen video only) — H.264 is encoded by Windows Media Foundation (the GPU's hardware encoder when one works, otherwise Windows' software encoder) from Direct3D 11 / 12 without leaving the GPU; Vulkan reads the frame back first (slower). Where H.264 cannot be used (OpenGL, macOS / Linux, Windows without an H.264 encoder) the video is sent as JPEG. Touch, gamepad and gyro do not need a GPU encoder.
  • Render pipeline — Built-in and URP (Universal Render Pipeline). The second-screen video works the same in both, with no setup. HDRP has not been tested yet. The samples' 3D materials are made for the Built-in pipeline; in a URP project the samples switch them to the pipeline's Lit shader at runtime, with nothing to convert. For player builds, run Window → PadPlay → Prepare Samples for URP or HDRP once (Import All Samples does it for you; see Samples).
  • Phone / tablet — Android 7.0 or newer, running the separate PadPlay app (see step 5). The iPhone version of the app is in preparation. A gyroscope is needed only for the gyro features (attitude, Gyro Camera, Pose Camera, Remote Pointers).
  • Network — PC and phone on the same Wi-Fi / LAN. Everything uses one UDP port (7780 by default). Internet play is out of scope.

What you need besides Unity

  • The PadPlay phone app — Every player needs the separate PadPlay app on their phone. One generic app works with every PadPlay game; there is no per-game app. How to get it: step 5.
  • The same Wi-Fi — The PC and the phones must be on the same Wi-Fi / LAN. PadPlay never goes over the internet and needs no internet connection. Guest networks and routers with "AP isolation" (privacy separator) keep devices apart: use a normal home or office network.
  • Windows Firewall — On the first Play, Windows asks whether Unity may use the network: choose Allow on Private networks, and make your Wi-Fi a Private network. Your built game is a separate program and asks again. See Troubleshooting.

Tested setup

  • PC — Windows, NVIDIA GPU (hardware H.264), Direct3D 12
  • Unity — 6000.6 with a phone. 2022.3.62f3 and 6000.0.84f1 pass the same automated tests (Edit Mode and Play Mode, the video on Direct3D 11, the samples)
  • Graphics API — Direct3D 12 with a phone; Direct3D 11, Vulkan and OpenGL Core (JPEG) in automated tests on the same PC
  • Render pipeline — Built-in; URP 17.6 (Unity 6000.6) and URP 14.0.12 (2022.3.62f3) in automated tests
  • Windows builds — Player builds with 2022.3.62f3 (Built-in and URP, Mono and IL2CPP) and 6000.6: QR code, connection and video of the samples
  • Android — Android 10, Samsung Galaxy S9+ (one device)
  • iPhone — Not yet tried on a device with this version (the app builds and passes its encryption tests in automated builds)

Other GPUs' hardware encoders, Windows' software encoder, macOS / Linux hosts, HDRP and other phones may work but have not been tested yet.

What it cannot do (yet)

  • macOS / Linux host — No H.264 encoder there yet: the second screen is sent as JPEG (larger, slower). Not tested.
  • Joining from a web browser — Not in this version: every player needs the PadPlay app. Planned as a free 1.x update.
  • Internet play — Same LAN only (no relay server, no STUN / TURN).
  • HDRP — Not tested yet.
  • Reconnecting after RenewToken() — Weaker than a normal join (no fresh key exchange; see step 4). A key exchange for this case is planned for 1.x.

PadPlay Lite

The free PadPlay Lite edition works exactly like the full version, with these limits: 1 player (Max Players is capped at 1), no second-screen video (PadPlayView and the video encoder are not included; the Video module shows a note and does nothing), two samples (Sample Hub with the Target Pop mini-game, and Minimal; the other samples show as grey cards in the Hub), and no phone app source code. Sections of this page about video, several players or the other samples apply to the full PadPlay SDK only.

2. Import the package

PadPlay comes from the Unity Asset Store. After you buy PadPlay SDK (or get the free PadPlay Lite) with your Unity ID:

  1. Open your project and sign in to the Unity Editor with the same Unity ID.
  2. Window → Package Manager. Choose My Assets (Unity 6: in the list on the left; Unity 2022.3: in the Packages drop-down at the top left).
  3. Select PadPlay SDK (or PadPlay Lite), press Download, then Import.
  4. In the Import Unity Package window keep everything ticked and press Import.

The package goes to Packages/dev.petaf.padplay (an embedded package: it is not under Assets, and the Package Manager lists it as PadPlay in both editions; the Welcome window's title says which edition you have). Unity installs its dependencies, Input System and uGUI, if the project does not have them yet. Then Window → PadPlay → Welcome opens.

PadPlay needs the Input System: Active Input Handling must be Both or Input System Package (New) (step 1). If the project still uses only the old Input Manager (the default for new Unity 2022.3 projects), the Welcome window shows a warning with Set to Both…. Press it and let Unity restart; code that uses the Input Manager keeps working with Both. PadPlay Setup and the Host Inspector show the same warning and button. Unity may also ask by itself whether to enable the Input System backends (Yes in Unity 2022.3, Enable & Restart in Unity 6). If the PadPlay warning is still shown after that, use Set to Both….

Updating: download and import the new version the same way. Samples you imported before stay in Assets/Samples; to get the new version, press Import all available samples and open the Sample Hub in the Welcome window (it offers to remove the old version's samples first, see below).

From PadPlay Lite to PadPlay SDK: import PadPlay SDK into the same project and keep everything ticked in the Import Unity Package window. It has the same package name, so it replaces Lite in place; your scenes and settings stay. The Welcome window's title then reads PadPlay SDK. Press Import all available samples and open the Sample Hub again: the samples go to the same folder as Lite's (Assets/Samples/PadPlay/<version>), so the full versions of Sample Hub and Minimal replace the Lite ones and the other four samples are added. If samples of an earlier version are still in Assets/Samples (for example Assets/Samples/PadPlay Lite), the Welcome window lists them and offers Remove the old samples… (it asks first and moves them to the trash). Leaving both copies gives two assemblies with the same name (Assembly with name … already exists), and Unity stops compiling; if that already happened and the Welcome window is not available (for example in Safe Mode), delete the older folder by hand (for example Assets/Samples/PadPlay Lite) and Unity compiles again. Importing PadPlay Lite over PadPlay SDK does not remove the SDK's files but turns on the Lite limits; import PadPlay SDK again to go back.

3. Add a PadPlayHost

One click: GameObject → PadPlay → PadPlay Setup. It adds, as one undoable step:

  • PadPlay — The PadPlayHost (selected afterwards), with a starter button layout in Buttons → Layout: a left stick, A (buttonSouth) and B (buttonEast). The phone shows them and the code in step 7 works right away. Change them as in step 10.
  • PadPlay UI — A Screen Space – Overlay Canvas (sorting order 100, no raycaster, so it never catches touches) with a QR code (PadPlayQrView, bottom right), its caption (game name and join URL) and a player list (PadPlayStatusView, top left). Move, resize or delete them as you like.
  • EventSystem — Only if the scene has none: an EventSystem with the Input System UI module. An existing EventSystem is left as it is.

If the scene already has a PadPlayHost, nothing is added; the existing host is selected.

By hand (same result):

  1. Create an empty GameObject (for example PadPlay).
  2. Add Component → PadPlay → Host.
  3. If your scene has uGUI, keep (or add) the usual EventSystem. Phone touches are sent through it.

That is all the setup the Host needs. With Auto Start on (default) it starts listening when you press Play.

The Host Inspector

The Inspector is laid out top to bottom as Players → Modules → Debug → Connection (plus a status line while playing). Tick the modules your game uses; each checkbox opens the module's settings right below it. An unticked module is folded and greyed out, and its values are kept. Hover over any field for a short explanation.

Most values can be changed while playing and take effect at once, so you can tune by feel. Fields read only when the host starts are greyed out during Play and marked (locked in Play mode).

Players (Settings.Players)

  • Max Players (default 4; locked in Play mode) — How many phones may join.
  • Resume Hold Seconds (default 60; locked in Play mode) — A phone that drops (Wi-Fi blip, app in background) gets the same player slot back within this time. After it, PlayerRemoved fires.
  • Accept New Players (default on; can change while playing) — Off = new phones are refused as "full"; dropped players can still come back. Same as host.AcceptNewPlayers.
  • Calibrate Yaw On Connect (default on; from the next connection) — On (re)connect, the direction the player faces becomes forward.
  • Create Devices (default on; from the next connection) — Create a PadPlayPad (Gamepad) per player in the Input System.

Modules (Settings.Modules) — the Preset menu next to the header (also the Host's context menu) picks a common set: Touch only, Gyro controller (attitude + buttons) or Second-screen controller (everything). Presets change only the checkboxes.

A disabled module is ignored by the host: its input is dropped (no uGUI events, no TouchReceived / AttitudeReceived / ButtonsReceived, nothing on the pad) and nothing is sent for it (no buttons, no haptics, no video).

Touch (Settings.Touch)

  • Drag Threshold Mode (default EventSystem) — How far a finger moves before a drag starts: EventSystem (same as the mouse), Pixels, or PhoneMillimeters (the same finger movement on any phone; converted per player from the phone's pixel ratio and screen size).
  • Drag Threshold Mm / Px (default 1.5 mm / 10 px) — The distance for the chosen mode. Px is also the fallback when a phone's size is unknown.
  • Raycast Only Player Screen (default on) — A player's touches only hit that player's screen (camera or display area).
  • Alpha threshold — Shortcut to the Alpha Threshold of every PadPlayRaycaster in the scene (touches pass through transparent pixels).
  • Stale Timeout Seconds (default 0) — Release a finger that sends nothing for this long (0 = never).
  • More: Send Ui Events, Click Speed Seconds, Player Targets — uGUI events on/off, double-tap interval, which screen each player touches (step 6).

Attitude (Settings.Attitude)

  • Max Extrapolation Ms (default 150) — How far ahead the attitude is predicted when Wi-Fi packets are late.
  • Correction Ms (default 50) — How quickly the prediction error is blended out (0 = jump).
  • Delay Buffer Ms (default 0) — Deliberate delay to interpolate between packets (smoother, later).
  • Smoothing (default 0) — Extra smoothing of pad.attitude (0 = none, higher = steadier but laggier).
  • Full Style (default KeepGravity) — How a Full recenter defines forward.
  • Recenter Mode (default Yaw) — How a Recenter button or the phone's corner long-press resets forward (step 8).
  • Allow Phone Recenter (default on) — Accept the phone's corner long-press (step 8). Off = only your buttons and code.

Buttons (Settings.Buttons)

  • Layout (default none) — On-screen buttons for every phone (step 10). New creates a layout asset with a stick, A and B.
  • Allow Haptics (default on) — Off = vibration is never sent (a running vibration stops).
  • Haptic Strength Scale (default 1) — Multiplies every vibration strength.
  • Haptic Refresh / Duration / Min Change (default 100 ms / 150 ms / 0.05) — How vibration is resent to the phone (rarely needs changing).

Video (Settings.Video)

  • Codec (default Auto) — Auto = H.264; JPEG for a phone that asks for it (its H.264 decoding is slow), and for everyone when this PC has no H.264 encoder. H264 / Jpeg force one (a forced H264 still falls back to JPEG when this PC has no H.264 encoder).
  • Adaptive Video / Min Kbps / Priority / Min Fps / Min Scale (default on / 300 / Quality / 30 / 0.5) — Lowers the bitrate, then the frame rate or the size, when the Wi-Fi gets worse, and raises them again slowly. Quality keeps the size (frame rate first); Smoothness keeps the frame rate (size first).
  • Total Max Kbps (default 0) — Upper limit for all phones together; each phone gets at most this divided by the players (0 = none).
  • Jpeg Scale / Fps / Quality (default 0.5 / 30 / 75) — The JPEG fallback: size as a fraction of the view's size, frame rate, starting quality (20–90; then it follows the bitrate).
  • Pacing Mbps / Max Playout Frames / Use Ltr Recovery (default 20 / 2 / on) — How fast a frame's pieces are sent (0 = all at once); the most frames a phone waits to smooth uneven arrival (0 = never; it waits only while the arrival is uneven); repair lost video with small recovery frames instead of key frames. Read when the host starts.
  • Prefer Readback (default off) — Copy each frame through the CPU even on Direct3D 11 / 12 (a workaround if the GPU path misbehaves; slower).
  • Views — Every PadPlayView in the scene with its player, size, frame rate, bitrate limit and Match Phone Aspect (step 9). With none, Create a camera and attach adds one.

Module settings may change while playing, except the three Video values marked above. Codec, Adaptive Video and the JPEG values apply when a player's video (re)starts. Turning Video on or off, or changing a View, restarts the affected players' video (from a key frame; the connection and the slot stay).

Debug (folded) — the Display 2 / 3 preview of each phone (Settings.Preview), Open Debugger and Add Debug Overlay. See Debugging.

Connection (folded; usually left alone)

  • Port (default 7780; locked in Play mode) — UDP port for everything (join, input, video). If busy, the next free port is used and put in the QR.
  • Game Name (default product name; locked in Play mode) — Shown on the phone.
  • Host Addresses (default automatic; locked in Play mode) — IP addresses put in the QR. Set when the PC has several network adapters.
  • Loopback Only (default off; locked in Play mode) — Listen on 127.0.0.1 only (tests).
  • Verbose Log (default off; can change while playing) — Logs the connection steps and the join URL to the Console. Handy for the first try.
  • Display Language (default Auto; can change while playing) — Language of the texts players see (QR caption, Status View). Auto = Japanese on Japanese systems, otherwise English.

The editor windows and Inspector tooltips can be shown in Japanese: pick Auto / English / 日本語 at the top right of the Welcome window or in Preferences → PadPlay (Japanese terms: Glossary-ja).

From code the same values are under host.Settings, for example host.Settings.Players.MaxPlayers, host.Settings.SetEnabled(PadPlayModules.Touch, false) or host.Settings.ApplyPreset(PadPlayModulePreset.TouchOnly). Scenes saved with an older version of the SDK are upgraded when loaded (the values move to their new place).

Player numbers are slots starting at 0 (PlayerSlot 0 is "P1" on screen).

4. Show the QR code

PadPlay Setup (step 3) already did this. By hand:

  1. GameObject → UI → Raw Image (any Canvas).
  2. On the Raw Image: Add Component → PadPlay → QR View.
  3. Optional: assign a Text or a TextMeshPro - Text (UI) to Caption to print the game name under the code (Show Uri adds the join URL; it is long, so players paste it rather than type it).

The QR View finds the Host in the scene, redraws whenever the join URL changes and hides itself while the Host is stopped. For an on-screen list of connected players, add PadPlay → Status View to a Text or a TextMeshPro text.

TextMeshPro works wherever PadPlay writes or reads text (QR View Caption, Status View, Phone Overlay), with nothing to set up: it is on by itself when the project has TextMeshPro (built into uGUI 2.x on Unity 6; com.unity.textmeshpro on Unity 2022.3). For Japanese captions, give the TMP text a font asset that has Japanese characters.

The QR code carries the PC's address, the UDP port, a token and a fresh key. The key never travels over the network: the phone uses it to encrypt and authenticate everything it sends and receives, so other devices on the Wi-Fi can neither read nor fake the input or the video. It changes every time the host starts. There is no setting to turn encryption off.

To invalidate the current QR code (for example between matches) call RenewToken(): it makes a new token and key. Phones that already joined stay connected. A joined phone whose Wi-Fi drops shortly after the renewal can still come back to its slot with the old code for host.NetworkSettings.RenewGraceMs (60 s by default, 0 = off); it proves itself with a secret it received when it joined, so a new phone always needs the new QR code. This return is protected by the old code's key and that secret, without a fresh key exchange, so it is weaker than a normal join (a known limitation, to be fixed in 1.x). If you renew the code to keep someone out, set RenewGraceMs to 0.

using PadPlay;
using UnityEngine;

public class Lobby : MonoBehaviour
{
    [SerializeField] PadPlayHost host;

    void OnEnable()
    {
        host.PlayerReady += OnReady;
        host.PlayerLeft += OnLeft;
        host.PlayerRemoved += OnRemoved;
    }

    void OnDisable()
    {
        // Unsubscribe, so a destroyed Lobby is not called (and, with Keep Across Scenes, not kept alive).
        host.PlayerReady -= OnReady;
        host.PlayerLeft -= OnLeft;
        host.PlayerRemoved -= OnRemoved;
    }

    void OnReady(PadPlayPlayer p) => Debug.Log($"P{p.PlayerSlot + 1} ready: {p.Device.Model} (resumed: {p.Resumed})");
    void OnLeft(PadPlayPlayerLeft left) => Debug.Log($"P{left.PlayerSlot + 1} left ({left.Reason}), may come back");
    void OnRemoved(PadPlayPlayerRemoved removed) => Debug.Log($"P{removed.PlayerSlot + 1} is gone ({removed.Reason})");

    public void NewQrCode() => host.RenewToken();

    public void StartMatch() => host.AcceptNewPlayers = false;   // players who drop can still come back
}

5. Connect the phone

  1. Install the PadPlay app on the phone (see Getting the app below).
  2. Press Play in Unity.
  3. On first run Windows may ask whether Unity may use the network: choose Allow (Private networks).
  4. In the app, scan the QR code and tap connect. (Without a camera, copy the join URL from the Debugger, Copy next to Join URI, and paste it into the app.) (The app follows the phone's language: the connect button reads "Connect" in English and 「つなぐ」 in Japanese.)

Getting the app

Every player installs the free PadPlay app from Google Play (Android 7.0 or newer). The iPhone version is in preparation. One app works with every PadPlay game, in PadPlay SDK and PadPlay Lite alike.

Your own app (PadPlay SDK only). PadPlay SDK also includes the app's source code: Packages/dev.petaf.padplay/PhoneApp~/PadPlayPhoneApp-…-source.zip (the folder does not show in the Unity Project window; open it in Explorer). Unzip it outside your Unity project and build it with Flutter (client/README.md in the zip has the steps), or publish it under your own name, app ID, icon and color (WHITE_LABEL.md). PadPlay Lite does not include the source.

No phone at hand? Window → PadPlay → Virtual Phones connects simulated phones in the Editor.

Connected

PlayerJoined fires when the phone is accepted and gets its slot; PlayerReady fires right after it, when input starts flowing (once per join). If it never becomes ready, see Troubleshooting.

A player slot goes through these states (host.GetPlayerState(slot)):

  • Connecting (entered by PlayerJoined) — Slot assigned, input not flowing yet. PlayerJoined.Resumed is true when the same phone came back.
  • Ready (entered by PlayerReady) — Input arrives. GetPad(slot) already returns the player's pad.
  • Reconnecting (entered by PlayerLeft) — The phone dropped; the slot and the pad are kept for Resume Hold Seconds.
  • Gone (entered by PlayerRemoved) — The slot is free for good (bye, stopped, or expired). The pad is already removed: remove the player's character here.

A phone also gets its old slot back when its app was closed and opened again (the app remembers a device id), as long as it comes back within Resume Hold Seconds and did not disconnect on purpose.

host.AcceptNewPlayers = false refuses new phones (they see "full") while letting dropped players resume. host.ScreenRotationChanged / host.GetScreenRotation(slot) tell you when a player turns the phone sideways.

6. Touch arrives as normal uGUI events

You do not need to change your UI code. Touches on the phone are turned into the standard OnPointerDown, OnDrag, OnPointerClick, … events, so Buttons, Sliders, ScrollRects and your own handlers just work — and the mouse keeps working at the same time for debugging.

Only if you want to know who touched, check for PadPlayPointerEventData:

using PadPlay;
using UnityEngine;
using UnityEngine.EventSystems;

public class WhoTouchedMe : MonoBehaviour, IPointerDownHandler
{
    public void OnPointerDown(PointerEventData eventData)
    {
        if (eventData is PadPlayPointerEventData phone)
            Debug.Log($"P{phone.PlayerSlot + 1}, finger {phone.FingerId}, at {phone.PhonePosition} on the phone");
        else
            Debug.Log("mouse / local touch");
    }
}

By default a phone touches the whole of Display 1. To give each player their own screen (split screen, a second display, or a camera that renders into a RenderTexture), point the player at a camera:

host.Touch.SetPlayerTarget(playerSlot: 1, camera: player2Camera);

or fill Touch → More → Player Targets in the Host Inspector. Touches are then hit-tested only against that player's camera (its Canvases and, with a PhysicsRaycaster on the camera, its 3D objects). PhonePosition is where the finger is on the phone screen (0…1, y = 0 at the top); position is the usual pixel position on the target screen.

Transparent parts of images: to let touches pass through the transparent pixels of a sprite, replace the Canvas's GraphicRaycaster with PadPlay → Raycaster and enable Read/Write on the sprite's texture (see Troubleshooting). It works for the mouse too.

7. Read the phone as a Gamepad

Every ready phone becomes a PadPlayPad device in the Input System. PadPlayPad is a Gamepad, so existing bindings like <Gamepad>/buttonSouth and <Gamepad>/leftStick, Gamepad.all and PlayerInput work unchanged. On top of the Gamepad it adds:

  • attitude — <PadPlayPad>/attitude: Quaternion (Unity's left-handed space, calibrated)
  • angularVelocity — <PadPlayPad>/angularVelocity: Vector3, rad/s
  • custom14 … custom31 — <PadPlayPad>/custom20: Button (game-defined buttons, step 10)
  • playerSlot — <PadPlayPad>/playerSlot: Integer (from C#, use pad.PlayerSlot)
  • recenter — <PadPlayPad>/recenter: Button: the player asked to reset forward (step 8). The SDK already re-centers by itself

Reading it directly from C#:

using PadPlay;
using UnityEngine;

public class PadReader : MonoBehaviour
{
    [SerializeField] PadPlayHost host;

    void Update()
    {
        PadPlayPad pad = host.GetPad(0);          // P1, or null if not connected
        if (pad == null || !pad.IsConnected)
            return;

        if (pad.buttonSouth.wasPressedThisFrame)
            Debug.Log("A pressed");
        Vector2 move = pad.leftStick.ReadValue();
        Quaternion attitude = pad.attitude.ReadValue();
        transform.rotation = attitude;
    }
}

Notes:

  • The phone shows buttons and sticks only when the host has a layout (step 10). PadPlay Setup gives the host a starter layout (left stick, A, B); a host added by hand has none, and its Gamepad buttons stay released until you assign one.
  • While a phone is reconnecting, its device is kept (IsConnected == false, buttons released, attitude frozen) so your PlayerInput pairing survives a Wi-Fi blip. It is removed just before PlayerRemoved.
  • The attitude is identity when the phone is held upright in portrait with the screen facing you. On connect the SDK aligns the yaw so "where the player faces now" is forward. To re-center later: host.Recenter(slot) or pad.Recenter() (step 8).

8. Gyro camera and pointer

For the common case you do not need to read the attitude yourself.

Gyro camera — add PadPlay → Gyro Camera to a Camera (or its parent) and set Player Slot. Its starting rotation is "forward". Modes (Settings → Mode, changeable while playing):

  • Window — The phone is a window into the scene: turn the phone, the view turns with it.
  • LookAround — Yaw and pitch only, no roll; sensitivity and pitch limit are adjustable.
  • Tilt — Tilting the phone turns the camera at a speed (like a stick). Tilt (−1…1) is also exposed for moving characters.
var gyroCamera = GetComponent<PadPlayGyroCamera>();
gyroCamera.Mode = PadPlayGyroMode.LookAround;
Vector2 tilt = gyroCamera.Tilt;

Gyro pointer — PadPlay → Gyro Pointer turns the phone into a laser pointer: ViewportPosition (viewport space: y = 0 at the bottom, center = 0.5, 0.5), GetScreenPosition(), GetRay(camera) and an optional Reticle (RectTransform) that follows it.

Naming: the components are called Gyro (what you add), the data is called attitude (AttitudeReceived, pad.attitude, the Attitude module).

All tuning values (sensitivity, smoothing, dead zones, re-center blend time) are in Settings and can be tweaked while playing.

Re-centering ("make this direction forward")

Why it is needed. The phone fuses gyro and accelerometer (Android Game Rotation Vector, iOS Core Motion). Gravity keeps pitch and roll correct, but nothing anchors the heading (yaw), so "forward" slowly drifts over minutes of play (faster near magnets or after quick spins). Restarting the app also changes the phone's yaw reference.

A re-center resets the player's forward everywhere at once: their PadPlayPad attitude and every Gyro Camera / Gyro Pointer reading that player (each blends over its own Recenter Blend Ms, so the view does not jump). Other players are not affected. Recenter Mode Yaw (default) keeps gravity (the horizon stays level); Full makes the whole current pose forward.

Three ways to give players a re-center button — pick one:

  1. No code: a layout button with a role. In your button layout asset, set the element's Role to Recenter (e.g. a Select button labelled "Recenter"). Pressing it re-centers that player. The button still reaches the game as a normal button.
  2. One line of code, e.g. from your pause menu: 
    host.Recenter(playerSlot);                       // Yaw; or host.Recenter(slot, AttitudeCalibrationMode.Full)
host.RecenterAll();                              // everyone
pad.Recenter();                                  // same as host.Recenter(pad.PlayerSlot)
  3. Your own InputAction: bind <PadPlayPad>/recenter. It is pressed while a Recenter role button is held and for one update when the player long-presses the phone's corner. Use it to react (sound, hint); the SDK has already re-centered.

Phone-side fallback. Even without any button, the player can long-press the top-left corner of the phone screen for 1 second (a faint crosshair marks it). The phone sends a recenter request; turn Attitude → Allow Phone Recenter off if your game must not allow it.

Event. host.Recentered tells you who and why (Reason: Code, Button, LongPress, Connect):

host.Recentered += r => Debug.Log($"P{r.PlayerSlot + 1} recentered by {r.Reason}");

gyroCamera.ResetForward() still re-centers that component only. The old Calibrate With Button (Select) option on the Gyro components is now off by default; use a Recenter role button instead.

9. Second screen (video)

To show a picture on the phone — the controller's second screen — add PadPlay → View to any GameObject (or press Create a camera and attach in the Host Inspector's Video module). The Video module must be ticked (it is by default):

  • Source Camera: a camera whose output goes to the phone only (the SDK creates its RenderTexture), or Source Texture: a RenderTexture you render yourself.
  • Player Slot: who sees it (-1 = everyone gets the same picture).
  • Width / Height (default 1280 × 720), Frame Rate (60), Max Bitrate Kbps (0 = 2500). The host lowers the bitrate, frame rate and size from there when the Wi-Fi gets worse (Video → Adaptive Video).
  • Use As Touch Target (on): that player's touches land on this camera's view, so tapping the picture on the phone hits the UI / objects shown in it.

While nobody is watching, the source camera is disabled so it costs nothing.

How the picture is sent. H.264 by default, through Windows Media Foundation (the GPU's hardware encoder when one works). The graphics API decides the path: Direct3D 11 and 12 hand the frame to the encoder without leaving the GPU; Vulkan copies it through the CPU (about one frame later); OpenGL, macOS and Linux have no H.264 path and send JPEG. A phone whose H.264 decoding turns out slow asks for JPEG by itself (Codec = Auto). Lost pieces are repaired with forward error correction; what it cannot repair is fixed with a small recovery frame (when the encoder supports it, Use Ltr Recovery) or else a key frame. host.VideoStatus says which path and encoder are used, or why H.264 cannot be used; host.GetVideoChoice(slot, out choice) tells whether a player gets H.264 or JPEG and why.

Render pipelines. The frame is taken after every camera has drawn it, so overlays drawn by other cameras into the same texture are included. In the Built-in Render Pipeline a hidden camera does this; in URP (and other Scriptable Render Pipelines) it happens at the end of the frame's rendering (RenderPipelineManager.endContextRendering). Nothing to set up either way. In URP the Source Camera must be a Base camera: an Overlay camera only draws as part of its Base camera's stack.

10. On-screen buttons and haptics

Button layout

  1. Assets → Create → PadPlay → Button Layout.
  2. Add Elements. Each element has an Id (South, East, …, DpadUp, Select, Custom14…Custom31, LeftStick, RightStick), a Shape (Circle / Rect; sticks are always sticks), Center and Size, a Label, Opacity, an optional Group and a Role. Center and Size are fractions of the video area on the phone, with (0, 0) at the top-left. When the player has no video, they are fractions of the whole phone screen (inside the safe area). Orientation (on the layout) picks how the phone is held while the layout is shown: Landscape (default), Portrait (locked upright, e.g. a one-handed remote without video) or Auto (not locked). Older phone apps show every layout in landscape. Buttons in the same Group (for example a D-pad or ABXY) let a finger slide from one to the next. Role Recenter makes the SDK reset that player's forward when the button is pressed (step 8); None (default) does nothing extra.
  3. Assign the asset to the Host: Buttons → Layout in the Host Inspector (everyone), or per player with SetLayout. A host placed by PadPlay Setup starts with the bundled PadPlayDefaultLayout (left stick, A, B). Press New next to the field to save an editable copy of it in your Assets (the bundled one is replaced when you update PadPlay).

Editing the asset while playing updates the phones on the next frame, so you can tune positions by feel.

using PadPlay;
using UnityEngine;

var layout = PadPlayButtonLayout.Create(
    new PadPlayButtonLayout.Element(PadPlayButtonId.LeftStick, PadPlayButtonShape.Circle,
        new Vector2(0.15f, 0.7f), new Vector2(0.25f, 0.45f)),
    new PadPlayButtonLayout.Element(PadPlayButtonId.South, PadPlayButtonShape.Circle,
        new Vector2(0.85f, 0.75f), new Vector2(0.1f, 0.18f), "A"),
    new PadPlayButtonLayout.Element(PadPlayButtonId.Custom20, PadPlayButtonShape.Rect,
        new Vector2(0.5f, 0.9f), new Vector2(0.2f, 0.1f), "Map"));

host.SetLayout(0, layout);       // P1 only; null = back to Settings.Buttons.Layout
// After changing layout.Elements from code, call layout.MarkChanged().

The phone app makes every button a little easier to hit: a finger up to 2.5 mm outside a button still presses it (the nearest button wins), and a pressed button lights up and gives a short vibration. This is set in the app, not by the game.

Short taps are not lost: button changes are also sent on the reliable channel, and a press and release that arrive in the same frame are spread over two frames, so wasPressedThisFrame sees every press.

Ids 0–13 map to the matching Gamepad buttons. Any id is read as pad.GetButton(PadPlayButtonId.Custom20).isPressed (or pad.GetButton(20)), and game-defined ids are bound as <PadPlayPad>/custom20.

Button looks

Every element has a Style (fold it open under the element). Left empty, the phone draws its default look. Otherwise:

  • Image — a picture of the button (of a stick: its base), stretched over it. Pressed Image — the picture while pressed (buttons only; empty = Image with the pressed glow around it). Knob Image — the stick's knob (sticks only).
  • Custom Colors — use Color (the fill; of a stick: its base), Pressed Color, Border Color and Label Color instead of the default white and amber. They start at the default look, so tick it and change only what you need. Alpha is multiplied by Opacity.
  • Custom Sizes — Border Width, Corner Radius (Rect buttons) and Label Size, as shares of the element's short side. Label Size 0 hides the label, for pictures that already have the text.

How pictures reach the phone:

  • Any imported Texture2D works. When the layout is sent, the PC encodes each picture as PNG. With Read/Write on in its import settings it is read on the CPU; otherwise it is copied through the GPU. Set Compression to None for the crispest picture.
  • The phone draws pictures at most 1024 px on the long side, so larger ones are scaled down before sending. A picture still over 256 KB as PNG is halved until it fits (a warning says so). A layout can use up to 64 pictures and 2 MB in total; pictures beyond that are not sent (a warning says so) and those buttons are drawn with their colors.
  • When a phone connects, it asks only for the pictures it does not have yet and keeps them (per game, in the app's cache). The next time, the buttons show their pictures at once and nothing is sent again. Until a picture arrives (about 100 KB per second, next to the input, which is never held up), the button is drawn with its colors.
  • Transparency is kept, so a round picture with transparent corners looks round. Older phone apps ignore styles and show the default look.
  • Virtual Phones fetch the pictures the same way as a phone, and the Game view's player preview (Settings → Preview) shows them too.
  • Changing a style in the Inspector while playing resends the layout. After changing a texture's pixels from code, call layout.MarkChanged().
var crystal = new PadPlayButtonStyle { Image = zoomTexture, PressedImage = zoomPressedTexture };
var plank = new PadPlayButtonStyle { Image = woodTexture, CustomColors = true, LabelColor = new Color(1f, 0.95f, 0.84f) };
var layout = PadPlayButtonLayout.Create(
    new PadPlayButtonLayout.Element(PadPlayButtonId.South, PadPlayButtonShape.Circle,
        new Vector2(0.88f, 0.76f), new Vector2(0.17f, 0.3f), style: crystal),
    new PadPlayButtonLayout.Element(PadPlayButtonId.Select, PadPlayButtonShape.Rect,
        new Vector2(0.13f, 0.88f), new Vector2(0.2f, 0.14f), "Recenter", role: PadPlayButtonRole.Recenter, style: plank));

The Floating Island sample uses exactly this (Layouts/FloatingIslandButtons, pictures in Textures/FloatingIsland). The Minimal sample shows the same without any code: its layout file Layouts/MinimalButtons gives A two pictures (Textures/Minimal) and the stick its own colors, and MinimalPad.cs reads them as before (buttonSouth, leftStick).

Haptics

PadPlayPad implements the Gamepad rumble API and forwards it to the phone's vibration motor:

pad.SetMotorSpeeds(0.6f, 0.6f);   // strength = max(low, high); phones have one motor
pad.SetMotorSpeeds(0f, 0f);       // stop

PauseHaptics, ResumeHaptics, ResetHaptics and InputSystem.ResetHaptics() work as usual. The vibration continues until you set it to zero (and stops by itself shortly after the Host stops).

Without the Input System (or with Players → Create Devices off), use the Host:

host.SetHaptics(playerSlot: 0, strength: 0.6f);   // same throttling as SetMotorSpeeds
host.SetHaptics(playerSlot: 0, strength: 0f);     // stop

For a single buzz of a set length (a hit, a pickup), use Pulse. The phone times it itself, so a hitch in the game does not stretch or cut it, and you do not have to send 0 afterwards. A continuous vibration keeps running: the phone plays the pulse on top and goes back to it when the pulse ends.

host.Pulse(playerSlot: 0, durationMs: 250, strength: 1f);   // false if the player is away or haptics are off

The phone app caps one vibration at 1 second. Older phone apps play a pulse like a SetHaptics command (a running continuous vibration then cuts it short).

11. Troubleshooting

For seeing what each phone shows and what arrives from it — the Display 2 / 3 preview, Window → PadPlay → Debugger and an in-game overlay — see Debugging.

Cannot connect? Open Window → PadPlay → Connection Check. It checks the items below in this order, says what it found and what to do next, and gives you commands to copy. It only reads: it never changes the firewall, the network or the host. Copy report puts the result on the clipboard (handy for a bug report; it contains no token or key). Network and firewall are checked at any time; the port and the connection attempts while playing. The Welcome window (Window → PadPlay → Welcome) has a short list of the usual causes under Trouble connecting?, with buttons that open Windows' own settings pages (they only open them).

  1. Host. A PadPlayHost is in the scene, running, and Connection → Loopback Only is off. → No host: GameObject → PadPlay → PadPlay Setup. Not running: turn on Auto Start or call host.StartHost().
  2. Network and QR address. The QR code lists this PC's IPv4 addresses; the phone tries them in order. The first one should be on your Wi-Fi or Ethernet adapter, and the phone must be on that same network (not a guest network, no "AP isolation" / privacy separator on the router). The phone's IP address (in its Wi-Fi settings) should start like the PC's, for example both 192.168.1.. → A virtual adapter (Hyper-V, WSL, VirtualBox, VMware, Docker) or a VPN (Tailscale, Radmin, ZeroTier, …) comes first, or the QR has no Wi-Fi address: put your Wi-Fi IP in Connection → Host Addresses (or disable that adapter). An address that is no longer this PC's: fix or clear Host Addresses (empty = automatic).
  3. Listening port. The host listens on UDP port 7780 (Connection → Port; if it is busy, the next free port is used and put in the QR). → Nothing listens: stop and press Play again and look for PadPlay errors in the Console.
  4. Windows Firewall — for the Unity Editor, and for your built game (the last Windows build location) if there is one. They are separate programs and each needs permission. Permission is per program, not per port (everything uses one UDP port).
    • Allowed: fine.
    • No rule yet: Windows asks on the first connection; choose Allow on Private networks. If it never asked, or you missed it, see Windows never asked below.
    • Blocked: someone pressed Cancel on that dialog, which creates a Block rule — Block rules win over Allow rules. Disable it in Windows Defender Firewall → Advanced settings → Inbound Rules (the rule for Unity.exe / your game's exe), then allow the program.
    • This network is Public and the program is not allowed on Public networks: phones read the QR code, then stop here. Windows' prompt allows Private networks only (unless Public is ticked too) and leaves a Block rule for Public. Make the Wi-Fi a Private network (Settings → Network & internet → Wi-Fi → your network → Private network), or tick Public for the program in Allow an app through firewall.
    • Only TCP allowed: nothing gets through (PadPlay uses UDP); allow UDP or all protocols.
    • Could not read: check by hand in Windows Security → Firewall & network protection → Allow an app through firewall.

    The commands it offers (run them yourself in an administrator Command Prompt / PowerShell):

    netsh advfirewall firewall add rule name="PadPlay Unity Editor" dir=in action=allow program="C:\Program Files\Unity\Hub\Editor\<version>\Editor\Unity.exe" enable=yes profile=private
    Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private

    Without administrator rights the check cannot tell TCP rules from UDP rules; it then says so.

  5. Last connection attempt — what reached the host since it started (also host.Diagnostics.LastJoinAttempt):
    • Nothing reached this PC — The phone's connection never arrived. Next: Same Wi-Fi (2), the QR address (2), the firewall (4).
    • Old QR code — The phone used a code from an earlier Play or from before RenewToken() (its token or key does not match). Joined phones get a grace period after RenewToken() (step 4); new phones do not. Next: Scan the QR code that is on screen now.
    • Full — All Max Players slots are taken, or Accept New Players is off. Next: Raise Max Players or accept new players.
    • Other protocol version — The phone app and the SDK do not match. Next: Update the app (or the SDK).
    • Joined — The join worked.

The Debugger (Window → PadPlay → Debugger) has a Check button next to the join URL that opens the same window, and its Events list shows every refused join (JoinRejected). Verbose Log prints the connection steps and the join URL to the Console.

Windows never asked, or you missed the prompt. The Windows Security Alert does not always appear (it can also open behind other windows), and once it is answered it is not asked again. Allow the program by hand (no administrator command is needed):

  1. Windows Security → Firewall & network protection → Allow an app through firewall (or the button of the same name under Trouble connecting? in the Welcome window), then Change settings.
  2. Find the Unity Editor (Unity 6000.x Editor) or your game and tick Private, and Public too if your network is Public.
  3. Not in the list: Allow another app… → Browse…, pick Unity.exe (or your game's .exe), Network types… → tick Private (and Public), Add.

Then make sure the network is Private: Settings → Network & internet → your Wi-Fi → Properties.

Still cannot connect: other usual causes.

  • A VPN, or antivirus software with its own firewall: Windows' settings do not apply to it. Turn the VPN off and allow the Unity Editor / your game in that software.
  • iPhone: allow Local Network for the PadPlay app (Settings → Privacy & Security → Local Network).
  • Office and school networks often stop devices from reaching each other. Try a home Wi-Fi.

Touch ignores transparent pixels / "texture is not readable" warning. PadPlayRaycaster needs to read the sprite's pixels. Enable Read/Write in the texture's import settings (Advanced → Read/Write); for sprites in a Sprite Atlas enable it on the atlas. Unreadable textures fall back to rectangle hit-testing.

Touches hit the wrong UI. A player with a camera target only hits that camera's view. Check Touch → More → Player Targets and PadPlayView.UseAsTouchTarget. RaycastOnlyPlayerScreen = false restores "hit whatever is in front".

Video is black, slow or blurry.

  • Use Direct3D 11 / 12 (fastest) or Vulkan (one frame later). OpenGL, macOS and Linux send JPEG only.
  • The hardware encoder is tried first, then Windows' software encoder (slower). Only NVIDIA's hardware encoder has been tested so far.
  • The Inspector and host.VideoStatus say which path and encoder are used, or why H.264 cannot be used (then JPEG is sent); host.GetVideoChoice(slot, out choice) tells which one a phone gets and why (for example, the phone asked for JPEG).
  • On a weak Wi-Fi keep Adaptive Video on (it lowers the bitrate, then the frame rate or size), pick the Priority you prefer, or lower the view's Max Bitrate Kbps. A view sent to several players is encoded once, at the quality of the weakest connection.
  • Black even in the Display preview: the source camera or RenderTexture. In PadPlay Lite there is no video.

"Forward" is off after the player restarts the app. That is expected (the phone's yaw reference changes, and yaw slowly drifts during play). Re-center (step 8): a layout button with Role Recenter, host.Recenter(slot), or the player long-presses the top-left corner of the phone screen.

The phone does not vibrate. Check that Buttons is ticked and Allow Haptics is on (vibration belongs to the Buttons module) and that Haptic Strength Scale is above 0. On the phone, the system vibration setting or Do Not Disturb can silence it. The Debugger's Events list shows HapticSent when the host sent a vibration.

12. Samples

The quickest way: Window → PadPlay → Import All Samples (or Import all available samples and open the Sample Hub in the Welcome window). It imports every sample into Assets/Samples, adds their scenes to the Build Settings and opens the Sample Hub. To import one sample: Package Manager → PadPlay → Samples → Import, then open its scene.

  • Sample Hub (start here) — Scenes/Hub. A menu for every sample. Scan the QR code once, point the phone at a card and press A; Menu on the phone or Esc on the PC comes back, still connected (Keep Across Scenes, Remote Pointers). Includes the mini-game Target Pop (Scenes/HubTargetPop). In PadPlay Lite too.
  • Minimal (the one to copy) — Scenes/Minimal. The shortest PadPlay game: one script of about 35 lines (Scripts/Minimal/MinimalPad.cs). Join with the QR code, press A on the phone to make it buzz, tilt the phone to turn a model, push the stick (pad.leftStick) or drag on the phone (a normal uGUI IDragHandler) to move a dot. Everything else is components in the scene. Its layout file (Layouts/MinimalButtons) also shows button looks with no code: A is drawn with two pictures and the stick in its own colors. In PadPlay Lite too.
  • Treasure Map (mini-game) — Scenes/TreasureMap. Two screens, one hunt: walk on the screen with the keyboard while each phone is a paper-style treasure map with only that player's X. Per-player second screen, haptics, choosing modules. The best way to see what PadPlay is for.
  • Floating Island (mini-game) — Scenes/FloatingIsland. Aim on the screen, look through the phone, shoot with the PC keys: each phone is a zoom lens (PadPlayPoseCamera; its crystal button zooms further in) and the screen shows a glowing ring where it points. Find five lights that only phones can see. PadPlayPoseCamera, PadPlayPhoneOverlay (a crosshair), host.Pulse, buttons drawn with the game's own pictures, PC keys and phones together. Up to two players; needs a layer named PhoneOnly at index 8 (see below).
  • Gyro Window — Scenes/GyroWindow. Two players look into a 3D room through their phones, each with their own picture (PadPlayGyroCamera + PadPlayView). Point the phone at the screen and press Recenter to start.
  • Room Dive — Scenes/RoomDive. 2 players only (one PC + one phone): asymmetric co-op in four colored rooms. The phone player picks a room with the phone's arrow buttons and says which one they are in; click a star in that room to show it to them for a few seconds; they look around with the phone and drag the star to the exit. Touch on 3D objects as standard events, a camera layer the phone does not draw, PadPlayPhoneOverlay, haptics.

In a URP project. Treasure Map, Floating Island and Room Dive use the Built-in Standard shader for their 3D objects, which URP draws pink. So when a Scriptable Render Pipeline is active, each sample switches its own renderers, when Play starts, to copies of those materials on the pipeline's Lit shader (color, main texture, smoothness, metallic, emission and transparency are copied); nothing needs converting to play in the Editor. Gyro Window and Minimal use Unlit/Color, which URP draws as is.

Player builds in URP: one menu, once. A build only includes the shaders that its materials use, so the samples also need Lit materials in the build. Choose Window → PadPlay → Prepare Samples for URP or HDRP after importing samples: it fills each sample's small <Sample>SrpLitSet asset (in its Materials folder) with Lit materials (in a <Sample>SrpLit folder next to it). The sample's scene refers to that asset, so the Lit shader goes into the build with the scene. Import All Samples (and the Welcome window's Import all available samples and open the Sample Hub) runs it for you. Run it again if you import a sample one by one later or switch the project to another pipeline; when everything is ready it writes nothing. Nothing runs on its own when scripts reload or before a build, and project settings such as Always Included Shaders are not touched. Without it the samples still play in the Editor, but in a player build their Standard objects are not drawn, and the player log points to this menu. The material assets are not changed, and in a Built-in project the menu does nothing (the assets stay empty). If you want to edit the materials in a URP project, you can still convert them with Edit → Rendering → Materials → Convert Selected Built-In Materials to Current SRP (avoid Convert All… if your project has Built-in materials you want to keep). The samples' scripts set both _Color and _BaseColor, so highlights work either way. HDRP has not been tested.

Sample Hub and Target Pop

Open Scenes/Hub and press Play. The screen shows a card for each sample. Scan the QR code once, point the phone at a card and press A to open that sample (the mouse works too). The phones stay connected while the scenes change: the Hub's Host has Keep Across Scenes ticked (Concepts: Across scenes). In a sample, the small Menu button on the phone or Esc on the PC returns to the Hub. A grey card means that sample is not imported yet (or, in PadPlay Lite, that it comes with PadPlay SDK only). The cards of Target Pop, Treasure Map and Floating Island are marked MINI-GAME.

Target Pop is a small pointer game in the Hub: targets appear on the screen and fade; point the phone at one and press A to pop it. Each pop is a point for that player and a short vibration. Rounds last 30 seconds; 1 to 4 players. It shows Remote Pointers: the targets are plain uGUI objects with IPointerClickHandler, and PadPlayPointerEventData.PlayerSlot tells who popped them.

Treasure Map (two screens, one hunt)

Open Scenes/TreasureMap and press Play. The screen (Game view) shows an island seen from above; each phone becomes an old paper-style treasure map that only its player sees. You need both screens: you walk on the screen, and the map is in your hand.

How to play

  • Scan the QR code with one or two phones. A round starts when the first phone joins and lasts 150 seconds.
  • Walk on the screen with the keyboard: P1 (the first phone) uses WASD, P2 uses the arrow keys (or the left stick of a gamepad connected to the PC). The phone has no buttons and takes no touch: just hold it.
  • The map shows the island's landmarks (shore, pond, trees, rocks, pier), a compass and your treasure (X), but not where you are. Match the landmarks with the island on the screen to work out where to go. Nobody else sees your X, neither on the screen nor on their phones.
  • Trees, rocks, the pond, the sea and the other player block your way.
  • The map buzzes softly when you are near your treasure and strongly when you find it (just walk onto it). The spot is marked as found and a new X is drawn somewhere else. The player with the most treasures wins the round.
  • There is no way to play without a phone: the maps exist only on the phones. To see them in the Editor, use the Display 2 / 3 preview (Debugging).

What it shows

  • Per-player second screen — Each player's phone UI (a camera that sees only the UI layer, sent by a PadPlayView) shows the paper map with that player's own X; the screen camera leaves the UI layer out
  • A map drawn from the scene — TreasureMapLandmark on each island object; TreasureMapPaper draws the paper, ink and burnt edges into a texture at run time (no image files)
  • Haptics without the Input System — host.SetHaptics(slot, strength)
  • Choosing modules — Buttons and Video ticked, with no button layout (haptics belong to the Buttons module); Touch and Attitude unticked

All feel values (walking speed, how near counts as "found", vibration strengths, round length, whether the map shows your own position: Show Self On Map) are in TreasureMapGame → Settings and can be changed while playing.

Floating Island (aim on the screen, look through the phone)

Open Scenes/FloatingIsland and press Play. The screen (Game view) shows the whole floating island, slowly circling it; each phone is a zoom lens into the same world, in the direction the player points it (Pose Camera), and the PC keys shoot. You need all three: the screen to find where to look, the phone to see what is there, the keyboard to act. Up to two players; one person can play alone with the phone in one hand and the keyboard at the other.

Before you play. The hidden lights are on layer 8, which the screen camera leaves out. Name layer 8 PhoneOnly in Project Settings → Tags and Layers. Layers work by number, so the sample runs without the name, but it logs a warning once per Play, and objects of your own on layer 8 are hidden from this sample's screen.

How to play

  • Scan the QR code with one or two phones. The QR board on the screen shows while more players can join.
  • Point the phone at the island. A glowing ring in your player color moves over the island on the screen: the inside of the ring is roughly what your phone shows, zoomed in. A crosshair marks the middle of the phone screen.
  • Shoot with the PC keys: P1 Space, P2 Enter (or the south button / right trigger of a gamepad connected to the PC, in the order they were plugged in). The shot goes through the crosshair. P1 R, P2 Backspace (gamepad: Select) make the direction the phone faces now the front.
  • The phone also has two buttons, drawn with the sample's own pictures: the crystal zooms the lens in (press again to zoom back out; the phone shows Zoom x2.5) and the wooden plank makes the direction the phone faces now the front. The phone does not shoot, and touch does nothing: the rest of the phone is the lens.
  • Shoot something to inspect it: its name shows on your phone and it glows in your player color for a moment; the phone buzzes softly.
  • Five lights are hidden around the island, and only phones can see them. On the screen they give themselves away only by faint sparks: find a spot on the screen, then check it through the phone. Shoot a light to find it: the phone buzzes strongly and the light appears on the screen too. The screen shows how many were found and what each player shot last.
  • When all five are found, a short celebration plays (a beam of light, spiraling pieces, flowers); after 20 seconds the lights hide again. They also hide again when everyone leaves.
  • Without a phone, use simulated phones (Window → PadPlay → Virtual Phones; right-drag on a phone's screen to turn it) and the keyboard as usual.

What it shows

  • Pose Camera — PadPlayPoseCamera + PadPlayView on each player's camera: the PC renders for the phone's orientation and the phone corrects the turn made since that frame. Its field of view is the zoom of the lens
  • Aiming through the phone from the PC — FloatingIslandGame.Shoot casts a ray through the middle of the Pose Camera (the phone shows the picture turned to its current orientation, so the camera's current forward is the crosshair)
  • Where each phone points, on the screen — FloatingIslandAim draws a ring where that ray meets the island, sized to what the lens shows; FloatingIslandFrustum draws the view frustum. Both draw on a layer the phone cameras leave out (UI), so only the screen shows them
  • Hints only the screen shows — FloatingIslandHints draws faint sparks around lights not found yet, on the same UI layer
  • Text and a crosshair fixed to the phone screen — PadPlayPhoneOverlay: the phone draws them over the video, so they do not move with the correction; its rectangle follows VisibleViewportRect
  • Haptics of a set length — host.Pulse(slot, durationMs, strength) (the phone times it)
  • Objects only phones see — Layer 8 (PhoneOnly) is left out of the screen camera; a found light moves to Default
  • Recentering from code — host.Recenter(slot) on R / Backspace; the Pose Camera follows it
  • PC keys and phones together — FloatingIslandControls reads every keyboard and the PC's gamepads (the phones' PadPlayPads are skipped)
  • Button looks — Layouts/FloatingIslandButtons: the crystal Zoom button has a picture and a pressed picture (FloatingIslandControls toggles the zoom on its press), the Recenter plank (Role = Recenter, no code) a picture with its own label color (Button looks)
  • Choosing modules — Attitude, Buttons and Video ticked; Touch unticked; Max Players 2

All feel values (the lens zoom, normal and with the crystal, vibration strengths and lengths, how long names and highlights stay, the celebration length) are in FloatingIslandGame → Settings and can be changed while playing. The keys are on FloatingIslandControls, the ring and the sparks on FloatingIslandAim and FloatingIslandHints, the screen camera's turning speed on FloatingIslandOrbit.

Room Dive (2 players only: one at the PC, one with a phone)

Package Manager → PadPlay → Samples → Room Dive → Import, then open Scenes/RoomDive. It needs exactly two people: one at the PC with the mouse, who sees the rooms from above, and one with a phone (the Diver), who is inside a room. It cannot be played alone, and a second phone is refused (Max Players 1). Until the phone joins, the screen says so. The screen shows four small rooms from above (Red, Blue, Green, Purple). The phone is a window from inside the room the Diver is in, and the phone decides the room: the screen does not show where the Diver is.

How to play

  • The Diver scans the QR code and dives into the first room. The phone shows the room's name in large letters (RED ROOM).
  • The Diver says which room they are in ("I'm in the red room!"). The arrow buttons < / > on the phone change to the previous / next room that still has stars.
  • Stars are drawn only on the screen. The Diver's phone does not show them.
  • Click a star in the Diver's room to show it to them: the Diver's phone shows that star for a few seconds (it blinks and fades at the end). Tell each other where it is ("on the shelf to your right!"). A click never moves the Diver: a star in another room is not shown, and that room's label says The phone player is not here for a moment.
  • The Diver tilts the phone to look around, touches the shown star and carries it into the yellow exit frame to collect it (a star being carried stays visible). The phone buzzes when a star is shown, softly when a shown star is near the center of the view, and strongly on a collect.
  • When a room is empty, the Diver moves on to the next room with stars by itself.
  • Collect all stars in the four rooms to start the next round. Select ("Recenter", Role Recenter) re-centers the view. If the phone drops, its room is kept and the PC player waits until it reconnects.

What it shows

  • Per-player second screen — PadPlayView + PadPlayGyroCamera (Window mode) on the Diver's camera.
  • Something only the screen shows — Stars that are not shown yet are on the built-in UI layer (5), which the Diver's camera leaves out of its culling mask. PhysicsRaycaster also uses the culling mask, so the phone cannot touch them either. No extra layer is needed.
  • Touch on 3D objects as standard events — RoomDiveStar implements only IBeginDragHandler / IDragHandler / IEndDragHandler; the camera has a PhysicsRaycaster.
  • Who touched — eventData is PadPlayPointerEventData p → p.PlayerSlot (RoomDiveGame.CanCarry); the mouse never carries stars.
  • The mouse on the screen — RoomDiveGame finds the room by Camera.pixelRect and the nearest star by WorldToScreenPoint.
  • Text fixed on the phone screen — PadPlayPhoneOverlay with RoomDivePhone (the room's name in large letters, what to do now, the stars).
  • Buttons — Layouts/RoomDiveButtons: Recenter = Select with Role Recenter, and < / > = DpadLeft / DpadRight, read by RoomDiveGame with pad.GetButton(id).wasPressedThisFrame (the Buttons module also carries haptics).
  • Haptics — pad.SetMotorSpeeds(strength, strength).
  • Player states — host.GetPlayerState(slot): anything but Gone keeps the room, so a dropped Diver is waited for.
  • QR and status — PadPlayQrView (hidden once the phone joined) and PadPlayStatusView.

All feel values (how long a shown star stays visible and fades, the click radius on the screen, how long the not here notice stays, vibration strengths, the angle that counts as "near", carry distance, the delay before the next round, and Show Phone Player On Screen to show the Diver's head and room on the screen) are in RoomDiveGame → Settings and can be changed while playing.
