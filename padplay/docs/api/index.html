API Reference

日本語

The types and members you use in a game. Everything is in the namespace PadPlay (using PadPlay;). The Inspector tooltips and the XML comments (IntelliSense) say the same in more detail. Guides: Quick Start, Concepts, Debugging.

A few types come from the engine-independent core assembly (AttitudeCalibrationMode, ClockSync, DeviceInfo, PadPlayPhoneOverlayItem, PadPlayNetworkSettings, PadPlayVideoCodecChoice); they are in the same namespace PadPlay.

Player numbers are slots starting at 0 (playerSlot 0 is "P1" on screen). Events are raised on the main thread.

Errors and exceptions. A mistake in what you pass throws at once and changes nothing: ArgumentNullException for a missing object, ArgumentOutOfRangeException for a negative slot given to a method that keeps something for that slot (SetLayout, SetPhoneOverlay, Touch.SetPlayerTarget), ArgumentException for a value the method does not take (an overlay list out of shape, a recenter mode other than Yaw / Full). A call that only depends on what is happening right now never throws: while the host is stopped, or when nobody is on the slot, the phone cannot vibrate or has no video, methods that return bool return false (Pulse, SetHaptics, Recenter, Kick, TryGet…) and the others return null, None, 0 or an empty list (GetPad, GetClockSync, GetCapabilities, RenewToken while stopped). Numbers with a natural range (strength 0 to 1, pulse length) are clamped. The one call that can fail because of the computer is StartHost(): it throws InvalidOperationException when no UDP port can be opened, and IsRunning stays false. An exception thrown by your own event handler is logged and the host keeps running.

PadPlayHost

Add Component → PadPlay → Host (or GameObject → PadPlay → PadPlay Setup). One per scene.

Starting and the QR code

  • Settings — All Inspector values (PadPlayHostSettings): Players, Modules, Touch, Attitude, Buttons, Video, Preview, Port, GameName, HostAddresses, LoopbackOnly, VerboseLog, DisplayLanguage; IsEnabled(module), SetEnabled(module, on), ApplyPreset(preset).
  • AutoStart — Start listening in Start (default on). Off: call StartHost() yourself.
  • StartHost(), StopHost() — Start / stop. Stopping disconnects every phone (PlayerLeft, then PlayerRemoved with reason stopped).
  • IsRunning, Port — Whether the host listens; the UDP port actually used (0 when stopped).
  • JoinUri, JoinUriChanged — The URL in the QR code (null when stopped) and the event when it changes.
  • RenewToken() — A new token and key (a new QR code); joined phones stay. Returns the new JoinUri (null while stopped).
  • AcceptNewPlayers — Off: new phones are refused as "full"; dropped players can still come back.
  • KeepAcrossScenes — Keep the phones connected through scene loads (Concepts).
  • KeptHost (static), ActiveHost — The Host kept across scenes; the Host that actually runs (the kept one, or this).
  • NetworkSettings — Advanced connection values (PadPlayNetworkSettings), read on StartHost (for example RenewGraceMs).
  • SdkVersion, ProtocolVersion, NowMs (static) — Package version, protocol version, the host clock in ms.

Players

  • PlayerJoined (PadPlayPlayer) — A phone joined and got a slot (Resumed = it came back). Input does not flow yet.
  • PlayerReady (PadPlayPlayer) — Input flows; GetPad(slot) returns its pad. Once per join.
  • PlayerLeft (PadPlayPlayerLeft) — The phone dropped (Reason). Unless the reason is Bye or Stopped (PadPlayLeaveReason), the slot is held for Resume Hold Seconds.
  • PlayerRemoved (PadPlayPlayerRemoved) — The slot is free for good (Bye, Stopped or Expired). Remove the player's character here.
  • PlayerCount, PlayerSlots — Joined phones (not counting reconnecting ones), their slots in ascending order.
  • TryGetPlayer(slot, out player) — The joined player (PlayerSlot, Device, AppVersion, Resumed, Capabilities).
  • GetPlayerState(slot) — Connecting, Ready, Reconnecting or Gone (PadPlayPlayerState).
  • Kick(slot) — Disconnect the phone (the slot is not held).
  • GetPad(slot), PadDevices — The player's PadPlayPad (null if none); all pads.
  • GetScreenRotation(slot), ScreenRotationChanged — The phone's display rotation in degrees.
  • GetCapabilities(slot), GetClockSync(slot) — What the phone app supports; clock offset and round trip.
  • GetConnectionQuality(slot), ConnectionQualityChanged (PadPlayConnectionQuality) — How good the player's link is: Level (Good, Poor, Bad) and Issue (Loss, Delay). The SDK lowers the video by itself and shows nothing; use this to show your own hint, such as "put your phone on 5 GHz" (QuickStart §11).
  • Diagnostics — Connection and input data for tools (Debugging §4).

Input

  • Touch — The touch dispatcher: SetPlayerTarget(slot, camera) / (slot, display, rect), ClearPlayerTarget(slot), PhonePositionToPixel, GetDragThresholdPx(slot).
  • Recenter(slot, mode = Yaw), RecenterAll(mode) — Make the player's current direction forward, for the pad and every gyro component.
  • Recentered (PadPlayRecentered) — Who re-centered and why (Reason: Code, Button, LongPress, Connect).
  • TouchReceived, AttitudeReceived, ButtonsReceived — Raw packets. uGUI events and PadPlayPad usually cover them.

Output to the phone

  • SetLayout(slot, layout), GetLayout(slot) — The player's on-screen buttons (null = back to Settings.Buttons.Layout).
  • SetHaptics(slot, strength) — Continuous vibration, 0 to 1 (0 stops). Same as pad.SetMotorSpeeds.
  • Pulse(slot, durationMs, strength = 1) — One vibration of a set length, timed by the phone.
  • SetPhoneOverlay(slot, items), GetPhoneOverlay(slot) — Text and boards drawn by the phone over the video (PadPlayPhoneOverlayItem; usually through PadPlayPhoneOverlay).

Video (PadPlay SDK only)

  • VideoStatus — How the video is sent (graphics API path, encoder, each player's codec), or why H.264 is not used. Text for people.
  • GetVideoChoice(slot, out choice) — H.264 or JPEG for the player, and why (Codec, Reason, Detail).
  • RequestVideoStats(slot, callback) — Sending statistics (PadPlayVideoStats).
  • TryGetPoseView(slot, out view) — What the phone reports for a Pose Camera frame (motion-to-photon, correction).

PadPlayPad

The Input System device of each phone. It is a Gamepad, so <Gamepad>/… bindings, Gamepad.all and PlayerInput work.

  • attitude, angularVelocity — QuaternionControl (calibrated, Unity's space), Vector3Control (rad/s). Paths <PadPlayPad>/attitude, <PadPlayPad>/angularVelocity.
  • recenter — ButtonControl: the player asked to re-center (already applied by the SDK).
  • GetButton(id) — A button by PadPlayButtonId or number; 14 to 31 are game-defined (<PadPlayPad>/custom14 … custom31).
  • ButtonBits — All 32 buttons as bits.
  • PlayerSlot, IsConnected — The player; false while the phone is reconnecting.
  • Recenter(mode = Yaw) — Same as host.Recenter(PlayerSlot).
  • SetMotorSpeeds(low, high) — Vibration (strength = the larger value). PauseHaptics, ResumeHaptics, ResetHaptics work as usual.

Touch

PadPlayPointerEventData (a PointerEventData): PlayerSlot, FingerId, PhonePosition (0 to 1 on the phone, y = 0 at the top), ViewPoseSeq (the Pose Camera frame the player saw). Test eventData is PadPlayPointerEventData p in any uGUI handler.

PadPlayRaycaster: a GraphicRaycaster that ignores transparent pixels (AlphaThreshold, default 0.1).

Components

PadPlayQrView

On a Raw Image. Main members: Host, Caption (a Text or a TextMeshPro text), Texture, ShownUri, Refresh().

PadPlayStatusView

On a Text or a TextMeshPro text. Main members: Host, Target (where it writes; empty = the one on its GameObject), Rows, TryGetRow(slot, out row), BuildText().

PadPlayView

Main members: SourceCamera or SourceTexture, PlayerSlot (AllPlayers = -1, the default), Width, Height, FrameRate, MaxBitrateKbps, MatchPhoneAspect, UseAsTouchTarget. PadPlay SDK only.

PadPlayGyroCamera

Main members: PlayerSlot, Mode (Window, LookAround, Tilt), Settings, Tilt, Rotation, BaseRotation, ResetForward() (this camera only).

PadPlayGyroPointer

Main members: PlayerSlot, Settings, ViewportPosition (y = 0 at the bottom), IsPointing, GetScreenPosition(), GetRay(camera), Reticle, ResetForward() (this pointer only). Settings.Axis (PadPlayPointerAxis) is the end of the phone that points: DeviceTop (default; the end with the camera, like a remote control, the display's left or right in landscape), TopEdge (the display's top edge), Back, Auto (the earlier default). A twist about that end does not move the point.

PadPlayPoseCamera

Main members: PlayerSlot, FieldOfView, Settings, YawOffsetDegrees, VisibleViewportRect, VisiblePixelRect, ScreenPointToRay(eventData), TryGetView(out view), ResetForward() (this camera only). See Pose Camera.

PadPlayPhoneOverlay

Main members: PlayerSlot (AllPlayers = -1), HideInPicture, RefreshSeconds, Refresh().

PadPlayRemotePointers

Main members: Layout, TargetCamera, Settings, GetPointerId(slot) (static), GetHovered(slot), IsPressing(slot), TryGetScreenPosition(slot, out pos), TryGetPointer(slot, out pointer), ShowRecenterHint(slot). See Remote Pointers.

PadPlayDebugOverlay

Main members: Host, Visible, ToggleKey, BuildText().

Button layouts

PadPlayButtonLayout (Assets → Create → PadPlay → Button Layout): Elements, Orientation (Landscape, Portrait, Auto), MarkChanged() after changing Elements from code, Create(params Element[]). PadPlayButtonLayout.Element: Id (PadPlayButtonId), Shape (Circle, Rect), Center, Size (0 to 1, (0, 0) at the top left), Label, Opacity, Group, Role (None, Recenter), Style. PadPlayButtonStyle (how an element looks on the phone; empty = the default look): Image, PressedImage, KnobImage (Texture2D, sent as PNG once), CustomColors with Color, PressedColor, BorderColor, LabelColor, CustomSizes with BorderWidth, CornerRadius, LabelSize, IsEmpty. PadPlayRemoteLayout: the bundled remote layout (Create(), button ids Press, Back, Recenter, Menu, Minus, Plus).

Editions

PadPlayEdition: IsLite, Name ("PadPlay SDK" or "PadPlay Lite"), LiteMaxPlayers (1), ClampMaxPlayers(requested).
