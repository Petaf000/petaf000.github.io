PadPlay

Lifecycle

What happens from a phone joining to leaving. Pick a stage to see its events and API.

  1. Show QR code

    The Host starts listening and QR View shows the code. When this PC is found to block phones, a strip appears under it.

    • host.AutoStart
    • host.JoinUriChanged
    • host.ConnectionHint
    • PadPlayQrView
    • console

  2. Join

    The player gets a slot. No input yet.

    • host.PlayerJoined
    • host.GetPlayerState
    • joinready

  3. Ready

    Input starts and the pad works. Spawn the character here.

    • host.PlayerReady
    • host.GetPad
    • two

  4. Buttons

    The button layout is sent: Settings.Buttons.Layout for everyone, SetLayout for one player.

    • Layout
    • host.SetLayout
    • PadPlayButtonLayout

  5. Input

    Touches arrive as uGUI events; buttons and gyro through PadPlayPad.

    • PadPlayPointerEventData.PlayerSlot
    • pad.attitude
    • pad.GetButton
    • host.Recentered
    • lag

  6. Video

    A View sends a camera's picture to the player's phone. It lowers quality on weak Wi-Fi, and the phone asks for a repair when the picture breaks.

    • PadPlayView.SourceCamera
    • PadPlayView.PlayerSlot
    • host.ConnectionQualityChanged
    • host.RequestVideoStats
    • lag

  7. Drops

    Wi-Fi dropped or the app went to the background. The slot and the pad stay.

    • host.PlayerLeft
    • pad.IsConnected
    • ResumeHoldSeconds

  8. Comes back

    Back within Resume Hold Seconds (default 300 s): the same slot, and Resumed is true.

    • host.PlayerJoined
    • host.PlayerReady

  9. Gone

    Timed out (Expired), Disconnect in the app or Kick (Bye), or the host stopped (Stopped). Remove the character here.

    • host.PlayerRemoved
    • host.Kick
    • leftremoved
