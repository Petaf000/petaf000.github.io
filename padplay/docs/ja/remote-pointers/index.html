Remote Pointers

English

遊ぶ人がスマホを画面に向けるとカーソルがついて動き、スマホの A を押すと、カーソルの下の uGUI をクリックします。カーソルはつながっているプレイヤーごとに 1 つ、そのプレイヤーの色で出ます。UI のコードは変わりません。Button・Toggle・Slider・ScrollView には、マウスやスマホのタッチと同じように、ふつうの OnPointerEnter / OnPointerDown / OnPointerClick / OnDrag のイベントが届きます(仕組み: タッチ)。

大きな画面のメニュー、「画面を指す」ミニゲームなど、スマホをタッチパネルではなくリモコンとして使うシーンに向いています。Sample Hub とそのミニゲーム Target Pop も、これを使っています(クイックスタート §12)。

最小の手順

  1. 部品を足す。 GameObject → PadPlay → Remote Pointers(または Add Component → PadPlay → Remote Pointers)。シーンの PadPlayHost を見つけ、シーンに無ければホスト・QR コード・EventSystem を足します。
  2. レイアウトを選ぶ。 Layout には最初から同梱の PadPlayRemoteLayout(Recenter、A、B、−、+、Menu)が入っています。そのまま使うか、自分のボタンのレイアウトを入れてください。このシーンではホストの Video のモジュールをオフにします。このレイアウトは、絵を出さずに縦に持つスマホ向けに作ってあります。Orientation が Portrait なので、スマホのアプリは画面を縦向きに固定し、画面全体にボタンを並べます。
  3. 完了。 再生してスマホで参加します(または Window → PadPlay → Virtual Phones: 傾きの球をドラッグし、A をクリックします)。

スマホが参加すると、画面とスマホが 1 回だけ、画面の真ん中を指して Recenter を押す ように案内します。Recenter で今の向きが真ん中になり、カーソルが真ん中に飛びます。カーソルがずれてきた時など、いつでも使えます。

同梱のレイアウト

  • A(大) — Press = Gamepad の buttonSouth。カーソルの下の UI を押します。押したままでドラッグします。
  • B — Back = buttonEast。それ自体は何もしません。「戻る」として読んでください(pad.buttonEast)。
  • Recenter — Recenter = custom14、Role は Recenter。今の向きを真ん中にします(コードは要りません)。
  • Menu — Menu = startButton。それ自体は何もしません。自分のメニューに戻る時などに読んでください。
  • − / + — Minus / Plus = leftShoulder / rightShoulder。それ自体は何もしません。ページ送り、ズーム、音量など。

Id が Gamepad のボタンなので、<Gamepad>/buttonSouth などの今あるバインドからも見えます。PadPlayRemoteLayout.Create() で、同じレイアウトをコードから作れます。

誰が指したかを知る

public void OnPointerClick(PointerEventData eventData)
{
    if (eventData is PadPlayPointerEventData p && p.FingerId == PadPlayRemotePointers.FingerId)
        Debug.Log($"P{p.PlayerSlot + 1} clicked with the remote pointer");
}

プレイヤーごとのカーソルには、マウスやスマホの指とは別の pointerId(PadPlayRemotePointers.GetPointerId(slot))があるので、2 人のプレイヤーとマウスが同時に別々のボタンを押せます。コードからは remote.GetHovered(slot)、remote.IsPressing(slot)、remote.TryGetScreenPosition(slot, out pos)、remote.TryGetPointer(slot, out gyroPointer)(カーソルの元になっている PadPlayGyroPointer)、remote.ShowRecenterHint(slot) が使えます。

知っておきたい動き

  • 無効な UI。 Interactable がオフの Selectable は、カーソルが乗っても無効の色のままで、クリックできません(uGUI の標準の動きです)。
  • 選択。 A は Gamepad の Submit でもあります。ボタンが 2 回押されないよう(カーソルで 1 回、入力モジュールの Submit で 1 回)、押すと EventSystem の選択を外します(Clear Ui Selection)。UI に選択が要る時だけオフにしてください。
  • タッチ。 部品が有効な間は、ボタンの外のスマホのタッチは uGUI に届きません(Block Touch Ui)。そうしないと、A の横に触れた指が、その位置にある画面のゲームの UI をクリックしてしまいます。TouchReceived は出ます。
  • 指していない時。 スマホの向きが分からない間(まだ姿勢が届いていない、再接続を待っている)は、カーソルが薄くなり、押しても取り消されます。
  • 画面。 カーソルは Display 1 の全体か、Target Camera の範囲を動きます。当たるのは、その画面の UI だけです。
  • 時間。 カーソルはスケールしない時間を使うので、一時停止したメニュー(Time.timeScale = 0)でも動きます。
  • シーンをまたぐ。 レイアウトは、部品が有効な間プレイヤーごとに設定し、無効になると外します。Keep Across Scenes を使う場合も、シーンごとに自分の Remote Pointers を持てます(持たなくてもかまいません)。Recenter した向きは Host がプレイヤーごとに持つので、シーンを替えても(スマホの画面が回っても)カーソルは真ん中に飛ばず、スマホが指す所にあります。

調整

Settings → Pointer は共通の PadPlayGyroPointerSettings です: Horizontal / Vertical Range Degrees(端から端までどれだけ振るか)、Smoothing、Recenter Blend Ms。Cursor Size、Dimmed Alpha、Hint Seconds で見た目を変えます。どれも再生中に変えられます。既定の値は出発点です。

スマホの持ち方

スマホはリモコンのように、上の端(カメラのある短い辺)を画面に向けて持ちます。画面の真ん中を指して Recenter を押してください。Axis = DeviceTop(既定)なら、平らに持っても少し傾けても、スマホの画面がどちらを向いていても、いつもその端で狙います(横向きの配置では、その端は表示の左か右の辺です。どちらかは表示の回転から PadPlay が決めます)。手首をひねっても(その端の軸のまわりに回しても)カーソルは動きません。窓のように縦に立てると天井を指します。窓の形は見回しの部品(PadPlayGyroCamera)に残しています。Axis のほかの値: TopEdge = 表示の上の辺、Back = 背面、Auto = 前の既定(合わせ直した時に表示の上の辺と背面のあいだで決める)。既定では、左右に約 ±20°、上下に約 ±15° 振ると画面の端に届きます(HorizontalRangeDegrees 40、VerticalRangeDegrees 30)。スマホにはセンサーバーが無いので、数分かけて向きが少しずつずれます。カーソルがずれたら、もう一度 Recenter を押してください。仮想スマホでは、Pitch 90 が平らに持った(リモコンの)持ち方です。最初の縦に立てた姿勢は真上を指すので、平らに倒して(上下に余裕を持たせるなら 90 より少し手前)Recenter を押してください。Recenter は Host の Yaw のモード(既定)で。KeepGravity の Full で合わせ直すと、スマホの軸が決め直されます。
