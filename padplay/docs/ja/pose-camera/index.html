Pose Camera: プレイヤーの手の中の窓

English

PadPlayPoseCamera は、プレイヤーのスマホに合わせてカメラを回し、カメラに映る物をそのスマホへ送ります。プレイヤーはスマホをかざし、窓のようにしてシーンの中を見回します。部品を 1 つ付けるだけで、ゲーム側のコードは要りません。

描画・エンコード・送信・復号には必ず時間がかかります(Wi-Fi ではふつう 50〜100 ms)。その間にスマホが回ると、ただの映像では手の動きより絵が遅れます。PadPlay はこれを隠します。PC はスマホに見せるより少し広く描き(オーバースキャン)、スマホはフレームを出す直前に、そのフレームが描かれてから自分が回った分だけ絵を回します。VR ヘッドセットの「タイムワープ」と同じ考え方です。

置き方

  1. シーンに PadPlay View を置き、その Source Camera に、スマホに映したいカメラを入れます(第二画面 を参照)。View の Player Slot には、スマホを持つプレイヤーを入れます。
  2. 同じカメラに PadPlay → Pose Camera を付けます。Player Slot には同じプレイヤーを入れます。
  3. 再生してスマホをつなぎます。カメラはスマホについて回り、スマホにはカメラの絵が映ります。

シーンが始まった時のカメラの回転が「正面」です。接続した時に、プレイヤーが向いている方向が正面になります(ヨーだけ。重力は下のままです)。ResetForward()(このカメラだけ)、host.Recenter(slot)、Role = Recenter のレイアウトのボタン、スマホの隅の長押しでも同じことができます。

設定と API

  • Settings.FieldOfView / FieldOfView(既定 60) — スマホに見せる範囲の縦の視野角(度)。変えるとズームします。カメラの fieldOfView は、オーバースキャンの分だけ広く設定されます。
  • Settings.OverscanPercent(既定 10) — 上下左右に余分に描く量(見える大きさに対する %)。多いほど速い回転も隠せますが、見える部分のピクセルは減ります(10% なら描いた絵の 83% が見える部分です。細かさが要るなら View の解像度を上げてください)。
  • Settings.PhoneCorrection(既定 オン) — スマホに絵を回させます。比べたい時はオフにします。
  • Settings.Predict(既定 オン) — 角速度から、描く時点の向きを予測します(上限は Host の Inspector の Attitude のモジュール)。
  • Settings.FollowScreenRotation(既定 オン) — スマホの画面の回転(横向き)に合わせます。
  • Settings.RecenterOnConnect / FollowPadRecenter(既定 オン / オン) — 正面をいつ合わせ直すか。
  • YawOffsetDegrees(既定 0) — スマホの向きに足すヨー。例えば座ったままドラッグで後ろを見る時に使います。
  • ScreenPointToRay(eventData) — スマホのタッチのワールドのレイ。プレイヤーが見ていたフレーム を通ります(下を参照)。
  • ScreenPointToRay(phonePosition, poseSeq) — 同じことを生の値(PadPlayTouch.ViewPoseSeq)から。
  • TryGetView(out PadPlayPoseView) / host.TryGetPoseView(slot, …) — 動かしてから画面に出るまでの時間と、スマホがかけた補正。
  • VisibleViewportRect / VisiblePixelRect — スマホが見せる部分(オーバースキャンの内側)。ビューポート(0〜1)か、カメラのピクセルで。オーバースキャンは上下左右で同じなので、この四角形は真ん中にあります。

既定の値は最初の見当です。実機のスマホで触って調整してください。

タップ

スマホが出すのは、回して切り取ったフレームです。プレイヤーがタップすると、スマホは回転と切り取りを元に戻し、そのフレームの 点(描いた絵全体に対する 0〜1、y = 0 が上)を、フレームの番号(PadPlayPointerEventData.ViewPoseSeq)と一緒に送ります。Pose Camera は直近 256 フレームのカメラを覚えているので、poseCamera.ScreenPointToRay(eventData) は、プレイヤーが実際に狙ったレイを返します。画面の端でも、ズーム中でも、素早く回している時でも同じです。

public void OnPointerClick(PointerEventData e)
{
    Ray ray = poseCamera.ScreenPointToRay(e);   // PadPlay touches use the frame the player saw
    if (Physics.Raycast(ray, out RaycastHit hit))
        Debug.Log("Tapped " + hit.collider.name);
}

View のレンダーテクスチャの上の uGUI も位置が合います。タッチの位置が、描いた絵の上の点だからです。カメラの 今の 状態を使う Raycaster(例えばカメラに付けた PhysicsRaycaster)は、そのフレームから後にカメラが動いた分だけずれることがあります。それが問題になる時はScreenPointToRay(eventData) を使ってください。

スマホの上の文字: 絵の中か、画面に固定か

カメラが描く物(Pose Camera の Screen Space - Camera の Canvas も含みます)は全部絵の一部なので、スマホは絵と一緒に回します。そのような UI は VisibleViewportRect の内側に置いてください(RectTransform をそこに合わせてアンカーします)。外に置くと、スマホが決して見せないオーバースキャンの部分に入ってしまいます。

スマホの画面に止まって見える べき文字(スコア、「3 / 5 found」、照準)は、Phone Overlay に置きます:

  1. スマホの映像の領域を表す RectTransform を作ります。Pose Camera なら、VisibleViewportRect に合わせてアンカーします。
  2. そこに PadPlay → Phone Overlay を付け、Player Slot を設定します(−1 = 全員)。
  3. その下にふつうの uGUI の Text か TextMeshPro - Text (UI)(単色の板なら Image)を置き、いつもどおりスクリプトから変えます。

部品は RefreshSeconds(0.05 秒)ごとにそれらを読み、何か変わっていればスマホへ送ります。スマホはそれを映像の上に、補正の外で描きます。送るのは、文字、フォントの大きさ、揃え、太字 / 斜体、色、リッチテキスト(<b>、<i>、<color>。ほかのタグは外します)です。画像は単色の板として送ります(スプライトは送りません。印には + や ● のような文字を使ってください)。最大 64 個、それぞれ文字は 1024 バイトまで。Hide In Picture(オン)にすると、ゲーム自身の描画ではこの層が見えず、クリックも抜けるので、二重に描かれません。コードからは host.SetPhoneOverlay(slot, items) と PadPlayPhoneOverlayItem.CreateText / CreateRect を使います(位置は映像の領域に対する 0〜1、y = 0 が上)。ホストはプレイヤーごとに最後のオーバーレイを覚えていて、スマホが再接続すると送り直します。Pose Camera だけでなく、どの PadPlayView でも使えます。古いスマホのアプリはこれを無視します。

補正で隠せること・隠せないこと

隠せること:

  • スマホを回すこと(見回すこと)。オーバースキャンの範囲まで。それより速い回転は、描いた絵の端で止まり(デバッグ表示に "(edge)" と出ます)、残りは遅れて届きます。

隠せないこと:

  • スマホを 動かす こと(歩く、身を乗り出す)。補正は回転だけです。
  • ゲームの中で動いている物(キャラクター、エフェクト)。フレームを描いた時の位置に出ます。
  • それ以外のこと全部の遅れそのもの: タップへの反応、音、ゲームのロジック。
  • 描いてから表示するまでの間にゲームが変えたこと: YawOffsetDegrees(ドラッグ)、正面合わせ。

補正は窓が手にくっついているように感じさせるだけで、接続を速くするわけではありません。

測る

スマホは、出しているフレームについて次のことを知らせます:

  • 動かしてから画面に出るまでの時間(motion-to-photon): そのフレームを描くのに使った姿勢の標本の時刻から、スマホが画面にフレームを組み立てるまでの時間(どちらもスマホの時計なので、時計の同期は関係しません。実際に光るのは、画面の更新 1 回分ほど後です)。
  • 補正: 絵を何度回したかと、端に当たったか。

これは デバッグ表示(window: m2p 48 ms fix 3.2°)と、host.TryGetPoseView(slot, out var view) に出ます。

スマホなしで試す

Window → PadPlay → Virtual Phones で、スマホの画面の上を右ドラッグすると回せます。Delay(遅らせる。例えば 150 ms)を設定するとゲームが古い向きで描くので、Correction(補正)をオン・オフして違いを見てください。窓では近似として絵をずらし、拡大・縮小します(ロールや遠近は扱いません)。本物のスマホは正確な射影をかけます。Phone Overlay は上に固定して描きます。ピンチを試すには、Ctrl + ドラッグ(Mac では Cmd)で真ん中に対して対称な指 2 本を、または画面の上でマウスホイールを使います。

必要なもの・互換性

  • スマホのアプリが対応している必要があります(対応しているアプリは、接続する時にそれを知らせます)。古いアプリには、姿勢の情報なしで同じ映像が届きます。オーバースキャンした絵の全体を出し、タップもこれまでどおりその絵に対応します。
  • 姿勢の情報は、そのフレームを描いた Pose Camera のプレイヤーにだけ送ります。
  • H.264 でも、JPEG に切り替えた時でも動きます。

仕組み(興味のある方へ)

Pose Camera の映像のフレームには、30 バイトの情報が付いています: 姿勢の番号、姿勢の標本の時刻、描いた時の向き(スマホ自身の座標で)、見える視野角、オーバースキャン、画面の回転です。カメラの回転は 正面 × 足したヨー × 正面合わせ × スマホの向き × 画面の回転 で、スマホの向きより左はどれもワールドに固定されているので、描いた時のカメラと「今の」カメラの違いは、スマホ自身の向きだけで決まります。スマホはこれを自分のセンサーから求め、それに合う射影変換(ホモグラフィー)でフレームを描きます。

Gyro Camera(PadPlayGyroCamera)とは別物です。こちらは、どのカメラ(例えばメインの画面のカメラ)でも、Window・Look Around・Tilt のモードで、平滑化と感度をかけてスマホに合わせて回します。その回転はスマホの向きだけで決まる関数ではないので、スマホは補正できません。そのスマホへ絵を送るカメラには Pose Camera を使ってください。
