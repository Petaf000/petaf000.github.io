PadPlay

API リファレンス

PadPlay のすべての型・メンバー・設定項目をこのページにまとめています。名前や意味で絞り込めます。

PadPlayTestPhone

自分のゲームの自動テスト(Unity Test Framework の Play Mode)で使う、テスト用のスマホです。アプリと同じつなぎ方でこの PC の中の PadPlayHost に参加し、ボタン・スティック・タッチ・傾きを送り、ゲームから届いた配置・振動・正面合わせを読めます。スマホも Wi-Fi も要りません。名前空間とアセンブリは PadPlay.Testing で、テストのアセンブリの参照に足します。ビルドしたゲームには入りません。

  • Connect — 参加して、ホストが PlayerReady を出すまで待ちます([UnityTest] で yield します)。ホストが始まるのも待ちます。終わったら IsConnected を確かめ、つながらなかった理由は Error にあります。Drop の後なら同じ枠に戻ります。
  • Disconnect — Disconnect はアプリが抜けるのと同じで、すぐ PlayerRemoved(Bye)になります。Drop は Wi-Fi が切れるのと同じで、PlayerLeft の後も枠が取っておかれます。テストの終わりには Dispose を呼びます。
  • Press — ボタンを押す・離す。押したボタンは Release まで押したままです。本物のスマホと違い、レイアウトに無いボタンも押せます。
  • SetStick — LeftStick か RightStick を倒します(x が右、y が上、長さは 1 まで)。Vector2.zero で戻ります。
  • TryPressAt — スマホのその位置に触れた指が押す物を、アプリと同じ決め方で押します(当たりの余白も同じ)。スティックなら id を返すだけです。何も無ければ false です。
  • TouchDown — 指(0〜31)を置く・動かす・離す。位置は表示する所に対する 0〜1 で、(0, 0) が左上です。uGUI のポインターのイベントとして届きます。ボタンの上でもタッチの画面に行きます。
  • SetAttitude — スマホの持ち方を、正面合わせの前の pad.attitude の値で決めます。参加した時の最初の姿勢が正面になる(Calibrate Yaw On Connect)ので、変わった量で比べます。RequestRecenter は隅の長押しと同じです。
  • LayoutButtons — ゲームから届いた物です。最後のボタン配置(LayoutButtons・LayoutCount・LayoutOrientation・LayoutHitSlopMm)、今の振動の強さ(HapticStrength。0 で止まっている)と回数(HapticCount・PulseCount)、正面合わせの知らせの回数(RecenterCount)。
  • GoAway — アプリがゲームの画面から離れたときと同じにします。GoAway は画面が消えた・ほかのアプリ(Away。ホストは holdSeconds の間つながったままにします)、LookAway は通知の幕(Glance)、ComeBack で戻ります。どれも先に入力を全部離します。iPhone のようにアプリが止まる形は、GoAway の後に Drop です。Connect の前に ReportsAway = false にすると、知らせないアプリとして振る舞います。
  • WaitUntil — 条件が true になるか、時間が過ぎるまで待ちます([UnityTest] で yield します)。
