PadPlay

API リファレンス

PadPlay のすべての型・メンバー・設定項目をこのページにまとめています。名前や意味で絞り込めます。

PadPlayHost

PC 側の本体で、シーンに 1 つ置きます。スマホからの接続を待ち受けて入力を受け取り、ボタン配置・振動・映像をスマホへ送ります。QR コードに入れる URL もこの部品が用意します。

  • GetPad — そのプレイヤーの PadPlayPad を返します。
  • PlayerReady — 入力が届き始めたときに呼ばれます。参加と復帰のたびに 1 回です。ここから GetPad がパッドを返すので、キャラクターはここで出します。
  • PlayerRemoved — 枠が本当に空いたときに呼ばれます。このときパッドはもう削除されています。キャラクターはここで消します。
  • Pulse — 決まった長さで 1 回振動させます。長さはスマホが計るので、ゲームが一瞬止まっても延びません。SetHaptics で続けている振動があれば、終わった後にそちらへ戻ります。
  • SetHaptics — 次に呼ぶまで、同じ強さで振動を続けます。
  • SetLayout — そのプレイヤーにだけ別のボタン配置を出します。次のフレームで送ります。StopHost までは枠ごとに覚えているので、復帰した人や、後から同じ枠に入った人にも出ます。
  • Recenter — そのプレイヤーの今の向きを正面にします。パッドの attitude と、それを読む Gyro Camera・Gyro Pointer がまとめて合わせ直されます。少しずつ移るので、表示は跳びません。Recentered イベントも呼ばれます。
  • Touch.SetPlayerTarget — そのプレイヤーのタッチを、指定したカメラの画面に当てます。画面分割や 2 枚目のディスプレイで使います。Display と範囲で指定する SetPlayerTarget(slot, displayIndex, viewportRect) と、元に戻す ClearPlayerTarget(slot) もあります。
  • GetPlayerState — 枠の今の状態を返します。
  • PlayerSlots — 参加している枠の番号(小さい順)と、その数です。再接続を待っている人は入りません。
  • PlayerJoined — スマホが参加して枠が決まったときに呼ばれます。入力はまだ届きません。
  • PlayerLeft — スマホとの通信が切れたときに呼ばれます。枠とパッドが残るかどうかは、理由によって決まります。
  • Recentered — 正面が合わせ直されたときに呼ばれます。この時点で、パッドと Gyro Camera・Gyro Pointer はもう合わせ始めています。
  • ConnectionQualityChanged — 回線の状態が変わったときに呼ばれます。回線が弱いと SDK は映像の画質を自動で下げますが、遊ぶ人には何も表示しません。「5 GHz の Wi-Fi につないでください」のような案内は、このイベントを受けて自分で出します。
  • ScreenRotationChanged — スマホの画面の回転が変わったときに呼ばれます。
  • JoinUriChanged — QR コードに入れる URL が変わったときに呼ばれます(StartHost・RenewToken・StopHost のときと、PC のアドレスが変わったとき)。QR View を使っていれば、自分で受ける必要はありません。
  • ConnectionHintChanged — QR コードの下の案内が変わったときに呼ばれます。QR View を使わずに、自分の画面で案内を出すときに使います。Show Connection Hints がオフでも、CheckPcAsync の後には呼ばれます。
  • TouchReceived / AttitudeReceived / ButtonsReceived — スマホから生のパケットが届いたときに呼ばれます。ふつうは uGUI のイベントと PadPlayPad で足ります。Touch の Send Ui Events をオフにすると、タッチはこちらにだけ届きます。
  • Settings — Inspector の値をコードから読み書きします。
  • AcceptNewPlayers — オフにすると新しいスマホを断ります。取っておいた枠に戻る人は入れます。試合中だけオフにする、といった使い方をします。Settings.Players.AcceptNewPlayers と同じ値で、変えるとすぐ効きます。
  • NetworkSettings — 通信の細かい値で、StartHost のときに読まれます。ふつうは変えません。変えることがあるのは RenewGraceMs で、RenewToken の後も、参加済みのスマホが古い QR で戻れる時間です。
  • SetPhoneOverlay — スマホが映像の上に描く文字と板を設定します。Gyro Camera の補正で動かないので、スコアや照準に向きます。枠ごとに覚えて参加・復帰のときに送り直すので、プレイヤーが来る前に設定してもかまいません。ふつうはこのメソッドではなく、Phone Overlay の部品を使います。
  • VideoStatus — 映像の送り方(グラフィックス API の経路・エンコーダー・プレイヤーごとのコーデック)か、送れない理由を、人が読むための文で返します。映像を使っていないときは空です。
  • GetVideoChoice — そのプレイヤーが H.264 と JPEG のどちらで映像を受けているかと、その理由を返します。
  • RequestVideoStats — 映像の送信の数値(fps・ビットレート・落ちた割合・画質を下げた回数など)を集め、1 フレーム以上後にメインスレッドで callback に渡します。映像の崩れを立て直した回数も入ります。新しい版のアプリは、数秒ごとに映した絵を PC の絵と比べ、合わなければキーフレームを頼んで直しています。
  • GetConnectionQuality — そのプレイヤーの今の回線の状態を返します。状態が変わったときは ConnectionQualityChanged が呼ばれます。
  • ConnectionHint — この PC がスマホを止めているときに、QR コードの下に出す案内です。ホストは QR を出したとき・PC のアドレスが変わったとき・直した後に、PC の設定を自分で調べます(約 5 秒、別のスレッドで)。IsCheckingPc は調べている間 true です。
  • FixConnectionHintAsync — QR の下の案内のボタンと同じことをします。遊ぶ人が押したボタンからだけ呼んでください(QR View のボタンはこれを呼びます)。ゲームは設定を変えず、Windows の画面を開くだけです。
  • CheckPcAsync — Windows がこのプログラム(エディターでは Unity)の通信を通すかを調べます。約 5 秒かかり、別のスレッドで動きます。設定は変えず、何も表示しません。最後の結果は PcCheck に残ります。
  • GetConnectionDiagnosis — スマホがつながらない理由のうち、いちばん可能性の高いものを返します。SDK はこの結果をどこにも表示しないので、自分のヘルプ画面などで使います。
  • Diagnostics — ホストの記録(PadPlayDiagnostics)です。ホストの Update のたびに、メインスレッドで更新されます。
  • TryGetPoseView — Gyro Camera の絵についてスマホが報告した値を返します。スマホを動かしてから画面に出るまでの時間(motion-to-photon)と、スマホがかけた補正の角度です。
  • CreateSupportReport — 問い合わせに添える報告を、1 つのテキストにまとめます。入るのは、版・PC と GPU のドライバー・設定・映像の経路・ネットワークとファイアウォール・スマホごとの数値・イベントの記録と、スマホのアプリの報告と突き合わせる照合の番号です。ユーザー名・PC 名・トークンと鍵・ネットワークの名前などは消し、何を消したかを最後の行に書きます。
  • AutoStart — オンなら Start で待ち受けを始めます。オフにしたときは StartHost() を自分で呼びます。
  • StartHost — 待ち受けを始める・止めます。止めると全員の通信を切ります(PlayerLeft の後に、理由が Stopped の PlayerRemoved が呼ばれます)。エディターで再生を止めたときは、Keep Phones Across Play がオンならスマホは待っていて、次の再生で同じ番号に戻ります。
  • IsRunning — IsRunning は待ち受け中かどうか、Port は実際に使っている UDP ポート、JoinUri は QR コードの URL です。
  • RenewToken — 新しいトークンと鍵で QR コードを作り直します。古い QR では新しいスマホは入れません。参加済みのスマホはつながったままです。
  • Kick — スマホを外します。枠は取っておきません(理由が Bye の PlayerLeft と PlayerRemoved が続きます)。
  • TryGetPlayer — TryGetPlayer は参加しているプレイヤーの情報(PlayerReady で届くものと同じ)を、GetCapabilities はそのアプリが使える機能を返します。
  • GetScreenRotation — GetScreenRotation はスマホの画面の回転(度)を、GetClockSync はスマホとの時計のずれと往復の時間を返します。ボタン配置で向きを固定しているのに、それと合わない回転が届いたときは、重力の向きから直した値を返します。
  • KeepAcrossScenes — オンにすると、別のシーンを読み込んでもスマホはつながったままです。値は Awake で読まれます。後から読み込んだシーンにも Host があれば、その Host はこの値に関係なく、自分の設定を残っている Host に渡して休止します。そのため、Host を置いたシーンは単独で開いてもそのまま動きます。
  • ActiveHost — ActiveHost は実際に通信している Host(残している Host か、この Host 自身)です。この Host のメンバーへの呼び出しはどれもそちらに渡されるので、ActiveHost が要るのは、シーンより長く生きるオブジェクトから購読するときだけです。KeptHost はシーンをまたいで残している Host です。
  • SdkVersion — パッケージの版、アプリと照らし合わせるプロトコルの版、ホストの時計です。

PadPlayView

カメラか RenderTexture の絵をスマホへ送り、手元の画面(第二画面)として映します。有料の PadPlay SDK だけの機能で、Lite 版にはありません。

  • SourceCamera — 送るカメラです。SDK がこのカメラの targetTexture を作るので、絵はスマホにだけ出ます。URP では Base カメラにします。SourceTexture が入っているときは、そちらを送ります。
  • SourceTexture — カメラの代わりに送る、自分で描いた RenderTexture です。映像の大きさはこのテクスチャの大きさになります。
  • PlayerSlot — 送る相手の枠の番号です。-1(AllPlayers)なら全員に同じ絵を送ります。全員向けの絵は 1 回だけエンコードするので、画質はいちばん弱い回線に合わせられます。
  • Width / Height — カメラを送るときの映像の大きさ(px、16 以上)です。SourceTexture のときは使いません。
  • FrameRate — エンコードの fps の上限です。0 は 60 として扱います。
  • MaxBitrateKbps — ビットレートの上限(kbps)です。0 は 2500 として扱います。Adaptive Video がオンなら、Wi-Fi に合わせてここから下げます。
  • MatchPhoneAspect — 映像の幅をスマホの画面の縦横比に合わせます(高さはそのまま)。1 人に送るときだけ効きます。
  • UseAsTouchTarget — このカメラを、そのプレイヤーのタッチの当たる先にします。スマホで映像をタップすると、そこに映っている UI が押されます。
  • TouchCamera — タッチが当たるカメラです。RenderTexture を送るときは、そこへ描いているカメラを入れます。空なら Source Camera です。
  • GetPlayerView — 今そのプレイヤーに見せている View です(host の拡張メソッド)。

PadPlayGyroCamera

スマホの向きに合わせてカメラを回します。このカメラを Source Camera にした PadPlay View で、絵を同じプレイヤーのスマホへ送ると、スマホを窓のようにかざして見回せます。通信の遅れは、スマホが表示の直前に絵を回して隠します。以前の Pose Camera(PadPlayPoseCamera)は、この部品にまとめられました。

  • PlayerSlot — どのプレイヤーのスマホでこのカメラを回すかを、枠の番号で指定します。2 人以上なら、カメラごとにこの部品を付けて番号を変えます。
  • View — このカメラの絵を送る PadPlay View です。空なら、このカメラを Source Camera にしている View を使います。
  • FieldOfView — スマホに見える範囲の縦の画角(度)です。小さくすると望遠のように大きく映ります。代入すると Settings.FieldOfView に書きます。
  • YawOffsetDegrees — スマホの向きに足す左右の回転(度、プラスが右)です。座ったままドラッグで後ろを見る、などに使います。この回転はスマホの補正では隠れません。
  • BaseRotation — 正面のときのカメラのローカルの回転です。Awake のときの localRotation が入ります。
  • ScreenPointToRay — タップした所を通るワールドのレイを返します。PadPlay のタッチなら、プレイヤーがそのとき見ていたフレームのカメラで計算するので、素早く回していてもずれません(直近 256 フレームを覚えています)。
  • ResetForward — このカメラだけ、スマホが今向いている方向を正面にします(左右だけ。重力は下のまま)。プレイヤー全体を合わせ直すなら host.Recenter を使います。
  • Settings.OverscanPercent — 遅れを隠している間、上下左右に余分に描く量(見える大きさに対する %)です。多いほど速い回転も隠せますが、見える部分のピクセルは減ります(10% なら描いた絵の 83%)。
  • Settings.PhoneCorrection — スマホに絵を回させて遅れを隠します。違いを比べたいときだけオフにします。
  • Settings.Predict — 角速度から、描く時点の向きを予測します。上限は Host の Attitude の Max Extrapolation Ms です。
  • Settings.Smoothing — 向きのなめらかさ(0〜0.99)です。絵がそのプレイヤーへ行かないカメラ(PC の画面のカメラなど)のときだけ効きます。遅れを隠している間は使いません。
  • Settings.RecenterOnConnect — RecenterOnConnect がオンなら、参加・復帰したときに正面を合わせます。FollowPadRecenter がオンなら、プレイヤーのリセンター(host.Recenter・Recenter のボタン・隅の長押し)に合わせて、このカメラも合わせ直します。FollowScreenRotation がオンなら、スマホを横にしたときの画面の回転に合わせます。
  • IsCorrectingDelay — スマホがこのカメラの遅れを隠しているかどうかです。このカメラが、同じプレイヤーに送る PadPlay View の Source Camera になっていれば true です。Inspector にも表示されます。
  • VisibleViewportRect — スマホに実際に見えている範囲(オーバースキャンの内側)です。スマホに見せたい UI はこの中に置きます。絵と一緒に動いてほしくない文字は Phone Overlay に置きます。
  • TryGetView — TryGetView は、スマホが今見せている絵の motion-to-photon の時間と補正を返します(host.TryGetPoseView(PlayerSlot) と同じ)。HasAttitude は姿勢が一度でも届いたかどうかで、届くまでカメラは回りません。
  • Step — カメラを 1 フレーム分回します。AutoUpdate がオン(既定)なら LateUpdate で呼ばれます。順番を自分で決めたいときだけオフにして呼びます。

PadPlayGyroPointer

スマホをリモコンのように画面へ向けると、指した所が画面の上の点になります。照準や、画面のメニューを指すカーソルに使います。手首をひねっても点は動きません。

  • PlayerSlot — どのプレイヤーのスマホで指すかを、枠の番号で指定します。2 人以上なら、プレイヤーごとにこの部品を付けます。
  • ViewportPosition — 指している点です。ビューポートと同じ 0〜1 で、y = 0 が下です。(0.5, 0.5) が正面で、画面の端で止まります。
  • IsPointing — 直前の更新でスマホの向きを読めたかどうかです。枠に誰もいない、再接続を待っている、まだ姿勢が届いていない、のどれかのときは false です。false の間は、カーソルを薄くしたり押す操作を取り消したりします。
  • GetRay — camera から、指している点を通るレイを返します。3D のオブジェクトとの当たり判定に使います。
  • GetScreenPosition — 指している点をスクリーンのピクセル(左下が原点)で返します。
  • Reticle — 点についてくる UI です(任意)。親の RectTransform の中で、アンカーを点の位置に合わせて動かします。
  • ResetForward — このポインターだけ、今の向きを真ん中にします(Recenter Blend Ms かけて移ります)。プレイヤー全体を合わせ直すなら host.Recenter を使います。
  • Settings.Axis — スマホのどの方向で指すかを決めます。DeviceTop はカメラのある短い辺で指します(リモコンと同じで、寝かせても傾けても変わりません)。TopEdge は表示の上の辺、Back は背面です。Auto はリセンターのたびに、平らに持っていれば上の辺、立てていれば背面を選びます。
  • Settings.HorizontalRangeDegrees — 点を左右の端から端まで、上下の端から端まで動かすのに、スマホを振る角度です。小さいほど敏感です。
  • Settings.Reference — リセンターのときに何を真ん中にするかを決めます。Full は今指している方向(左右と上下)を真ん中にします。Yaw は左右だけを合わせ、高さは水平が真ん中になります。
  • Settings.Smoothing — 向きのなめらかさ(0〜0.99)と、合わせ直した後に前の点から移る時間(ms)です。ポインターは小さな揺れが目立つので、カメラより強めでもかまいません。
  • Settings.FollowPadRecenter — FollowPadRecenter がオンなら、プレイヤーのリセンターに合わせてこのポインターも合わせ直します。CalibrateOnConnect がオンなら、参加・復帰したときに合わせ直します。FollowScreenRotation がオンなら、スマホを横にしても、右へ振れば点が右へ動きます。
  • TryGetForward — シーンを変えても、点を同じ所に保つための API です。今のポインターの正面を TryGetForward で取っておき、次のシーンのポインターの最初のフレームより前に StartFrom で渡します。ForwardCount は正面が変わるたびに増えます。

PadPlayQrView

Raw Image に QR コードを出し、URL が変わると描き直します。再生中にこの PC がスマホを止めていると分かったときは、QR の下に 1 行の案内とボタンを帯で出します(スマホがつながっている間は出しません)。

  • Caption — ゲーム名を小さく出す Text か TextMeshPro のテキストです(任意)。Inspector の Show Uri をオンにすると URL も出します。
  • ShownHint — 今、帯に出している案内です。ボタンは「ファイアウォールの設定」「設定を開く」「もう一度」のどれかで、押すと host.FixConnectionHintAsync() を呼びます。「ファイアウォールの設定」の後は、開いた画面で押す所を帯に出します。
  • Refresh — 今の JoinUri で描き直します。URL が変わると自分で描き直すので、ふつうは要りません。
  • Texture — 今出している QR のテクスチャと、その中の URL です。止まっている間は null です。

PadPlayStatusView

参加しているスマホの一覧を Text か TextMeshPro に書きます。1 人 1 行で、番号・機種・状態・最後の入力からの秒数・ping を出します。実機で試すときの確認用です。抜けた人の行も残り、同じ枠に誰かが戻ると書き換わります。

  • Target — 書き込む先の Text か TextMeshPro のテキストです。空なら、同じ GameObject に付いているものに書きます。
  • Rows — 各行の元になる値です(PlayerSlot・Model・Os・State・LeftReason・LastInputKind・LastInputHostMs)。一覧を自分の UI で表示するときに使います。
  • Refresh — Refresh は今すぐ書き直します(ふつうは Refresh Interval Seconds ごと)。BuildText は書く文(色つきのリッチテキスト)を返します。言語はホストの Display Language に従います。

PadPlayPhoneOverlay

この RectTransform の下にある uGUI の Text・TextMeshPro・Image を、スマホが映像の上に描く層として送ります。この RectTransform の四角がスマホの映像の範囲になります(Gyro Camera なら VisibleViewportRect に合わせます)。中の文字はいつもどおりスクリプトから変えれば、変わった分だけが送られます。

  • PlayerSlot — 表示するプレイヤーの枠の番号です。-1(AllPlayers)なら全員のスマホに出します。
  • HideInPicture — ゲーム側の絵ではこの層を隠し、クリックも通り抜けるようにします。オフにすると、映像の中とスマホの上で二重に描かれます。
  • RefreshSeconds — uGUI を読む間隔(秒)です。0 は毎フレーム。Refresh() は今すぐ読みます。
  • 送れる物 — Text と TextMeshPro からは、文字・大きさ・揃え・太字と斜体・色と、リッチテキストの <b> <i> <color> を送ります(ほかのタグは外します)。Image は単色の板として送り、スプライトは送りません(印には + や ● のような文字を使います)。最大 64 個、文字はそれぞれ UTF-8 で 1024 バイトまでです。

PadPlayRaycaster

Canvas の Graphic Raycaster の代わりに付けます(両方は付けません)。Image の透明な所には当たらず、後ろの UI へ抜けます。スマホのタッチにもマウスにも同じように効きます。この部品が無くてもタッチは届きます。

  • AlphaThreshold — Image のこの値より透明な所には当たりません。0 なら Graphic Raycaster と同じです。
  • WarnUnreadableTexture — テクスチャの Read/Write がオフの Image は透明さを読めないので、四角として当たります。そのときテクスチャごとに 1 回 Console に警告を出します。直すにはテクスチャの Advanced › Read/Write をオンにします。

PadPlayDebugOverlay

ビルドしたゲームの画面の隅に、人数・各プレイヤーの状態・往復の時間・押しているボタンを出します。表示中に報告のキーを押すと、報告を保存してクリップボードにも入れます。遊ぶ人に報告を送ってもらうときに使います。Canvas を使わないので、ゲームの UI には影響しません。

  • ToggleKey — ToggleKey は表示を切り替えるキー(Input System の Key)、Visible は今表示しているかどうかです。Key.None にすると、キーでは切り替わりません。
  • ReportKey — 表示中に押すと報告を保存するキーです。保存すると画面に「報告を保存してコピーしました。ゲームを作った人に送ってください: 」とファイルの場所が出ます(文はホストの Display Language に従います)。SaveReport() はキーと同じことをします。
  • BuildText — 表示している文を返します。報告の行とキーの案内以外は英語です。Gyro Camera のプレイヤーには window: m2p 48 ms fix 3.2° のような行が出ます。

PadPlayPad

スマホ 1 台が Input System の Gamepad 1 つになります。<Gamepad>/… のバインドや PlayerInput がそのまま動きます。PlayerReady のときに作られ、PlayerRemoved のときに消えます。

  • attitude — 校正した後のスマホの姿勢(Unity の座標)です。縦に持って画面をこちらに向けたときが単位回転です。ReadValue() で Quaternion が取れ、<PadPlayPad>/attitude でバインドもできます。
  • angularVelocity — 角速度です。単位は rad/s で、軸はカメラのローカルの軸です。
  • IsConnected — 再接続を待っている間は false です。その間もパッドは残り、姿勢は最後の値のまま、ボタンは離した状態になります。
  • GetButton — ボタン配置の Id でボタンを取ります。0〜13 は Gamepad のボタン(0 = buttonSouth、8 = dpad.up)、14〜31 はゲームが決めるボタンです(<PadPlayPad>/custom14 … custom31)。
  • recenter — プレイヤーがリセンターを求めたことを表すボタンです。SDK はもう合わせているので、効果音や案内に使います。
  • RecenterCount — 姿勢を合わせ直した回数です。合わせ直した姿勢と同じ更新で変わるので、attitude で物を回すコードは、このフレームで合わせ直せば跳びません。
  • Recenter — host.Recenter(PlayerSlot, mode) と同じです。
  • SetMotorSpeeds — スマホを振動させます。スマホのモーターは 1 つなので、2 つの値のうち大きいほうが強さになります。0, 0 で止まります。PauseHaptics・ResumeHaptics・ResetHaptics もいつもどおり使えます。
  • PlayerSlot — 0 始まりの枠の番号です(画面に出すときは +1 します)。復帰しても変わりません。
  • ButtonBits — 押しているボタンを、ボタン配置の Id のビットで返します(14〜31 も入ります)。

PadPlayPointerEventData

スマホのタッチ(と PadPlayScreenPointer)が uGUI に渡すイベントのデータです。PointerEventData の一種なので、どのハンドラーでも eventData is PadPlayPointerEventData p で、誰が触ったかが分かります。

  • PlayerSlot — 触ったプレイヤーの、0 始まりの枠の番号です。
  • PhonePosition — スマホの画面の上の指の位置です。0〜1 で、y = 0 が上です。position は、これをタッチが当たる画面のピクセルに直した値です。
  • FingerId — そのスマホの中での指の番号(0〜31)です。PadPlayScreenPointer のイベントでは -1 です。
  • ViewPoseSeq — タップしたときにプレイヤーが見ていた Gyro Camera のフレームの番号です。gyroCamera.ScreenPointToRay(eventData) がこれを使います。

PadPlayScreenPointer

1 人分の「画面の上の点」と「押しているか」から、uGUI のふつうのポインターのイベント(Enter・Exit・Down・Up・Click・ドラッグ)を出します。スマホの指以外で UI を押すとき、たとえば Gyro Pointer のカーソルに使います。部品ではなく C# のクラスで、自分では何も描かず、入力も読みません。メインスレッドだけで使います。

  • Process — 1 フレームに 1 回呼びます。
  • Cancel — クリックにせずに押す操作を終え、ホバーを外します。自分の部品を無効にするときや、プレイヤーが抜けたときに呼びます。
  • OverClickable — OverClickable は点の下にクリックを受けるものがあるか、Hovered は点の下のオブジェクト、IsPressed は押しているかどうかです。カーソルの見た目を変えるのに使います。
  • Data — 送っているイベントのデータです。最初の Process の前は null です。
  • GetPointerId — プレイヤーごとの pointerId です。マウスやスマホの指とは重ならないので、何人かとマウスが同時に別のボタンを押せます。イベントの FingerId はいつも -1 です。

PadPlayButtonLayout

スマホに出すボタンとスティックの配置です。アセットでもコードでも作れます。全員に同じ配置なら Host の Buttons › Layout に、1 人だけ変えるなら host.SetLayout で渡します。

  • Create — コードから配置を作ります。アセットとしては保存されません。
  • Element — ボタンかスティック 1 つ分の設定です。
  • Orientation — この配置を出している間のスマホの向きです。Landscape と Portrait は向きを固定し、Auto は持ち方に合わせます。変えると配置を送り直します。
  • MarkChanged — コードで Elements を変えた後に呼ぶと、次のフレームで送り直します。Inspector で変えたときは要りません。

PadPlayHostSettings

Host の Inspector の値です(host.Settings)。各項目と既定値は、このページの「設定項目(Inspector)」にあります。

  • ApplyPreset — Modules をよく使う組み合わせにします。ほかの値は変えません。
  • SetEnabled — モジュールを入れたり外したりします。動作中でもすぐ効きます(スマホに伝える一覧は次の参加から変わります)。
  • Players — Inspector の組ごとの値です。Port・GameName・HostAddresses・LoopbackOnly・AnnounceOnLan・VerboseLog・DisplayLanguage・ShowConnectionHints は、このクラスに直接あります。

PadPlayPcFix

Windows 自身の設定の画面を開きます。PadPlay もゲームも設定は変えず、管理者の権限も求めません。設定を変えるのは、開いた画面で遊ぶ人です。遊ぶ人が押した自分のボタンからだけ呼んでください(QR の下の帯のボタンは、host.FixConnectionHintAsync() を通してこれを使います)。

  • OpenFirewallSettings — Windows Defender ファイアウォールの「ファイアウォールによるアプリケーションの許可」の画面を開きます。一緒に GetFirewallSettingsSteps() の文を表示してください。遊ぶ人がゲームに戻ったら、host.CheckPcAsync() で調べ直します。
  • GetFirewallSettingsSteps — 開いた画面で押す所を、遊ぶ人向けの 2 文で返します。ゲームがまだ一覧に無い場合に備えて、このゲームの .exe の名前も入ります。
  • OpenNetworkSettings — Windows の「設定 → ネットワークとインターネット」を開きます。遊ぶ人はそこで Wi-Fi を「プライベート ネットワーク」にします。
  • PadPlayPcFixResult — FixConnectionHintAsync などの結果です。Opened は Windows の画面を開いた(変えるのは遊ぶ人)、Done はホストを動かし直した、Cancelled は管理者の確認が断られた(エディターの道具だけ)、Failed は開けなかった、NotSupported は Windows 以外です。

PadPlayFirstPrompt

Windows でゲームが初めて待ち受けを始めると、Windows が通信を許可するかを聞いてくることがあります(いつもではありません)。そこでキャンセルされるとスマホはつながらないので、その前に遊ぶ人へ 1 文を見せるためのクラスです。PadPlay がこの文を自分から出すことはありません。インストーラーでファイアウォールの規則を足すゲームでは要りません。

  • IsNeededAsync — Windows のファイアウォールの規則を調べ(約 5 秒、別のスレッドで)、このゲームの規則がまだ無ければ true を返します。StartHost の前、たとえばタイトル画面で呼びます。例外は投げません。
  • GetText — 確認画面の前に見せる 1 文を返します。
  • MarkShown — 見せたことをこの PC に記録します(PlayerPrefs)。MayBeNeeded は Windows を調べずに答える簡易な判定で、Windows のビルドでまだ MarkShown を呼んでいなければ true です。

PadPlayDiagnostics

ホストが受け取ったものと送ったものの、読み取り専用の記録です(host.Diagnostics)。PadPlay Debug・Debug Overlay・報告はこれを読みます。ゲームの動きには影響しません。

  • LastJoinAttempt — ホストが始まってから最後に届いた参加の試みと、届いた数です。PadPlay Debug の接続タブの「最後の接続の試み」はこれです。
  • ButtonPressesReceived — スマホから届いたボタンの押下の数(Input System の手前で数える)と、ゲームが読めた押下の数です。比べると「届いているのにゲームに見えていない」が分かります。PadPlay Debug の状態タブの「なぜ?」の行はこれを使います。
  • Players — ホストが始まってから見たプレイヤーごとの記録です(抜けた人も)。入力の頻度(TouchRateHz・AttitudeRateHz・ButtonsRateHz)、最後の入力の時刻、今触れている指、最後の姿勢とボタン、回線の状態などです。
  • CopyEvents — イベントの記録(古い順、最大 512 件)を写します。参加・退出・ボタン配置・振動・断った参加(JoinRejected)・回線・映像・SDK が自分でしたこと(AutoAction)・PadPlay の警告とエラーが入ります。

PadPlayDeepCheck

この PC のネットワーク アダプターを数秒見張り、スマホの通信がどこで止まっているかを調べます(Windows の Packet Monitor)。Windows の Unity エディターだけで動き、管理者の確認が 1 回出ます。ビルドで呼ぶと、すぐに Problem が NotSupported の結果を返します(ゲームは管理者の権限を求めないため)。ふつうは PadPlay Debug の接続タブの「詳しく調べる」から使います。

  • RunAsync — seconds 秒のあいだ見張って、スマホの通信がどこで止まっているかを調べます。見張っている間(Stage が Watching)に、スマホで QR コードを読んでもらいます。設定は何も変えず、例外も投げません。
  • Stage — 今の段階(Idle・Asking・Watching・Reading)と残りの秒数、見張りを今すぐ終える Stop()、最後の結果です。最後の結果は報告の [check] にも入ります。

PadPlayEdition

PadPlay SDK(有料)と PadPlay Lite(無料)のどちらかです。Lite には映像(第二画面、PadPlay View)がありません。人数を含め、そのほかは同じ動きで、時間の制限や透かしはありません。

  • IsLite — Lite なら true です。Name は "PadPlay SDK" か "PadPlay Lite" です。

PadPlayPlayerColors

プレイヤーごとの色です(P1 青・P2 赤・P3 緑・P4 黄 … 8 色で繰り返し)。Status View・プレビューの指・PadPlay Debug も同じ色を使うので、誰の入力かが見分けられます。

  • Get — その枠の色と、リッチテキスト用の "#RRGGBB" です。

設定項目(Inspector)

Host の Inspector と同じ順に並べています。

  • Max Players (Settings.Players.MaxPlayers, 既定値 4) — 参加できるスマホの数です(1〜64)。
  • Resume Hold Seconds (Settings.Players.ResumeHoldSeconds, 既定値 300) — 通信が切れた人の枠を取っておく秒数です。この間に同じスマホが戻れば同じ番号になり、過ぎると PlayerRemoved が呼ばれます。0 で取っておきません。
  • Accept New Players (Settings.Players.AcceptNewPlayers, 既定値 on) — オフにすると新しいスマホを断ります(戻る人は入れます)。host.AcceptNewPlayers と同じ値です。
  • Calibrate Yaw On Connect (Settings.Players.CalibrateYawOnConnect, 既定値 on) — 参加・復帰したときにスマホが向いている方向を正面にします。スマホの左右の基準は起動のたびに変わるためです。
  • Create Devices (Settings.Players.CreateDevices, 既定値 on) — プレイヤーごとに PadPlayPad(Gamepad)を作ります。オフにすると、AttitudeReceived などの生のイベントだけが届きます。
  • Keep Phones Across Play (Settings.Players.KeepPhonesAcrossPlay, 既定値 on) — エディターだけ。再生を止めてもスマホは待っていて、次の再生で QR を読み直さずに同じ番号に戻ります。ビルドしたゲームでは、起動のたびに QR が変わります。
  • Modules (Settings.Modules, 既定値 Touch, Attitude, Buttons, Video) — 使う機能です。外したモジュールの入力はホストが捨て、何も送りません。Preset で Touch only・Gyro controller・Second-screen controller を選べます。
  • Drag Threshold Mode (Settings.Touch.DragThresholdMode, 既定値 EventSystem) — ドラッグを始める距離の決め方です。EventSystem はマウスと同じ値、Pixels は Drag Threshold Px、PhoneMillimeters はスマホの画面の上の Drag Threshold Mm を使います。mm で決めると、画面の大きさによらず同じ指の動きでドラッグが始まります。
  • Drag Threshold Mm / Px (Settings.Touch.DragThresholdMm / DragThresholdPx, 既定値 1.5 mm / 10 px) — Drag Threshold Mode が PhoneMillimeters のときは Mm を、Pixels のときは Px を使います。
  • Raycast Only Player Screen (Settings.Touch.RaycastOnlyPlayerScreen, 既定値 on) — タッチをそのプレイヤーの画面の Raycaster にだけ当てます。オフなら全部の Raycaster のいちばん手前に当たります。
  • Stale Timeout Seconds (Settings.Touch.StaleTimeoutSeconds, 既定値 0) — データが途絶えた指を、この秒数がたったら離したものとして扱います。0 なら扱いません。アプリは止まっている指のデータを送らないので、ふつうは 0 のままにします。
  • Send Ui Events (Settings.Touch.SendUiEvents, 既定値 on) — タッチを uGUI のイベントとして送ります。オフにすると、TouchReceived だけが届きます。
  • Click Speed Seconds (Settings.Touch.ClickSpeedSeconds, 既定値 0.3) — ダブルタップとみなすタップの間隔の上限です。
  • Player Targets (Settings.Touch.PlayerTargets, 既定値 empty) — プレイヤーごとにタッチが当たる画面(カメラか Display と範囲)です。無い人は Display 1 の全体です。コードでは host.Touch.SetPlayerTarget。
  • Max Extrapolation Ms (Settings.Attitude.MaxExtrapolationMs, 既定値 150) — 姿勢が届かない間、角速度で先を予測する時間の上限です。長いほど Wi-Fi の切れ目を埋めますが、その間に手が止まると行き過ぎて戻ります。
  • Correction Ms (Settings.Attitude.CorrectionMs, 既定値 50) — 予測した姿勢と、新しく届いた姿勢の差を埋める時間です。0 にすると、すぐに新しい姿勢へ跳びます。
  • Delay Buffer Ms (Settings.Attitude.DelayBufferMs, 既定値 0) — 届いた姿勢の間を補間するために遅らせる時間です。0 なら常に最新の姿勢を使います。ふつうの揺れをならすなら 10〜20 にします。
  • Smoothing (Settings.Attitude.Smoothing, 既定値 0) — pad.attitude のなめらかさ(0〜0.99)です。大きいほど手ぶれが減り、遅れが増えます。
  • Full Style (Settings.Attitude.FullStyle, 既定値 KeepGravity) — Full のリセンターの決め方です。KeepGravity は持っている傾きを取り除き(重力は下のまま)、KeepDeviceAxes はスマホの軸をそのままカメラの軸にします。
  • Recenter Mode (Settings.Attitude.RecenterMode, 既定値 Yaw) — Recenter のボタンと隅の長押しでの合わせ方です。Yaw は左右の向きだけを、Full は今の姿勢全体を合わせます。
  • Allow Phone Recenter (Settings.Attitude.AllowPhoneRecenter, 既定値 on) — スマホの画面の左上の隅を 1 秒長押しして、正面を合わせられるようにします。オフにすると、ゲームのボタンとコードからしか合わせられません。
  • Layout (Settings.Buttons.Layout, 既定値 none (PadPlay Setup: stick, A, B)) — 全員のスマホに出すボタン配置です。空ならボタンは出ません。再生中に変えるとすぐ送り直します。
  • Allow Haptics (Settings.Buttons.AllowHaptics, 既定値 on) — オフにすると振動を送らず、続いている振動も止めます。
  • Haptic Strength Scale (Settings.Buttons.HapticStrengthScale, 既定値 1) — すべての振動の強さに掛ける倍率(0〜1)です。機種による差をならすのに使います。
  • Haptic Refresh Ms / Duration Ms / Min Change (Settings.Buttons.HapticRefreshMs …, 既定値 100 / 150 / 0.05) — 続ける振動の送り方です。Refresh Ms は送り直す間隔、Duration Ms は 1 回に送る長さです(Host が止まっても、スマホはこの時間がたつと止まります)。Min Change は、間隔を待たずにすぐ送る強さの変化の大きさです。
  • Codec (Settings.Video.Codec, 既定値 Auto) — Auto なら H.264 を使い、H.264 の復号が遅いスマホから求められたときは JPEG にします。H.264 のエンコーダーが無い環境(macOS・Linux・OpenGL)では、全員 JPEG です。
  • Adaptive Video / Min Kbps / Priority / Min Fps / Min Scale (Settings.Video.AdaptiveVideo …, 既定値 on / 300 / Quality / 30 / 0.5) — Wi-Fi に合わせて、ビットレート・fps・大きさを上げ下げします。Priority は Quality なら大きさを保って fps から、Smoothness なら fps を保って大きさから下げます。
  • Total Max Kbps (Settings.Video.TotalMaxKbps, 既定値 0) — 全員を合わせたビットレートの上限です。1 人あたりの上限は、これを人数で割った値です。0 なら上限はありません。
  • Jpeg Scale / Fps / Quality (Settings.Video.JpegScale …, 既定値 0.5 / 30 / 75) — JPEG のときの大きさ(View に対する割合)・fps・最初の画質です。
  • Pacing Mbps (Settings.Video.PacingMbps, 既定値 20) — 1 フレーム分のデータを分けて、この速さで少しずつ送ります。キーフレームで Wi-Fi があふれるのを防ぐためです。0 なら一度に送ります。
  • Max Playout Frames (Settings.Video.MaxPlayoutFrames, 既定値 2) — 届き方が乱れているときに、スマホがならすために待つフレーム数の上限です。乱れていなければ待ちません。0 なら常に待ちません。
  • Use Ltr Recovery (Settings.Video.UseLtrRecovery, 既定値 on) — 映像が落ちたとき、エンコーダーが対応していれば、キーフレームより小さな立て直し用のフレームで直します。
  • Prefer Readback (Settings.Video.PreferReadback, 既定値 off) — Direct3D 11 / 12 でも、毎フレーム CPU へ読み戻します。GPU の経路で映像がおかしいときの回避策で、その分遅くなります。
  • Auto Prefer Readback (Settings.Video.AutoPreferReadback, 既定値 on) — GPU の経路で映像が直ってはまた崩れる PC では、自動で読み戻しに切り替えます。切り替えはその実行の間ずっと続き(エディターでは Play ごとに戻ります)、理由は PadPlay Debug と報告に出ます。遊ぶ人には何も出ません。
  • Mode (Settings.Preview.Mode, 既定値 EditorOnly) — 各スマホの画面を Game ビューの Display 2・3… に出します。既定はエディターだけです。
  • Player Displays / Show Touches / Show Buttons / Overlay Opacity / Show Caption (Settings.Preview.PlayerDisplays …, 既定値 2, 3, 4, 5 / on / on / 0.6 / on) — プレイヤーごとの Display の番号(0 は出さない)と、指・ボタン・説明の重ね方です。
  • Port (Settings.Port, 既定値 7780) — 通信に使う UDP ポートです。ほかで使われていれば次の空いている番号を使い、その番号を QR に入れます。
  • Game Name (Settings.GameName, 既定値 empty (Product Name)) — スマホと QR コードの横に出すゲームの名前です。
  • Host Addresses (Settings.HostAddresses, 既定値 auto) — QR コードに入れる IP アドレスです。VPN や仮想のネットワーク アダプターがある PC で、Wi-Fi のアドレスを先にするときに入れます。
  • Loopback Only (Settings.LoopbackOnly, 既定値 off) — 127.0.0.1 だけで待ち受けます(テスト用)。スマホはつながらず、Windows の確認画面も出ません。
  • Announce On LAN (Settings.AnnounceOnLan, 既定値 on) — 動いている間、この PC の Wi-Fi / LAN に「PadPlay のゲームがここにある」と知らせます(送るだけ)。つながらないスマホはこれを聞いて、止めているのが PC か Wi-Fi かを見分けます。送るのは、QR のトークンから作った名前(これでは参加できません)・ポート・PC のアドレスだけです。
  • Verbose Log (Settings.VerboseLog, 既定値 off) — 参加・退出・ボタン配置・映像の流れと、参加用の URL を Console に出します。
  • Display Language (Settings.DisplayLanguage, 既定値 Auto) — 遊ぶ人に見せる文(QR の下の文・Status View・Debug Overlay の報告の行)の言語です。Auto なら、OS が日本語のときは日本語、それ以外は英語です。エディターの表示言語とは別に決まります。
  • Show Connection Hints (Settings.ShowConnectionHints, 既定値 on) — この PC がスマホを止めているとき、QR コードの下に 1 行の案内とボタンを出し、スマホのアプリにも伝えます。そのため、QR を出したときに PC の設定を自分で調べます(約 5 秒、別のスレッドで)。オフにしても、CheckPcAsync などの API は使えます。
