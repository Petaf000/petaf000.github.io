クイックスタート

English

スマホに PadPlay アプリを入れてあれば(手順 5)、空の Unity プロジェクトから「スマホでゲームを操作できる」状態まで、10 分ほどで進められます。

流れ: パッケージをインポート → PadPlayHost を置く → QR コードを出す → スマホのアプリでつなぐ →タッチ・Gamepad・ジャイロの入力を受け取る →(必要なら)第二画面の映像を送る・画面のボタンを置く・スマホを振動させる。

設計の考え方は 仕組み、エディタの道具は デバッグ にあります。全部のページの一覧: ドキュメントの目次。

Window → PadPlay → Welcome(パッケージを入れた後に 1 回だけ自動で開きます)にも同じ最初の手順があります。1 クリックで全部のサンプルを入れて Sample Hub を開けるほか、スマホのアプリとこのドキュメントへのリンクもあります。

メニューの道筋は英語の表示で書いています。Unity エディタを日本語にしている場合は、Window = ウィンドウ、GameObject = ゲームオブジェクト、Assets = アセット、Add Component = コンポーネントを追加、Project Settings = プロジェクト設定、Preferences = 環境設定、のように読み替えてください。PadPlay が足すメニュー(PadPlay → … の下)は、どの言語でも英語のままです。

1. 必要な環境

  • Unity — Unity 2022.3 LTS(2022.3.62f3)以降。Unity 6 も含みます。動作を確かめた環境 も見てください。
  • パッケージ — 依存パッケージとして自動で入ります: Input System(com.unity.inputsystem 1.11.2 以上)、uGUI(com.unity.ugui)。ほかには何も要りません。通信は SDK 独自の UDP の PadPlay Link です。
  • Active Input Handling — Project Settings → Player → Active Input Handling(プロジェクト設定 → プレイヤー)を Input System Package (New) か Both にします。
  • PC(ホスト) — Windows 10 / 11。エディタか、Windows x64 のスタンドアロンビルドで動きます。macOS と Linux のホストはまだ確かめていません(映像も JPEG だけになります。後述)。
  • GPU(第二画面の映像を使う時だけ) — H.264 は Windows Media Foundation でエンコードします(GPU のハードウェアエンコーダーが使えればそれを、無ければ Windows のソフトウェアエンコーダーを使います)。Direct3D 11 / 12 では絵が GPU から出ずにエンコードまで進みます。Vulkan は一度 CPU に読み戻すので遅くなります。H.264 を使えない環境(OpenGL、macOS / Linux、H.264 のエンコーダーが無い Windows)では、映像を JPEG で送ります。タッチ・Gamepad・ジャイロには GPU のエンコーダーは要りません。
  • レンダーパイプライン — ビルトイン と URP(Universal Render Pipeline)。第二画面の映像はどちらでも同じように動き、設定は要りません。HDRP はまだ確かめていません。サンプルの 3D のマテリアルはビルトイン用です。URP のプロジェクトでは、サンプルが実行時にパイプラインの Lit シェーダーに切り替えるので、変換の作業は要りません。Player をビルドする時は、Window → PadPlay → Prepare Samples for URP or HDRP を 1 回実行してください(Import All Samples なら自動で行います。サンプル を参照)。
  • スマホ / タブレット — Android 7.0 以降、または iOS 15 以降の iPhone で、別途 PadPlay アプリを入れたもの(手順 5)。ジャイロスコープは、ジャイロの機能(姿勢・Gyro Camera・Pose Camera・Remote Pointers)を使う時だけ要ります。
  • ネットワーク — PC とスマホを 同じ Wi-Fi / LAN につなぎます。通信は全部 1 つの UDP ポート(既定は 7780)を使います。インターネット越しの対戦は対象外です。

Unity のほかに要るもの

  • スマホの PadPlay アプリ — 遊ぶ人全員のスマホに、別途 PadPlay アプリが要ります。アプリは 1 つで、PadPlay を使ったどのゲームにもつながります。ゲームごとのアプリはありません。入れ方は 手順 5 にあります。
  • 同じ Wi-Fi — PC とスマホは 同じ Wi-Fi / LAN につないでください。PadPlay はインターネットを通らず、インターネット接続も要りません。ゲスト用のネットワークや「AP の分離」(プライバシーセパレーター)が有効なルーターでは端末どうしがつながらないので、ふつうの家庭やオフィスのネットワークを使ってください。
  • Windows ファイアウォール — 初めて再生した時に、Windows が Unity にネットワークの使用を許可するか聞いてきます。プライベート ネットワークで 許可 を選び、使う Wi-Fi をプライベート ネットワークにしてください。ビルドしたゲームは別のプログラムなので、もう一度聞かれます。トラブルシューティング も見てください。

動作を確かめた環境

  • PC — Windows、NVIDIA の GPU(ハードウェアの H.264)、Direct3D 12
  • Unity — 6000.6 で実機のスマホと。2022.3.62f3 と 6000.0.84f1 は同じ自動テスト(Edit Mode と Play Mode、Direct3D 11 での映像、サンプル)が通ります
  • グラフィックス API — 実機のスマホとは Direct3D 12。同じ PC の自動テストで Direct3D 11・Vulkan・OpenGL Core(JPEG)
  • レンダーパイプライン — ビルトイン。自動テストで URP 17.6(Unity 6000.6)と URP 14.0.12(2022.3.62f3)
  • Windows のビルド — 2022.3.62f3(ビルトインと URP、Mono と IL2CPP)と 6000.6 の Player ビルドで、サンプルの QR コード・接続・映像
  • Android — Android 10、Samsung Galaxy S9+(1 台)
  • iPhone — この版ではまだ実機で試していません(アプリは自動のビルドでビルドでき、暗号のテストも通っています)

ほかの GPU のハードウェアエンコーダー、Windows のソフトウェアエンコーダー、macOS / Linux のホスト、HDRP、ほかのスマホでも動く見込みですが、まだ確かめていません。

まだできないこと

  • macOS / Linux のホスト — まだ H.264 のエンコーダーがないため、第二画面は JPEG で送ります(データが大きく、遅くなります)。動作は確かめていません。
  • Web ブラウザからの参加 — この版にはありません。遊ぶ人全員に PadPlay アプリが要ります。1.x の無料アップデートで足す予定です。
  • インターネット越しの対戦 — 同じ LAN の中だけです(中継サーバー・STUN / TURN はありません)。
  • HDRP — まだ確かめていません。
  • RenewToken() の後の再接続 — ふつうの参加より守りが弱くなります(鍵の交換をやり直さないため。手順 4 を参照)。この場合の鍵の交換は 1.x で足す予定です。

PadPlay Lite

無料の PadPlay Lite は、有料版とまったく同じように動きますが、次の制限があります: 1 人まで(Max Players の上限が 1)、第二画面の映像なし(PadPlayView と映像のエンコーダーは入っていません。Video のモジュールは注意書きを出すだけで何もしません)、サンプルは 2 つ(ミニゲーム Target Pop つきの Sample Hub と Minimal。ほかのサンプルは Hub に灰色のカードで出ます)、スマホのアプリのソースなし。このページのうち、映像・複数のプレイヤー・ほかのサンプルについての節は、有料版の PadPlay SDK だけに当てはまります。

2. パッケージをインポートする

PadPlay は Unity Asset Store から入れます。Unity ID で PadPlay SDK を購入した(または無料の PadPlay Lite を入手した)後:

  1. プロジェクトを開き、同じ Unity ID で Unity エディタにサインインします。
  2. Window → Package Manager(ウィンドウ → パッケージマネージャー)を開き、My Assets を選びます(Unity 6 では左の一覧、Unity 2022.3 では左上の Packages のドロップダウンにあります)。
  3. PadPlay SDK(または PadPlay Lite)を選び、Download を押してから Import を押します。
  4. Import Unity Package の窓では全部にチェックを入れたまま Import を押します。

パッケージは Packages/dev.petaf.padplay に入ります(埋め込みパッケージなので Assets の下には入りません。Package Manager ではどちらの版も*PadPlay* と表示されます。どちらの版かは Welcome の窓の見出しで分かります)。依存する Input System と uGUI がプロジェクトに無ければ、Unity が入れます。その後、Window → PadPlay → Welcome が開きます。

PadPlay には Input System が要ります。Active Input Handling を Both か Input System Package (New) にしてください(手順 1)。プロジェクトが古い Input Manager だけを使っている場合(Unity 2022.3 で新しく作ったプロジェクトの既定)は、Welcome の窓に警告とSet to Both…(Both にする…)のボタンが出ます。押して Unity を再起動してください。Both なら Input Manager を使うコードもそのまま動きます。PadPlay Setup と Host の Inspector にも同じ警告とボタンが出ます。Unity が自分から Input System のバックエンドを有効にするか聞いてくることもあります(Unity 2022.3 では Yes、Unity 6 では Enable & Restart)。その後も PadPlay の警告が出たままなら、Set to Both… を使ってください。

アップデート: 新しい版も同じ手順でダウンロードしてインポートします。前に入れたサンプルは Assets/Samples に残ります。新しい版のサンプルにするには、Welcome の窓の Import all available samples and open the Sample Hub(使えるサンプルを全部入れて Sample Hub を開く)を押してください(先に古い版のサンプルを片付けるか聞いてきます。下を参照)。

PadPlay Lite から PadPlay SDK へ: 同じプロジェクトに PadPlay SDK をインポートします。Import Unity Package の窓では全部にチェックを入れたままにしてください。パッケージの名前が同じなので Lite がその場で置き換わり、シーンと設定はそのまま残ります。Welcome の窓の見出しが PadPlay SDK になります。もう一度 Import all available samples and open the Sample Hub を押してください。サンプルは Lite と同じフォルダ(Assets/Samples/PadPlay/<版>)に入るので、Sample Hub と Minimal は有料版に置き換わり、ほかの 4 つのサンプルが足されます。前の版のサンプルが Assets/Samples に残っている場合(例えば Assets/Samples/PadPlay Lite)は、Welcome の窓がそれを一覧にし、Remove the old samples…(古いサンプルを片付ける…)を出します(先に確かめてから、ごみ箱に移します)。両方を残すと同じ名前のアセンブリが 2 つになり(Assembly with name … already exists)、Unity がコンパイルできなくなります。すでにそうなっていて Welcome の窓を使えない場合(例えばセーフモード)は、古いほうのフォルダ(例えば Assets/Samples/PadPlay Lite)を手で消せば、またコンパイルできるようになります。PadPlay SDK の上に PadPlay Lite をインポートすると、SDK のファイルは消えませんが Lite の制限がかかります。戻すには PadPlay SDK をもう一度インポートしてください。

3. PadPlayHost を置く

1 クリックで: GameObject → PadPlay → PadPlay Setup(ゲームオブジェクト → PadPlay → PadPlay Setup)。次の物を、1 回の Undo で戻せるひとまとまりとして足します:

  • PadPlay — PadPlayHost(足した後に選択されます)。Buttons → Layout に最初の ボタンのレイアウト が入っています: 左スティック・A(buttonSouth)・B(buttonEast)。スマホにこれが出て、手順 7 のコードがすぐに動きます。変え方は 手順 10 にあります。
  • PadPlay UI — Screen Space – Overlay の Canvas(Sorting Order 100、Raycaster なしなのでタッチを受け止めません)。QR コード(PadPlayQrView、右下)とその下の案内(ゲームの名前と参加の URL)、プレイヤーの一覧(PadPlayStatusView、左上)が入っています。動かしても、大きさを変えても、消してもかまいません。
  • EventSystem — シーンに無い時だけ。Input System の UI モジュールつきの EventSystem です。すでにある EventSystem はそのままにします。

シーンにもう PadPlayHost がある時は何も足さず、今あるホストを選びます。

手で置く場合(結果は同じです):

  1. 空の GameObject を作ります(例えば PadPlay)。
  2. Add Component → PadPlay → Host(コンポーネントを追加 → PadPlay → Host)。
  3. シーンで uGUI を使っているなら、いつもの EventSystem を残します(無ければ足します)。スマホのタッチはこれを通って届きます。

Host に要る準備はこれだけです。Auto Start がオン(既定)なら、再生すると待ち受けを始めます。

Host の Inspector

Inspector は上から Players → Modules → Debug → Connection の順に並んでいます(再生中はその上に状態の行が出ます)。ゲームで使うモジュールにチェックを入れると、そのすぐ下にモジュールの設定が開きます。チェックを外したモジュールはたたまれて灰色になり、値はそのまま残ります。項目にマウスを重ねると、短い説明が出ます。

ほとんどの値は 再生中に 変えられ、すぐに効きます。触った感じを見ながら調整できます。ホストが始まる時にだけ読む項目は、再生中は灰色になり (locked in Play mode)(再生中は変更不可)と出ます。

Players(Settings.Players)

  • Max Players(既定 4。再生中は変更不可) — 参加できるスマホの台数。
  • Resume Hold Seconds(既定 60。再生中は変更不可) — 切れたスマホ(Wi-Fi が一瞬切れた・アプリが裏に回った)は、この時間内なら同じプレイヤー枠に戻れます。過ぎると PlayerRemoved が出ます。
  • Accept New Players(既定 オン。再生中も変更可) — オフにすると、新しいスマホは「満員」として断ります。切れたプレイヤーは戻れます。host.AcceptNewPlayers と同じです。
  • Calibrate Yaw On Connect(既定 オン。次の接続から) — 接続(再接続)した時に、プレイヤーが向いている方向を正面にします。
  • Create Devices(既定 オン。次の接続から) — プレイヤーごとに Input System の PadPlayPad(Gamepad)を作ります。

Modules(Settings.Modules)— 見出しの横の Preset(プリセット)のメニュー(Host のコンテキストメニューにもあります)で、よく使う組み合わせを選べます:Touch only(タッチだけ)、Gyro controller(ジャイロのコントローラー: 姿勢 + ボタン)、Second-screen controller(第二画面つきコントローラー: 全部)。プリセットはチェックだけを変えます。

オフにしたモジュールは、ホストが無視します。その入力は捨てられ(uGUI のイベントも、TouchReceived / AttitudeReceived /ButtonsReceived も出ず、パッドにも何も入りません)、そのモジュールのためには何も送りません(ボタン・振動・映像を送りません)。

Touch(タッチ。Settings.Touch)

  • Drag Threshold Mode(既定 EventSystem) — 指がどれだけ動いたらドラッグを始めるか(ドラッグ開始距離)の決め方: EventSystem(マウスと同じ)、Pixels、PhoneMillimeters(どのスマホでも指の動きの量が同じ。スマホのピクセル比と画面の大きさから、プレイヤーごとに換算します)。
  • Drag Threshold Mm / Px(既定 1.5 mm / 10 px) — 選んだ決め方での距離。スマホの大きさが分からない時は Px を使います。
  • Raycast Only Player Screen(既定 オン) — プレイヤーのタッチは、そのプレイヤーの画面(カメラか表示する領域)にだけ当たります。
  • Alpha threshold — シーンの全部の PadPlayRaycaster の Alpha Threshold への近道(透明なピクセルはタッチが抜けます)。
  • Stale Timeout Seconds(既定 0) — この時間何も送ってこない指を離したことにします(0 = しない)。
  • More: Send Ui Events, Click Speed Seconds, Player Targets — uGUI のイベントのオン・オフ、ダブルタップの間隔、プレイヤーごとにどの画面を触るか(手順 6)。

Attitude(姿勢。Settings.Attitude)

  • Max Extrapolation Ms(既定 150) — Wi-Fi のパケットが遅れた時に、姿勢をどこまで先まで予測するか。
  • Correction Ms(既定 50) — 予測のずれをどのくらいの速さでなじませるか(0 = すぐに飛ぶ)。
  • Delay Buffer Ms(既定 0) — パケットの間を補間するための、わざと入れる遅れ(なめらかになりますが、遅れます)。
  • Smoothing(既定 0) — pad.attitude に足す平滑化(0 = なし。大きいほど安定しますが遅れます)。
  • Full Style(既定 KeepGravity) — Full の正面合わせで、正面をどう決めるか。
  • Recenter Mode(既定 Yaw) — Recenter のボタンやスマホの隅の長押しで、正面をどう合わせ直すか(手順 8)。
  • Allow Phone Recenter(既定 オン) — スマホの隅の長押しを受け付けます(手順 8)。オフにすると、ゲームのボタンとコードからだけになります。

Buttons(ボタン。Settings.Buttons)

  • Layout(既定 なし) — 全部のスマホに出すボタン(手順 10)。New でスティック・A・B 入りのレイアウトのアセットを作ります。
  • Allow Haptics(既定 オン) — オフにすると振動を送りません(振動中なら止まります)。
  • Haptic Strength Scale(既定 1) — 全部の振動の強さに掛ける値。
  • Haptic Refresh / Duration / Min Change(既定 100 ms / 150 ms / 0.05) — 振動をスマホへ送り直す方法(ふつうは変えなくて大丈夫です)。

Video(映像。Settings.Video)

  • Codec(既定 Auto) — Auto = H.264。求めてきたスマホ(H.264 の復号が遅いもの)には JPEG、この PC に H.264 のエンコーダーが無ければ全員に JPEG を使います。H264 / Jpeg はどちらかに固定します(H264 に固定しても、この PC に H.264 のエンコーダーが無ければ JPEG になります)。
  • Adaptive Video / Min Kbps / Priority / Min Fps / Min Scale(既定 オン / 300 / Quality / 30 / 0.5) — Wi-Fi が悪くなるとビットレートを下げ、次にフレームレートか大きさを下げます。よくなるとゆっくり戻します。Quality は大きさを保ちます(フレームレートを先に下げます)。Smoothness はフレームレートを保ちます(大きさを先に下げます)。
  • Total Max Kbps(既定 0) — 全部のスマホを合わせた上限。1 台あたりはこれをプレイヤーの数で割った値までになります(0 = 上限なし)。
  • Jpeg Scale / Fps / Quality(既定 0.5 / 30 / 75) — JPEG にした時の設定: View の大きさに対する割合、フレームレート、最初の画質(20〜90。その後はビットレートに合わせます)。
  • Pacing Mbps / Max Playout Frames / Use Ltr Recovery(既定 20 / 2 / オン) — 1 フレームの断片を送る速さ(0 = 一度に全部)。届き方のむらをならすためにスマホが待つ最大のフレーム数(0 = 待たない。むらがある間だけ待ちます)。失った映像をキーフレームではなく小さな復旧フレームで直すか。ホストが始まる時に読みます。
  • Prefer Readback(既定 オフ) — Direct3D 11 / 12 でも、毎フレーム CPU を通してコピーします(GPU の経路がうまく動かない時の回避策。遅くなります)。
  • Views — シーンの全部の PadPlayView と、そのプレイヤー・大きさ・フレームレート・ビットレートの上限・Match Phone Aspect(手順 9)。1 つも無ければ Create a camera and attach(カメラを作って付ける)で足せます。

モジュールの設定は、上で印を付けた Video の 3 つの値を除いて再生中に変えられます。Codec・Adaptive Video・JPEG の値は、プレイヤーの映像が始まる(始め直す)時に効きます。Video のオン・オフや View を変えると、そのプレイヤーの映像は始め直しになります(キーフレームから。接続とプレイヤー枠はそのままです)。

Debug(たたまれています)— スマホごとの Display 2 / 3 のプレビュー(Settings.Preview)、Open Debugger(デバッガーを開く)、Add Debug Overlay(デバッグ表示を追加)。デバッグ を見てください。

Connection(たたまれています。ふつうは変えません)

  • Port(既定 7780。再生中は変更不可) — 全部(参加・入力・映像)に使う UDP ポート。使われていれば次の空いているポートを使い、それを QR に入れます。
  • Game Name(既定 製品名。再生中は変更不可) — スマホに出す名前。
  • Host Addresses(既定 自動。再生中は変更不可) — QR に入れる IP アドレス。PC にネットワーク アダプターが複数ある時に設定します。
  • Loopback Only(既定 オフ。再生中は変更不可) — 127.0.0.1 だけで待ち受けます(テスト用)。
  • Verbose Log(既定 オフ。再生中も変更可) — 接続の流れと参加の URL を Console に出します。初めて試す時に便利です。
  • Display Language(既定 Auto。再生中も変更可) — 遊ぶ人が見る文字(QR の下の案内、Status View)の言語。Auto = OS が日本語なら日本語、それ以外は英語。

エディタの窓と Inspector の説明は日本語でも出せます。Welcome の窓の右上か Preferences → PadPlay で Auto / English / 日本語 を選んでください(日本語の用語: Glossary-ja)。

コードからは同じ値が host.Settings の下にあります。例えば host.Settings.Players.MaxPlayers、host.Settings.SetEnabled(PadPlayModules.Touch, false)、host.Settings.ApplyPreset(PadPlayModulePreset.TouchOnly) です。古い版の SDK で保存したシーンは、読み込んだ時に新しい形に直ります(値が新しい場所に移ります)。

プレイヤーの番号は 0 から始まる枠 です(PlayerSlot 0 が画面の「P1」)。

4. QR コードを出す

PadPlay Setup(手順 3)を使ったなら、もうできています。手で置く場合:

  1. GameObject → UI → Raw Image(どの Canvas でもかまいません)。
  2. Raw Image に Add Component → PadPlay → QR View。
  3. 必要なら、Caption に Text か TextMeshPro - Text (UI) を入れると、コードの下にゲームの名前が出ます(Show Uri で参加の URL も出ます。長いので、遊ぶ人は打ち込まずに貼り付けて使います)。

QR View はシーンの Host を見つけ、参加の URL が変わるたびに描き直し、Host が止まっている間は隠れます。つながっているプレイヤーの一覧を画面に出すには、Text か TextMeshPro のテキストに PadPlay → Status View を付けます。

TextMeshPro は、PadPlay が文字を書く・読む所(QR View の Caption、Status View、Phone Overlay)のどこでも、設定なしで使えます。プロジェクトに TextMeshPro があれば自動で有効になります(Unity 6 では uGUI 2.x に入っています。Unity 2022.3 では com.unity.textmeshpro)。日本語の案内を出す時は、日本語の文字を含むフォントアセットを TMP のテキストに設定してください。

QR コードには、PC のアドレス・UDP ポート・トークン・毎回新しい鍵が入っています。鍵はネットワークを流れません。スマホはこの鍵で送受信するものを全部暗号化・認証するので、同じ Wi-Fi のほかの端末は入力や映像を読むことも偽ることもできません。鍵はホストが始まるたびに変わります。暗号化を切る設定はありません。

今の QR コードを無効にするには(例えば試合と試合の間に)、RenewToken() を呼びます。新しいトークンと鍵を作ります。参加済みのスマホはつながったままです。参加済みのスマホが作り直しの直後に Wi-Fi が切れた場合は、host.NetworkSettings.RenewGraceMs(既定 60 秒、0 = オフ)の間なら古いコードで自分の枠に戻れます。戻る時は参加した時に受け取った秘密の値で本人であることを示すので、新しいスマホにはいつも新しい QR コードが要ります。この戻り方は、鍵の交換をやり直さず、古いコードの鍵とその秘密の値で守っているので、ふつうの参加より守りが弱くなります(分かっている制限で、1.x で直す予定です)。誰かを締め出すためにコードを作り直す時は、RenewGraceMs を 0 にしてください。

using PadPlay;
using UnityEngine;

public class Lobby : MonoBehaviour
{
    [SerializeField] PadPlayHost host;

    void OnEnable()
    {
        host.PlayerReady += OnReady;
        host.PlayerLeft += OnLeft;
        host.PlayerRemoved += OnRemoved;
    }

    void OnDisable()
    {
        // Unsubscribe, so a destroyed Lobby is not called (and, with Keep Across Scenes, not kept alive).
        host.PlayerReady -= OnReady;
        host.PlayerLeft -= OnLeft;
        host.PlayerRemoved -= OnRemoved;
    }

    void OnReady(PadPlayPlayer p) => Debug.Log($"P{p.PlayerSlot + 1} ready: {p.Device.Model} (resumed: {p.Resumed})");
    void OnLeft(PadPlayPlayerLeft left) => Debug.Log($"P{left.PlayerSlot + 1} left ({left.Reason}), may come back");
    void OnRemoved(PadPlayPlayerRemoved removed) => Debug.Log($"P{removed.PlayerSlot + 1} is gone ({removed.Reason})");

    public void NewQrCode() => host.RenewToken();

    public void StartMatch() => host.AcceptNewPlayers = false;   // players who drop can still come back
}

5. スマホをつなぐ

  1. スマホに PadPlay アプリを入れます(下の「アプリの入れ方」を参照)。
  2. Unity で 再生 します。
  3. 初めての時は、Windows が Unity にネットワークの使用を許可するか聞いてくることがあります。許可(プライベート ネットワーク)を選んでください。
  4. アプリで QR コードを読み、つなぐボタンをタップします。(カメラが使えない時は、デバッガーの Join URI(参加 URI)の横の Copy(コピー)で参加の URL をコピーし、アプリに貼り付けます。)(アプリはスマホの言語に合わせて表示します。つなぐボタンは日本語では「つなぐ」、英語では "Connect" です。)

アプリの入れ方

遊ぶ人はそれぞれ、無料の PadPlay アプリを Google Play から入れます(Android 7.0 以上)。iPhone は App Store から入れます(iOS 15 以降)。アプリは 1 つで、PadPlay を使ったどのゲームにもつながります。PadPlay SDK と PadPlay Lite のどちらでも同じです。

自分のアプリ(PadPlay SDK のみ)。 PadPlay SDK にはアプリのソースも入っています:Packages/dev.petaf.padplay/PhoneApp~/PadPlayPhoneApp-…-source.zip(このフォルダは Unity の Project ウィンドウには出ません。エクスプローラーで開いてください)。Unity のプロジェクトの外に展開して Flutter でビルドするか(手順は zip の中の client/README.md にあります)、自分の名前・アプリ ID・アイコン・色で公開できます(WHITE_LABEL.md)。PadPlay Lite にはソースは入っていません。

手元にスマホが無い時は、Window → PadPlay → Virtual Phones(仮想スマホ)でエディタの中の仮想のスマホをつなげます。

つながったら

スマホが受け入れられてプレイヤー枠が決まると PlayerJoined が出ます。その直後、入力が流れ始めた時に PlayerReady が出ます(参加 1 回につき 1 回)。いつまでも準備完了にならない時は トラブルシューティング を見てください。

プレイヤー枠は、次の状態を順にたどります(host.GetPlayerState(slot)):

  • Connecting(PlayerJoined で入る) — 枠は決まったが、まだ入力が流れていない。同じスマホが戻ってきた時は PlayerJoined.Resumed が true です。
  • Ready(PlayerReady で入る) — 入力が届いている。GetPad(slot) はもうそのプレイヤーのパッドを返します。
  • Reconnecting(PlayerLeft で入る) — スマホが切れた。枠とパッドは Resume Hold Seconds の間、取っておきます。
  • Gone(PlayerRemoved で入る) — 枠はもう空いた(bye・stopped・expired)。パッドはすでに消えています。プレイヤーのキャラクターはここで消してください。

アプリを閉じてもう一度開いた場合も、スマホは前の枠に戻れます(アプリが端末の ID を覚えているため)。ただし Resume Hold Seconds の間に戻り、自分から切断していない場合に限ります。

host.AcceptNewPlayers = false にすると、切れたプレイヤーは戻れるまま、新しいスマホを断ります(スマホには「満員」と出ます)。host.ScreenRotationChanged / host.GetScreenRotation(slot) で、プレイヤーがスマホを横に向けたことが分かります。

6. タッチはふつうの uGUI のイベントで届く

UI のコードは変えなくてかまいません。スマホのタッチは、標準の OnPointerDown・OnDrag・OnPointerClick などのイベントになるので、Button・Slider・ScrollRect や自分で書いたハンドラーがそのまま動きます。同時にマウスも使えるので、デバッグにも困りません。

誰が 触ったかを知りたい時だけ、PadPlayPointerEventData かどうかを見ます:

using PadPlay;
using UnityEngine;
using UnityEngine.EventSystems;

public class WhoTouchedMe : MonoBehaviour, IPointerDownHandler
{
    public void OnPointerDown(PointerEventData eventData)
    {
        if (eventData is PadPlayPointerEventData phone)
            Debug.Log($"P{phone.PlayerSlot + 1}, finger {phone.FingerId}, at {phone.PhonePosition} on the phone");
        else
            Debug.Log("mouse / local touch");
    }
}

既定では、スマホは Display 1 の全体を触ります。プレイヤーごとに自分の画面を持たせるには(画面の分割、2 つ目のディスプレイ、RenderTexture に描くカメラ)、プレイヤーにカメラを割り当てます:

host.Touch.SetPlayerTarget(playerSlot: 1, camera: player2Camera);

Host の Inspector の Touch → More → Player Targets に入れてもかまいません。そうすると、タッチはそのプレイヤーのカメラ(その Canvas と、カメラに PhysicsRaycaster があれば 3D のオブジェクト)にだけ当たり判定をします。PhonePosition はスマホの画面での指の位置(0〜1、y = 0 が上)、position は対象の画面でのいつものピクセルの位置です。

画像の透明な部分: スプライトの透明なピクセルをタッチが抜けるようにするには、Canvas の GraphicRaycaster を*PadPlay → Raycaster* に替え、スプライトのテクスチャの Read/Write を有効にします(トラブルシューティングを参照)。マウスでも同じように効きます。

7. スマホを Gamepad として読む

準備完了になったスマホは、どれも Input System の PadPlayPad デバイスになります。PadPlayPad は Gamepad そのもの なので、<Gamepad>/buttonSouth や <Gamepad>/leftStick のような今のバインド、Gamepad.all、PlayerInput がそのまま動きます。Gamepad に加えて、次のものがあります:

  • attitude — <PadPlayPad>/attitude: Quaternion(Unity の左手系、校正後)
  • angularVelocity — <PadPlayPad>/angularVelocity: Vector3、rad/s
  • custom14 … custom31 — <PadPlayPad>/custom20: Button(ゲームが決めるボタン。手順 10)
  • playerSlot — <PadPlayPad>/playerSlot: Integer(C# からは pad.PlayerSlot)
  • recenter — <PadPlayPad>/recenter: Button: プレイヤーが正面を合わせ直したいと求めた(手順 8)。SDK はもう自分で正面合わせを済ませています

C# から直接読む例:

using PadPlay;
using UnityEngine;

public class PadReader : MonoBehaviour
{
    [SerializeField] PadPlayHost host;

    void Update()
    {
        PadPlayPad pad = host.GetPad(0);          // P1, or null if not connected
        if (pad == null || !pad.IsConnected)
            return;

        if (pad.buttonSouth.wasPressedThisFrame)
            Debug.Log("A pressed");
        Vector2 move = pad.leftStick.ReadValue();
        Quaternion attitude = pad.attitude.ReadValue();
        transform.rotation = attitude;
    }
}

補足:

  • スマホにボタンとスティックが出るのは、ホストにレイアウトがある時だけ です(手順 10)。PadPlay Setup で置いたホストには最初のレイアウト(左スティック・A・B)が入っています。手で足したホストには無いので、レイアウトを入れるまで Gamepad のボタンは離したままです。
  • スマホが再接続を待っている間も、デバイスは残します(IsConnected == false、ボタンは離した状態、姿勢は止まったまま)。そのため、Wi-Fi が一瞬切れても PlayerInput の組み合わせは崩れません。デバイスは PlayerRemoved の直前に消えます。
  • 姿勢は、スマホを縦向きにまっすぐ立て、画面を自分に向けた時に単位回転(identity)です。接続した時に SDK が向き(ヨー)を合わせ、「プレイヤーが今向いている方向」を正面にします。後で正面を合わせ直すには host.Recenter(slot) か pad.Recenter() を使います(手順 8)。

8. ジャイロのカメラとポインター

よくある使い方なら、姿勢を自分で読む必要はありません。

Gyro Camera — Camera(かその親)に PadPlay → Gyro Camera を付け、Player Slot を設定します。付けた時の回転が「正面」になります。モード(Settings → Mode。再生中も変えられます):

  • Window — スマホがシーンをのぞく窓になります。スマホを回すと、見える向きも一緒に回ります。
  • LookAround — ヨーとピッチだけでロールはしません。感度とピッチの範囲を調整できます。
  • Tilt — スマホを傾けると、その分の速さでカメラが回ります(スティックのような操作)。キャラクターを動かすための Tilt(−1〜1)も読めます。
var gyroCamera = GetComponent<PadPlayGyroCamera>();
gyroCamera.Mode = PadPlayGyroMode.LookAround;
Vector2 tilt = gyroCamera.Tilt;

Gyro Pointer — PadPlay → Gyro Pointer でスマホがレーザーポインターになります:ViewportPosition(ビューポートの座標: y = 0 が下、真ん中が 0.5, 0.5)、GetScreenPosition()、GetRay(camera)、それと、ポインターについて動く Reticle(RectTransform。任意)があります。

名前の付け方: 部品は Gyro(付ける物)、データは attitude(姿勢。AttitudeReceived・pad.attitude・Attitude のモジュール)と呼んでいます。

調整する値(感度・平滑化・デッドゾーン・正面合わせのなじませ時間)は全部 Settings にあり、再生中に変えられます。

正面合わせ(「今の向きを正面にする」)

なぜ要るのか。 スマホはジャイロと加速度センサーを組み合わせて向きを出しています(Android の Game Rotation Vector、iOS の Core Motion)。重力があるのでピッチとロールは正しく保たれますが、向き(ヨー) を固定するものが無いため、遊んでいるうちに数分かけて「正面」が少しずつずれます(磁石の近くや、素早く回した後はもっと速くずれます)。アプリを起動し直すと、スマホのヨーの基準も変わります。

正面合わせは、そのプレイヤーの正面を 全部まとめて 合わせ直します。その PadPlayPad の姿勢と、そのプレイヤーを読んでいる全部の Gyro Camera /Gyro Pointer です(それぞれ自分の Recenter Blend Ms でなじませるので、画面は飛びません)。ほかのプレイヤーには影響しません。Recenter Mode が Yaw(既定)なら重力を保ちます(地平線は水平のまま)。Full なら今の姿勢全体を正面にします。

プレイヤーに正面合わせのボタンを用意する方法は 3 つあります。どれか 1 つを選んでください:

  1. コードなし: 役割つきのレイアウトのボタン。 ボタンのレイアウトのアセットで、要素の Role を Recenter にします(例えば "Recenter" と書いた Select ボタン)。押すとそのプレイヤーの正面合わせをします。ボタンはふつうのボタンとしてもゲームに届きます。
  2. コード 1 行。 例えばポーズメニューから: 
    host.Recenter(playerSlot);                       // Yaw; or host.Recenter(slot, AttitudeCalibrationMode.Full)
host.RecenterAll();                              // everyone
pad.Recenter();                                  // same as host.Recenter(pad.PlayerSlot)
  3. 自分の InputAction: <PadPlayPad>/recenter をバインドします。Recenter の役割のボタンを押している間と、プレイヤーがスマホの隅を長押しした時の1 回の更新の間、押された状態になります。効果音やヒントを出すなど、反応するのに使ってください。正面合わせ自体は SDK がもう済ませています。

スマホ側の予備の手段。 ボタンが 1 つも無くても、プレイヤーは スマホの画面の左上の隅を 1 秒長押し すれば正面合わせができます(薄い十字の印が目印です)。スマホは recenter の要求を送ります。ゲームで許したくない時は Attitude → Allow Phone Recenter をオフにしてください。

イベント。 host.Recentered で、誰がなぜ正面を合わせたか(Reason: Code・Button・LongPress・Connect)が分かります:

host.Recentered += r => Debug.Log($"P{r.PlayerSlot + 1} recentered by {r.Reason}");

gyroCamera.ResetForward() は今も使えますが、正面合わせをするのは その部品だけ です。Gyro の部品の古い Calibrate With Button(Select)のオプションは、今は既定でオフです。代わりに Recenter の役割のボタンを使ってください。

9. 第二画面(映像)

スマホに絵を出す(コントローラーの第二画面)には、どれかの GameObject に PadPlay → View を付けます(または、Host の Inspector の Video のモジュールで Create a camera and attach を押します)。Video のモジュールにはチェックが入っている必要があります(既定で入っています):

  • Source Camera: 出力をスマホにだけ送るカメラ(RenderTexture は SDK が作ります)。またはSource Texture: 自分で描く RenderTexture。
  • Player Slot: 誰に見せるか(-1 = 全員に同じ絵)。
  • Width / Height(既定 1280 × 720)、Frame Rate(60)、Max Bitrate Kbps(0 = 2500)。Wi-Fi が悪くなると、ホストはここからビットレート・フレームレート・大きさを下げます(Video → Adaptive Video)。
  • Use As Touch Target(オン): そのプレイヤーのタッチがこのカメラの絵に当たるので、スマホで絵をタップすると、そこに映っている UI やオブジェクトに当たります。

誰も見ていない間はソースのカメラを止めるので、負荷はかかりません。

絵の送り方。 既定は H.264 で、Windows Media Foundation を通します(GPU のハードウェアエンコーダーが使えればそれを使います)。経路はグラフィックス API で決まります。Direct3D 11 と 12 は絵を GPU から出さずにエンコーダーへ渡します。Vulkan は CPU を通してコピーします(1 フレームほど遅れます)。OpenGL・macOS・Linux には H.264 の経路が無いので、JPEG で送ります。H.264 の復号が遅いと分かったスマホは、自分から JPEG を求めます(Codec = Auto)。失った断片は前方誤り訂正(FEC)で直し、それで直せない分は小さな復旧フレーム(エンコーダーが対応していれば。Use Ltr Recovery)か、キーフレームで直します。host.VideoStatus で、使っている経路とエンコーダー、または H.264 を使えない理由が分かります。host.GetVideoChoice(slot, out choice) で、プレイヤーが H.264 と JPEG のどちらを受けているか、その理由が分かります。

レンダーパイプライン。 絵は、全部のカメラが描き終わった後に取るので、ほかのカメラが同じテクスチャに描いた重ねの表示も入ります。ビルトインのレンダーパイプラインでは隠したカメラがこれを行い、URP(とほかの Scriptable Render Pipeline)ではフレームの描画の最後(RenderPipelineManager.endContextRendering)に行います。どちらも設定は要りません。URP では Source Camera は Base のカメラにしてください。Overlay のカメラは、Base のカメラのスタックの一部としてしか描かれません。

10. 画面のボタンと振動

ボタンのレイアウト

  1. Assets → Create → PadPlay → Button Layout(アセット → 作成 → PadPlay → Button Layout)。
  2. Elements を足します。要素はそれぞれ Id(South、East、…、DpadUp、Select、Custom14〜Custom31、LeftStick、RightStick)、Shape(Circle / Rect。スティックはいつもスティックの形)、Center と Size、Label、Opacity、必要なら Group、それと Role を持ちます。Center と Size は、スマホの映像の領域に対する割合で、(0, 0) が左上 です。そのプレイヤーに映像が無い時は、スマホの画面全体(セーフエリアの内側)に対する割合です。Orientation(レイアウトの設定)で、そのレイアウトを出している間のスマホの持ち方を選びます: Landscape(横向き。既定)、Portrait(縦向きに固定。例えば映像なしの片手のリモコン)、Auto(固定しない)。古いスマホのアプリは、どのレイアウトも横向きで出します。同じ Group のボタン(例えば十字キーや ABXY)は、指を滑らせて隣のボタンに移れます。Role を Recenter にすると、そのボタンを押した時に SDK がそのプレイヤーの正面を合わせ直します(手順 8)。None(既定)なら何もしません。
  3. アセットを Host に入れます: Host の Inspector の Buttons → Layout(全員)、またはプレイヤーごとに SetLayout で。PadPlay Setup で置いたホストには、最初から同梱の PadPlayDefaultLayout(左スティック・A・B)が入っています。欄の横の New を押すと、編集できる写しが Assets に保存されます(同梱のほうは PadPlay を更新すると置き換わります)。

再生中にアセットを編集すると、次のフレームでスマホに反映されます。触った感じを見ながら位置を調整できます。

using PadPlay;
using UnityEngine;

var layout = PadPlayButtonLayout.Create(
    new PadPlayButtonLayout.Element(PadPlayButtonId.LeftStick, PadPlayButtonShape.Circle,
        new Vector2(0.15f, 0.7f), new Vector2(0.25f, 0.45f)),
    new PadPlayButtonLayout.Element(PadPlayButtonId.South, PadPlayButtonShape.Circle,
        new Vector2(0.85f, 0.75f), new Vector2(0.1f, 0.18f), "A"),
    new PadPlayButtonLayout.Element(PadPlayButtonId.Custom20, PadPlayButtonShape.Rect,
        new Vector2(0.5f, 0.9f), new Vector2(0.2f, 0.1f), "Map"));

host.SetLayout(0, layout);       // P1 only; null = back to Settings.Buttons.Layout
// After changing layout.Elements from code, call layout.MarkChanged().

スマホのアプリは、どのボタンも少し押しやすくしています。ボタンの外側 2.5 mm までは押したことになり(一番近いボタンが優先)、押したボタンは光って短く振動します。これはアプリ側の設定で、ゲームからは変えられません。

短いタップも取りこぼしません。ボタンの変化は確実に届く経路でも送り、同じフレームに届いた「押した」と「離した」は 2 フレームに分けるので、wasPressedThisFrame はどの押下も拾えます。

Id の 0〜13 は、同じ名前の Gamepad のボタンに対応します。どの Id も pad.GetButton(PadPlayButtonId.Custom20).isPressed(または pad.GetButton(20))で読め、ゲームが決める Id は <PadPlayPad>/custom20 のようにバインドできます。

ボタンの見た目

要素はそれぞれ Style を持ちます(要素の下で開きます)。空のままなら、スマホはいつもの見た目で描きます。変える時は:

  • Image — ボタンの画像(スティックは台)。ボタンいっぱいに引き伸ばして描きます。Pressed Image — 押している間の画像(ボタンだけ。空 = Image のまわりに押した光)。Knob Image — スティックのつまみ(スティックだけ)。
  • Custom Colors — いつもの白と琥珀色の代わりに、Color(塗り。スティックは台)・Pressed Color・Border Color・Label Color を使います。値はいつもの見た目から始まるので、チェックを入れて変えたい所だけ変えてください。アルファは Opacity と掛け合わせます。
  • Custom Sizes — Border Width・Corner Radius(Rect のボタン)・Label Size を、要素の短い辺に対する割合で決めます。Label Size を 0 にすると文字を描きません(画像に文字が入っている時)。

画像がスマホに届くまで:

  • 取り込んだ Texture2D なら何でも使えます。レイアウトを送る時に、PC が画像を PNG にします。取り込みの設定で Read/Write がオンならCPU で読み、オフなら GPU を通して写します。くっきりさせたい時は Compression を None にしてください。
  • スマホは長い辺 1024 px までで描くので、それより大きい画像は送る前に縮めます。PNG にしてまだ 256 KB を超える画像は、収まるまで半分にします(警告が出ます)。1 つのレイアウトで使える画像は 64 枚・合計 2 MB までです。超えた分は送らず(警告が出ます)、そのボタンは色で描きます。
  • スマホはつないだ時に、まだ持っていない画像だけを頼み、受け取った画像を覚えます(ゲームごと、アプリのキャッシュに)。次からはすぐ画像で出て、もう送りません。届くまでの間(およそ 100 KB/秒。入力と並んで流れ、入力を待たせません)は、そのボタンを色で描きます。
  • 透明はそのまま使えるので、角が透明な丸い画像は丸く見えます。古いスマホのアプリは Style を読まず、いつもの見た目で出します。
  • 仮想スマホもスマホと同じやり方で画像を受け取ります。Game ビューのプレイヤーのプレビュー(Settings → Preview)にも出ます。
  • 再生中に Inspector で Style を変えるとレイアウトを送り直します。コードでテクスチャの画素を変えた後は layout.MarkChanged() を呼んでください。
var crystal = new PadPlayButtonStyle { Image = zoomTexture, PressedImage = zoomPressedTexture };
var plank = new PadPlayButtonStyle { Image = woodTexture, CustomColors = true, LabelColor = new Color(1f, 0.95f, 0.84f) };
var layout = PadPlayButtonLayout.Create(
    new PadPlayButtonLayout.Element(PadPlayButtonId.South, PadPlayButtonShape.Circle,
        new Vector2(0.88f, 0.76f), new Vector2(0.17f, 0.3f), style: crystal),
    new PadPlayButtonLayout.Element(PadPlayButtonId.Select, PadPlayButtonShape.Rect,
        new Vector2(0.13f, 0.88f), new Vector2(0.2f, 0.14f), "Recenter", role: PadPlayButtonRole.Recenter, style: plank));

サンプルの Floating Island がこのとおりに使っています(Layouts/FloatingIslandButtons、画像は Textures/FloatingIsland)。Minimal のサンプルは同じことをコードなしで見せています:配置のファイル Layouts/MinimalButtons だけで A に 2 枚の画像(Textures/Minimal)、スティック に専用の色を付けていて、MinimalPad.cs はいつもどおり読むだけです(buttonSouth・leftStick)。

振動

PadPlayPad は Gamepad の振動(rumble)の API を実装していて、スマホの振動モーターに伝えます:

pad.SetMotorSpeeds(0.6f, 0.6f);   // strength = max(low, high); phones have one motor
pad.SetMotorSpeeds(0f, 0f);       // stop

PauseHaptics・ResumeHaptics・ResetHaptics・InputSystem.ResetHaptics() もいつもどおり使えます。振動は 0 にするまで続きます(Host が止まると、少し後に自然に止まります)。

Input System を使わない場合(または Players → Create Devices がオフの場合)は、Host を使います:

host.SetHaptics(playerSlot: 0, strength: 0.6f);   // same throttling as SetMotorSpeeds
host.SetHaptics(playerSlot: 0, strength: 0f);     // stop

決まった長さで 1 回だけ震わせたい時(当たった・拾った)は、Pulse を使います。時間はスマホが自分で計るので、ゲームが引っかかっても伸びたり切れたりせず、後で 0 を送る必要もありません。続けて振動している最中なら、スマホはその上にパルスを重ね、終わったら元の振動に戻ります。

host.Pulse(playerSlot: 0, durationMs: 250, strength: 1f);   // false if the player is away or haptics are off

スマホのアプリは、1 回の振動を 1 秒までにしています。古いスマホのアプリは、パルスを SetHaptics の命令と同じように扱います(その場合、続けて振動している最中だとパルスが途中で切れます)。

11. トラブルシューティング

スマホごとに何が映っているか・スマホから何が届いているかを見る方法(Display 2 / 3 のプレビュー、Window → PadPlay → Debugger、ゲームの中のオーバーレイ)は デバッグ にあります。

つながらない時は Window → PadPlay → Connection Check(接続チェック)を開いてください。 下の項目をこの順に調べ、何が見つかったか・次に何をすればよいかを示し、コピーして使えるコマンドも出します。読むだけで、ファイアウォール・ネットワーク・ホストを変えることはありません。Copy report(結果をコピー)で結果をクリップボードに入れられます(不具合の報告に便利です。トークンや鍵は入りません)。ネットワークとファイアウォールはいつでも、ポートと接続の試みは再生中に調べます。Welcome の窓(Window → PadPlay → Welcome)の うまくつながらない時 にも、よくある原因の短い一覧と、Windows の設定の画面を開くボタン(開くだけです)があります。

  1. ホスト。 シーンに PadPlayHost があって動いていて、Connection → Loopback Only がオフか。→ ホストが無い: GameObject → PadPlay → PadPlay Setup。動いていない: Auto Start をオンにするか、host.StartHost() を呼びます。
  2. ネットワークと QR のアドレス。 QR コードにはこの PC の IPv4 のアドレスが並んでいて、スマホは順に試します。最初のアドレスは Wi-Fi か有線 のネットワーク アダプターの物であるべきで、スマホはそれと同じネットワークにいる必要があります(ゲスト用のネットワークや、ルーターの「AP の分離」・プライバシーセパレーターは不可)。スマホの IP アドレス(スマホの Wi-Fi の設定で見られます)がPC と同じ数字で始まるか(例: どちらも 192.168.1.)を見てください。→ 仮想のネットワーク アダプター(Hyper-V、WSL、VirtualBox、VMware、Docker)や VPN(Tailscale、Radmin、ZeroTier など)が先頭にある、または QR に Wi-Fi のアドレスが無い: Connection → Host Addresses に Wi-Fi の IP を入れます(か、そのネットワーク アダプターを無効にします)。もうこの PC の物でないアドレスがある: Host Addresses を直すか、空にします(空 = 自動)。
  3. 待ち受けのポート。 ホストは UDP ポート 7780 で待ち受けます(Connection → Port。使われていれば次の空いているポートを使い、それを QR に入れます)。→ 何も待ち受けていない: 再生を止めてもう一度再生し、Console に PadPlay のエラーが無いか見ます。
  4. Windows ファイアウォール — Unity エディタ と、あれば ビルドしたゲーム(最後に Windows 用にビルドした場所)について調べます。この 2 つは別のプログラムなので、それぞれに許可が要ります。許可はポートごとではなくプログラムごとです(通信は全部 1 つの UDP ポートです)。
    • 許可されている: 問題ありません。
    • 規則がまだ無い: 最初の接続で Windows が聞いてきます。プライベート ネットワークで 許可 を選んでください。聞かれなかった・見落とした時は、下の Windows に聞かれなかった時 を見てください。
    • ブロックされている: 誰かがそのダイアログで キャンセル を押すと ブロック の規則ができます。ブロックの規則は許可の規則より強いです。Windows Defender ファイアウォール → 詳細設定 → 受信の規則 でその規則(Unity.exe やゲームの exe の規則)を無効にしてから、プログラムを許可してください。
    • このネットワークはパブリックで、プログラムがパブリック ネットワークで許可されていない: スマホは QR コードを読めても、ここで止まります。Windows の確認で「許可」を押しても、パブリックにチェックを入れない限り許可されるのはプライベートだけで、パブリックにはブロックの規則が残ります。Wi-Fi を プライベート ネットワークにするか(設定 → ネットワークとインターネット → Wi-Fi → 使っているネットワーク → プライベート ネットワーク)、ファイアウォールによるアプリケーションの許可 でそのプログラムの パブリック にチェックを入れます。
    • TCP だけ許可されている: 何も通りません(PadPlay は UDP を使います)。UDP か全部のプロトコルを許可します。
    • 読めなかった: Windows セキュリティ → ファイアウォールとネットワーク保護 → ファイアウォールによるアプリケーションの許可 で手で確かめます。

    出てくるコマンド(管理者 のコマンド プロンプト / PowerShell で、自分で実行します):

    netsh advfirewall firewall add rule name="PadPlay Unity Editor" dir=in action=allow program="C:\Program Files\Unity\Hub\Editor\<version>\Editor\Unity.exe" enable=yes profile=private
    Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private

    管理者の権限が無いと、TCP の規則と UDP の規則を見分けられません。その時はそう表示します。

  5. 最後の接続の試み — ホストが始まってから届いたもの(host.Diagnostics.LastJoinAttempt でも読めます):
    • この PC に何も届いていない — スマホからの接続が一度も届いていません。次にすること: 同じ Wi-Fi か(2)、QR のアドレス(2)、ファイアウォール(4)。
    • 古い QR コード — スマホが前の再生のコード、または RenewToken() の前のコードを使いました(トークンか鍵が合いません)。参加済みのスマホには RenewToken() の後に猶予があります(手順 4)が、新しいスマホにはありません。次にすること: 今画面に出ている QR コードを読みます。
    • 満員 — Max Players の枠が全部埋まっているか、Accept New Players がオフです。次にすること: Max Players を増やすか、新しいプレイヤーを受け付けます。
    • プロトコルの版が違う — スマホのアプリと SDK の版が合っていません。次にすること: アプリ(か SDK)を更新します。
    • 参加した — 参加できました。

デバッガー(Window → PadPlay → Debugger)の参加の URL の横にある Check(診断)のボタンでも同じ窓が開きます。デバッガーの Events の一覧には、断った参加(JoinRejected)が全部出ます。Verbose Log をオンにすると、接続の流れと参加の URL が Console に出ます。

Windows に聞かれなかった・確認を見落とした時。Windows セキュリティの重要な警告 はいつも出るとは限らず(ほかの窓の後ろに出ることもあります)、一度答えると二度と聞かれません。手でプログラムを許可します(管理者のコマンドは要りません):

  1. Windows セキュリティ → ファイアウォールとネットワーク保護 → ファイアウォールによるアプリケーションの許可(または Welcome の窓の うまくつながらない時 にある同じ名前のボタン)を開き、設定の変更 を押します。
  2. 一覧から Unity エディタ(Unity 6000.x Editor)かゲームを探し、プライベート に、ネットワークがパブリックなら パブリック にもチェックを入れます。
  3. 一覧に無い時: 別のアプリの許可… → 参照… で Unity.exe(かゲームの .exe)を選び、ネットワークの種類… でプライベート(とパブリック)にチェックを入れて 追加 します。

そのあと、ネットワークがプライベートか確かめます: 設定 → ネットワークとインターネット → 使っている Wi-Fi → プロパティ。

それでもつながらない時: ほかによくある原因。

  • VPN や、ウイルス対策ソフトの独自のファイアウォール: Windows の設定はそれには効きません。VPN を切り、そのソフトで Unity エディタ・ゲームを許可します。
  • iPhone: PadPlay アプリに ローカルネットワーク を許可します(設定 → プライバシーとセキュリティ → ローカルネットワーク)。
  • 会社・学校のネットワークは、端末どうしの通信を止めていることが多いです。家の Wi-Fi などで試してください。

タッチが透明なピクセルを無視しない / 「texture is not readable」の警告が出る。PadPlayRaycaster はスプライトのピクセルを読む必要があります。テクスチャのインポート設定で Read/Write を有効にしてください(Advanced → Read/Write)。Sprite Atlas に入っているスプライトは、アトラスのほうで有効にします。読めないテクスチャでは、四角形での当たり判定になります。

タッチが違う UI に当たる。カメラを割り当てたプレイヤーは、そのカメラの絵にしか当たりません。Touch → More → Player Targets とPadPlayView.UseAsTouchTarget を確かめてください。RaycastOnlyPlayerScreen = false にすると「手前にある物に当たる」に戻ります。

映像が黒い・遅い・ぼやける・乱れる。

  • Direct3D 11 / 12(一番速い)か Vulkan(1 フレーム遅れる)を使ってください。OpenGL・macOS・Linux は JPEG だけです。
  • まずハードウェアエンコーダーを試し、だめなら Windows のソフトウェアエンコーダー(遅い)を使います。確かめたハードウェアエンコーダーは、今のところ NVIDIA のものだけです。
  • Inspector と host.VideoStatus で、使っている経路とエンコーダー、または H.264 を使えない理由(その時は JPEG を送ります)が分かります。host.GetVideoChoice(slot, out choice) で、スマホがどちらを受けていて、その理由(例えばスマホが JPEG を求めた)が分かります。
  • Wi-Fi が弱い時は Adaptive Video をオンのままにし(ビットレートを、次にフレームレートか大きさを下げます)、好みの Priority を選ぶか、View の Max Bitrate Kbps を下げてください。複数のプレイヤーに送る View は 1 回だけエンコードし、一番弱い接続に合わせた画質になります。
  • ブロック状のノイズ・にじみ・短い止まりが時々出るのは、たいてい Wi-Fi でパケットが落ちているためです。スマホをルーターの5 GHz の Wi-Fi につないでください(2.4 GHz は混みやすく、Bluetooth や電子レンジとも電波を分け合います)。ルーターの近くで使い、PC はできれば有線にしてください。Debugger の Video の列で、落ちの割合と、スマホが映像の戻しを頼んだ回数が分かります。こうした落ちが短い間に続くと、SDK は早めにビットレートを下げ(続けば 60 → 30 fps)、Wi-Fi が落ち着くとまた上げます。
  • Display のプレビューでも黒い: ソースのカメラか RenderTexture の問題です。PadPlay Lite には映像はありません。

Wi-Fi が弱いことをプレイヤーに知らせたい(任意)。Wi-Fi が弱い時、SDK は自分で映像を下げるだけで、PC にもスマホにも何も表示しません。「スマホを 5 GHz に」のような案内を出したい時は、プレイヤーごとの回線の状態を読んでください: host.GetConnectionQuality(slot) か ConnectionQualityChanged のイベント(Level: Good・Poor・Bad、Issue: Loss(落ち)か Delay(遅れ))。悪くなる時はすぐ、良くなる時は数秒落ち着いてから変わるので、案内がちらつきません。F3(PadPlayDebugOverlay)と Debugger の 回線 の列にも同じ値が出ます。

using PadPlay;
using UnityEngine;

// Shows a hint while a player's Wi-Fi loses packets (the SDK itself shows nothing).
public class WifiHint : MonoBehaviour
{
    [SerializeField] PadPlayHost _host;
    [SerializeField] GameObject _hint;   // for example a text "Weak Wi-Fi: put your phone on the 5 GHz network"

    void OnEnable() => _host.ConnectionQualityChanged += OnQuality;
    void OnDisable() => _host.ConnectionQualityChanged -= OnQuality;

    void OnQuality(PadPlayConnectionQuality q)
    {
        // Loss is what 2.4 GHz Wi-Fi usually shows; Delay is a slow or busy network. q.PlayerSlot says whose phone it is.
        _hint.SetActive(q.Level != PadPlayConnectionLevel.Good && q.Issue == PadPlayConnectionIssue.Loss);
    }
}

そのプレイヤーのスマホに出したい時は、PadPlayPhoneOverlay か host.SetPhoneOverlay(q.PlayerSlot, items) を使ってください。

プレイヤーがアプリを起動し直したら「正面」がずれた。これは想定どおりです(スマホのヨーの基準が変わり、遊んでいる間もヨーは少しずつずれます)。正面合わせ(手順 8)をしてください:Role が Recenter のレイアウトのボタン、host.Recenter(slot)、またはプレイヤーがスマホの画面の左上の隅を長押しします。

スマホが振動しない。Buttons にチェックが入り、Allow Haptics がオンか確かめてください(振動は Buttons のモジュールの機能です)。Haptic Strength Scale が 0 より大きいかも見てください。スマホ側では、システムの振動の設定やおやすみモードで止まることがあります。ホストが振動を送ると、デバッガーの Events の一覧に HapticSent が出ます。

12. サンプル

一番早いのは Window → PadPlay → Import All Samples(または Welcome の窓の Import all available samples and open the Sample Hub)です。全部のサンプルを Assets/Samples に入れ、シーンを Build Settings に足し、Sample Hub を開きます。1 つだけ入れる時は、Package Manager → PadPlay → Samples → Import を押してから、そのシーンを開きます。

  • Sample Hub(まずはここから) — Scenes/Hub。全部のサンプルを選べるメニュー。QR コードを 1 回読み、スマホをカードに向けて A を押します。スマホの Menu か PC の Esc で、つながったまま戻れます(Keep Across Scenes、Remote Pointers)。ミニゲーム Target Pop(Scenes/HubTargetPop)つき。PadPlay Lite にもあります。
  • Minimal(まねして書くための 1 本) — Scenes/Minimal。一番短い PadPlay のゲーム: 約 35 行のスクリプト 1 つ(Scripts/Minimal/MinimalPad.cs)。QR コードで参加し、スマホの A で振動、スマホを傾けると模型が回り、スティック(pad.leftStick)を倒すかスマホでドラッグすると点が動きます(ドラッグはふつうの uGUI の IDragHandler)。ほかは全部シーンの部品です。配置のファイル(Layouts/MinimalButtons)は、コードなしのボタンの見た目の例でもあります: A は 2 枚の画像で、スティックは専用の色で描かれます。PadPlay Lite にもあります。
  • Treasure Map(ミニゲーム) — Scenes/TreasureMap。2 つの画面で 1 つの宝探し: スマホのスティックかキーボードで画面の上を歩き、スマホはその人の X だけが描かれた紙の宝の地図になります。プレイヤーごとの第二画面、ゲームの画像で描くスティック、振動、モジュールの選び方。PadPlay で何ができるかが一番よく分かります。
  • Floating Island(ミニゲーム) — Scenes/FloatingIsland。画面で狙い、スマホでのぞき、PC のキーで撃つ: スマホはそれぞれ望遠レンズ(PadPlayPoseCamera。水晶のボタンでさらにズーム)になり、画面にはスマホが向いている所に光る輪が出ます。スマホにしか見えない光を 5 つ見つけます。PadPlayPoseCamera、PadPlayPhoneOverlay(照準)、host.Pulse、ゲームの画像で描くボタン、PC のキーとスマホの組み合わせ。2 人まで。8 番に PhoneOnly という名前のレイヤーが要ります(下を参照)。
  • Gyro Window — Scenes/GyroWindow。2 人がスマホを窓にして 3D の部屋をのぞきます。スマホに出る絵は 1 人ずつ違います(PadPlayGyroCamera + PadPlayView)。スマホを画面に向けて Recenter を押してから始めます。
  • Room Dive — Scenes/RoomDive。2 人専用(PC 1 台 + スマホ 1 台): 4 つの部屋での、役割の違う協力プレイ。スマホの人はスマホの矢印のボタンで部屋を選び、どの部屋にいるかを言います。その部屋の星をクリックすると、スマホの人に数秒だけ見えるようになります。スマホの人はスマホで見回し、その星を出口へドラッグします。3D のオブジェクトへのタッチを標準のイベントで受ける、スマホには描かないカメラのレイヤー、PadPlayPhoneOverlay、振動。

URP のプロジェクトでは。 Treasure Map・Floating Island・Room Dive は、3D のオブジェクトにビルトインの Standard シェーダーを使っていて、URP ではピンクに描かれます。そこで Scriptable Render Pipeline が有効な時は、再生を始めた時に、各サンプルが自分のレンダラーのマテリアルを、パイプラインの Lit シェーダーを使う写しに切り替えます(色・メインのテクスチャ・Smoothness・Metallic・Emission・透明度を写します)。エディタで遊ぶだけなら変換は要りません。Gyro Window と Minimal は Unlit/Color を使っていて、URP でもそのまま描かれます。

URP での Player ビルド: メニューを 1 回。 ビルドには、そのマテリアルが使うシェーダーしか入らないので、サンプルにはビルドに入る*Lit* のマテリアルも要ります。サンプルを入れた後に Window → PadPlay → Prepare Samples for URP or HDRP を選んでください。各サンプルの小さな <Sample>SrpLitSet アセット(その Materials フォルダの中)に、Lit のマテリアル(隣の <Sample>SrpLit フォルダの中)を入れます。サンプルのシーンはそのアセットを参照しているので、Lit シェーダーがシーンと一緒にビルドに入ります。Import All Samples(と Welcome の窓の Import all available samples and open the Sample Hub)は、これを自動で行います。後から 1 つずつサンプルを入れた時や、プロジェクトを別のパイプラインに切り替えた時は、もう一度実行してください。全部そろっていれば何も書きません。スクリプトの再読み込みやビルドの前に勝手に動くことはなく、Always Included Shaders などのプロジェクトの設定にも触れません。実行しなくてもエディタではサンプルを遊べますが、Player ビルドでは Standard のオブジェクトが描かれず、Player のログがこのメニューを案内します。マテリアルのアセット自体は変えません。ビルトインのプロジェクトでは、このメニューは何もしません(アセットは空のまま)。URP のプロジェクトでマテリアルを編集したい場合は、これまでどおり Edit → Rendering → Materials → Convert Selected Built-In Materials to Current SRP で変換できます(残したいビルトインのマテリアルがプロジェクトにある時は、Convert All… は避けてください)。サンプルのスクリプトは _Color と _BaseColor の両方を設定するので、どちらでもハイライトが効きます。HDRP はまだ確かめていません。

Sample Hub と Target Pop

Scenes/Hub を開いて再生します。画面にサンプルごとのカードが出ます。QR コードを 1 回読み、スマホをカードに向けて A を押すと、そのサンプルが開きます(マウスでも選べます)。シーンが変わってもスマホはつながったままです。Hub の Host で Keep Across Scenes(シーンをまたいで保つ)にチェックが入っているためです(仕組み: シーンをまたぐ)。サンプルの中では、スマホの小さな Menu のボタンか PC の Esc で Hub に戻ります。灰色のカードは、そのサンプルをまだ入れていないことを示します(PadPlay Lite では、PadPlay SDK だけにあるサンプルであることを示します)。Target Pop・Treasure Map・Floating Island のカードには*MINI-GAME* の札が付いています。

Target Pop は Hub の中の小さなポインターのゲームです。画面に的が出ては薄れて消えていきます。スマホを的に向けて A を押すと割れます。割るたびにそのプレイヤーに 1 点が入り、短く振動します。1 ラウンドは 30 秒で、1〜4 人で遊べます。Remote Pointers の見本です。的は IPointerClickHandler を持つふつうの uGUI のオブジェクトで、PadPlayPointerEventData.PlayerSlot で誰が割ったかが分かります。

Treasure Map(2 つの画面で 1 つの宝探し)

Scenes/TreasureMap を開いて再生します。画面(Game ビュー)には上から見た島が出て、スマホはそれぞれその人だけが見られる、古い紙の宝の地図 になります。両方の画面が要ります。画面の上を歩き、地図は手の中にあります。

遊び方

  • 1 台か 2 台のスマホで QR コードを読みます。最初のスマホが参加するとラウンドが始まり、150 秒続きます。
  • 画面の上を歩きます: スマホの地図の左右にある方位磁針のスティックのどちらかをドラッグ するか、キーボードでP1(最初のスマホ)は WASD、P2 は矢印キー(または PC につないだゲームパッドの左スティック)。スティックとキーは足し合わされます。地図そのものはタッチを受けません。
  • 地図には島の目印(浜・池・木・岩・桟橋)、方位、自分の宝(X) が描かれていますが、自分がどこにいるかは描かれていません。目印を画面の島と見比べて、どこへ行けばよいかを考えます。自分の X は、画面にもほかの人のスマホにも出ません。
  • 木・岩・池・海・もう 1 人のプレイヤーは通れません。
  • 宝に近づくと地図が弱く震え、見つけると強く震えます(上を歩くだけで見つかります)。その場所は見つけた印が付き、別の場所に新しい X が描かれます。一番多く宝を見つけた人がそのラウンドの勝ちです。
  • スマホなしでは遊べません。地図はスマホにしか無いためです。エディタで見るには、Display 2 / 3 のプレビューを使ってください(デバッグ)。

見られること

  • プレイヤーごとの第二画面 — プレイヤーごとのスマホの UI(UI のレイヤーだけを見るカメラを PadPlayView で送る)が、その人の X が入った紙の地図を出します。画面のカメラは UI のレイヤーを描きません
  • シーンから描く地図 — 島のオブジェクトそれぞれに TreasureMapLandmark。TreasureMapPaper が、紙・インク・焦げた縁を実行時にテクスチャに描きます(画像のファイルは使いません)
  • Input System を使わない振動 — host.SetHaptics(slot, strength)
  • ゲームの画像で描くスティック — Layouts/TreasureMapButtons: 左右のスティック(pad.leftStick・pad.rightStick)を、方位磁針と真鍮のつまみの画像(スタイルの Image と Knob Image)で地図の左右の空きに置きます
  • モジュールの選び方 — Buttons(スティックと振動)と Video にチェック。Touch と Attitude はチェックなし

手触りの値(歩く速さ、どこまで近づけば「見つけた」になるか、振動の強さ、ラウンドの長さ、地図に自分の位置を出すか: Show Self On Map)は全部 TreasureMapGame → Settings にあり、再生中に変えられます。

Floating Island(画面で狙い、スマホでのぞく)

Scenes/FloatingIsland を開いて再生します。画面(Game ビュー)には浮島の全体が出て、ゆっくり周りを回ります。スマホはそれぞれ同じ世界を、プレイヤーが向けた方向にのぞく 望遠レンズ になり(Pose Camera)、PC のキーで撃ちます。3 つとも要ります。画面でどこを見るか見当をつけ、スマホでそこに何があるかを見て、キーボードで撃ちます。2 人まで遊べます。1 人でも、片手にスマホ、もう片手をキーボードに置いて遊べます。

遊ぶ前に。 隠れた光はレイヤー 8 にあり、画面のカメラはこのレイヤーを描きません。Project Settings → Tags and Layers(プロジェクト設定 → タグとレイヤー)で、レイヤー 8 に PhoneOnly という名前を付けてください。レイヤーは番号で効くので名前が無くても動きますが、再生のたびに 1 回警告が出ます。また、自分のオブジェクトをレイヤー 8 に置いていると、このサンプルの画面には映りません。

遊び方

  • 1 台か 2 台のスマホで QR コードを読みます。まだ参加できる間は、画面に QR の板が出ています。
  • スマホを島に向けます。画面の島の上を、自分のプレイヤーの色の光る輪が動きます。輪の内側が、だいたいスマホに拡大して映っている所です。スマホの画面の真ん中には照準の印が出ます。
  • PC のキーで撃ちます: P1 は Space、P2 は Enter(または PC につないだゲームパッドの下のボタン / 右トリガー。つないだ順)。弾は照準を通ります。P1 は R、P2 は Backspace(ゲームパッドでは Select)で、スマホが今向いている方向を正面にします。
  • スマホにはボタンも 2 つあり、サンプル専用の画像で描かれています。水晶 でレンズをズームし(もう一度押すと戻ります。スマホに Zoom x2.5 と出ます)、木の板 でスマホが今向いている方向を正面にします。スマホでは撃てず、タッチの操作もありません。ほかの所はレンズです。
  • 何かを撃つと調べられます。スマホにその名前が出て、少しの間自分のプレイヤーの色で光り、スマホが弱く震えます。
  • 島の周りに光が 5 つ隠れていて、スマホにしか見えません。画面では かすかな火花 でしか分かりません。画面で場所の見当をつけ、スマホでのぞいて確かめてください。光を撃つと見つかり、スマホが強く震えて、画面にも光が出ます。画面には、見つけた数と、プレイヤーごとに最後に撃った物が出ます。
  • 5 つ全部見つけると、短いお祝いの演出(光の柱・渦を巻く欠片・花)が出ます。20 秒後に光はまた隠れます。全員が抜けた時も、また隠れます。
  • スマホが無い時は、仮想スマホ(Window → PadPlay → Virtual Phones。スマホの画面の上を右ドラッグで回せます)と、いつもどおりキーボードを使ってください。

見られること

  • Pose Camera — プレイヤーごとのカメラに PadPlayPoseCamera + PadPlayView。PC はスマホの向きで描き、スマホはそのフレームから回った分を補正します。視野角がレンズの倍率です
  • PC からスマホ越しに狙う — FloatingIslandGame.Shoot が、Pose Camera の真ん中を通る光線を飛ばします(スマホは絵を今の向きに回して出すので、カメラの今の正面が照準になります)
  • 画面で、スマホがどこを向いているか — FloatingIslandAim が、その光線が島に当たる所に、レンズに映る大きさに合わせて輪を描きます。FloatingIslandFrustum は視錐台を描きます。どちらもスマホのカメラが描かないレイヤー(UI)に描くので、画面にだけ出ます
  • 画面にだけ出すヒント — FloatingIslandHints が、まだ見つかっていない光の周りに、同じ UI のレイヤーでかすかな火花を描きます
  • スマホの画面に固定した文字と照準 — PadPlayPhoneOverlay: スマホが映像の上に描くので、補正しても動きません。その四角形は VisibleViewportRect に合わせます
  • 決まった長さの振動 — host.Pulse(slot, durationMs, strength)(時間はスマホが計ります)
  • スマホにしか見えない物 — レイヤー 8(PhoneOnly)は画面のカメラが描きません。見つけた光は Default に移ります
  • コードからの正面合わせ — R / Backspace で host.Recenter(slot)。Pose Camera もそれに従います
  • PC のキーとスマホを一緒に — FloatingIslandControls が全部のキーボードと PC のゲームパッドを読みます(スマホの PadPlayPad は読みません)
  • ボタンの見た目 — Layouts/FloatingIslandButtons: 水晶のズームのボタンは画像と押した時の画像(押すたびに FloatingIslandControls がズームを切り替えます)、正面合わせの板(Role = Recenter。コードは要りません)は画像と自分の文字の色(ボタンの見た目)
  • モジュールの選び方 — Attitude・Buttons・Video にチェック。Touch はチェックなし。Max Players は 2

手触りの値(レンズの倍率。ふだんと水晶でズームした時、振動の強さと長さ、名前とハイライトが残る時間、お祝いの長さ)は全部 FloatingIslandGame → Settings にあり、再生中に変えられます。キーは FloatingIslandControls、輪と火花は FloatingIslandAim と FloatingIslandHints、画面のカメラの回る速さは FloatingIslandOrbit にあります。

Room Dive(2 人専用: PC の人とスマホの人)

Package Manager → PadPlay → Samples → Room Dive → Import を押してから、Scenes/RoomDive を開きます。ちょうど 2 人が要ります: PC でマウスを持ち、部屋を上から見ている人と、スマホを持って部屋に潜る人(Diver)です。1 人では遊べず、2 台目のスマホは断ります(Max Players 1)。スマホが参加するまでは、画面にそう出ます。画面には 4 つの小さな部屋(Red・Blue・Green・Purple)が、上から見た形で出ます。スマホは、Diver がいる部屋の中から見た窓になります。部屋を決めるのはスマホ側です: 画面には Diver がどの部屋にいるかは出ません。

遊び方

  • Diver が QR コードを読み、最初の部屋に潜ります。スマホに部屋の名前が大きく出ます(RED ROOM)。
  • Diver はどの部屋にいるかを声で伝えます(「赤い部屋にいる!」)。スマホの矢印のボタン < / > で、星の残っている前 / 次の部屋へ移ります。
  • 星は画面にだけ描かれています。 Diver のスマホには出ません。
  • Diver のいる部屋の星をクリックすると、スマホの人に見えるようになります: Diver のスマホに数秒だけその星が出ます(最後は点滅して薄れます)。どこにあるかを声で伝え合ってください(「右の棚の上!」)。クリックで Diver は移りません。別の部屋の星は見えるようにならず、その部屋の札に少しの間 The phone player is not here と出ます。
  • Diver はスマホを傾けて見回し、見えるようになった星に触れて、黄色の 出口 の枠まで運ぶと集められます(運んでいる星は見えたままです)。星が見えるようになった時、見えている星が視界の真ん中に近い時(弱く)、集めた時(強く)、スマホが震えます。
  • 部屋が空になると、Diver は星の残っている次の部屋へ自分で進みます。
  • 4 つの部屋の星を全部集めると、次の回が始まります。Select("Recenter"、Role は Recenter)で視界の正面を合わせ直します。スマホが切れても、その部屋は残り、PC の人は再接続するまで待ちます。

見られること

  • プレイヤーごとの第二画面 — Diver のカメラに PadPlayView + PadPlayGyroCamera(Window モード)。
  • 画面にだけ出す物 — まだ見えるようにしていない星はビルトインの UI レイヤー(5)にあり、Diver のカメラはこれを Culling Mask から外しています。PhysicsRaycaster も Culling Mask を使うので、スマホからも触れません。レイヤーを足す必要はありません。
  • 3D のオブジェクトへのタッチを標準のイベントで — RoomDiveStar は IBeginDragHandler / IDragHandler / IEndDragHandler だけを実装しています。カメラには PhysicsRaycaster があります。
  • 誰が触ったか — eventData is PadPlayPointerEventData p → p.PlayerSlot(RoomDiveGame.CanCarry)。マウスでは星を運べません。
  • 画面でのマウス — RoomDiveGame が Camera.pixelRect で部屋を、WorldToScreenPoint で一番近い星を見つけます。
  • スマホの画面に固定した文字 — PadPlayPhoneOverlay と RoomDivePhone(大きな部屋の名前、今すること、星)。
  • ボタン — Layouts/RoomDiveButtons: Recenter = Role が Recenter の Select、< / > = DpadLeft / DpadRight(RoomDiveGame が pad.GetButton(id).wasPressedThisFrame で読みます。Buttons のモジュールは振動も受け持ちます)。
  • 振動 — pad.SetMotorSpeeds(strength, strength)。
  • プレイヤーの状態 — host.GetPlayerState(slot): Gone 以外なら部屋を残すので、切れた Diver を待てます。
  • QR と状態の表示 — PadPlayQrView(スマホが参加したら隠れます)と PadPlayStatusView。

手触りの値(見えるようにした星が出ている時間と薄れる時間、画面でのクリックの半径、not here の案内が出ている時間、振動の強さ、「近い」とみなす角度、運べる距離、次の回までの間、Diver の頭と部屋を画面に出す Show Phone Player On Screen)は全部*RoomDiveGame → Settings* にあり、再生中に変えられます。
