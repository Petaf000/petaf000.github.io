デバッグ

English

Unity エディタから出ずに、3 つの疑問に答えるための道具です:スマホはつながっているか? スマホから何が届いているか? スマホの画面には何が映っているか?

  • Display のプレビュー(Game ビュー → Display 2、Display 3、…) — プレイヤーごとのスマホの画面(映像・指・ボタン)を、メインの画面と並べて見る。
  • PadPlay デバッガー(Window → PadPlay → Debugger) — 接続の状態、往復の時間、入力の頻度、ボタンのビット、ジャイロ、タッチ、イベントの記録。正面合わせ、振動のテスト、切断。
  • デバッグ表示(Add Component → PadPlay → Debug Overlay) — ビルドしたゲーム に出す小さな状態の表示(F3 で表示・非表示)。
  • host.Diagnostics(C#) — 同じ数字を、自分のコードや道具から読む。
  • 接続チェック(Window → PadPlay → Connection Check) — スマホがつながらない・Connecting のまま進まない理由: QR のアドレスとネットワーク アダプター、ポート、Windows ファイアウォール、最後の接続の試み。読むだけです。クイックスタート §11 を参照。
  • 仮想スマホ(Window → PadPlay → Virtual Phones) — エディタの中の仮想のスマホ: タッチはマウス、ボタンはマウスかキー、傾きはマウスで球をドラッグ。スマホは要りません。
  • Input Debugger(Unity)(Window → Analysis → Input Debugger(ウィンドウ → 解析 → Input Debugger)) — Input System が PadPlayPad のデバイスをどう扱っているか(バインド、アクション、PlayerInput)。

最初の 4 つはホストを 読むだけ で、ゲームが受け取る物を変えることはありません。仮想スマホは本物のスマホと同じように入力を送ります。Host の Inspector の Debug の節(Modules と Connection の間)に、プレビューの設定と、デバッガーを開くボタン・デバッグ表示を足すボタンがあります。

1. Display のプレビュー: スマホごとの画面を Display 2・3… に

エディタで再生している間、ホストはスマホごとに映っている物をそれぞれのディスプレイに描きます:P1 → Display 2、P2 → Display 3、以下同様です。Display 1(ゲームの画面)には一切触れません。

  1. 2 つ目(と 3 つ目)の Game ビュー を開きます: Game のタブを右クリック → Add Tab → Game。
  2. 新しい Game ビューの左上のドロップダウンで、それぞれ Display 2 / Display 3 を選びます。必要なら大きさをタブレットの解像度(例えば 1920 × 1200)に合わせてください。絵の縦横比は保たれます。
  3. 再生 してスマホをつなぎます。

各ディスプレイに見える物:

  • 黒 — ディスプレイのうち、スマホの外の部分。
  • 濃い灰色 — スマホの画面(縦横比はスマホが知らせた大きさから。スマホが縦向きと知らせない限り横向き)。
  • 映像 — そのプレイヤーに送っている PadPlayView のテクスチャ。スマホと同じように上下左右に帯を入れて収めます(映像の縦横比。映像がまだ無い時は 16:9)。ボタンはあるが映像が無いプレイヤーは、スマホのアプリと同じく、スマホの画面全体を使います。
  • 重ねの表示 — プレイヤーの指(プレイヤーの色の点)と、そのプレイヤーのレイアウトの画面のボタン。押しているボタンは、押している間プレイヤーの色で光ります(押した後も少なくとも Button Highlight Ms の間光らせることもできます)。スティックのつまみはスティックの値に合わせて動きます。
  • 見出し — プレイヤー、ディスプレイ、状態、スマホの機種、往復の時間。スマホが無い時は waiting for a phone と出ます。

設定: Host の Inspector → Debug(host.Settings.Preview)。どれも再生中に変えられます。

  • Mode(既定 EditorOnly) — Off、EditorOnly(ビルドしたゲームでは何も出さない)、EditorAndBuilds(ビルドしたゲームでも、つながっている追加のモニターを有効にして使う)。
  • Player Displays(既定 2, 3, 4, 5) — プレイヤーごとの Display の番号。要素 0 が P1 です。0 でそのプレイヤーを出しません。1 は使えません(ゲームの画面のため)。
  • Show Touches / Show Buttons(既定 オン) — 重ねの表示の部品。
  • Overlay Opacity(既定 0.6) — 重ねの表示の濃さ。
  • Show Caption(既定 オン) — 上の文字の行。
  • Button Highlight Ms(既定 0) — 0 = 押している間だけ光る(ゲームが読む値)。0 より大きいと、押したボタンは押した後も少なくともこの時間光ります。プレビュー・デバッガー・デバッグ表示に効きます。デバッガーの Min lit ms(最短点灯 ms)でも変えられます。

仕組み: ホストは表示するプレイヤーごとに(シーンの階層の外に、保存しない形で)、ディスプレイを黒で消すだけのカメラ(cullingMask = 0)と、そのディスプレイの Screen Space – Overlay の Canvas を作ります。Canvas にはGraphicRaycaster が無いので、マウスのクリックやスマホのタッチが当たることはありません。映像はエンコードしているのと同じ RenderTexture なので、プレビューのために余分に描くことはありません。

2. PadPlay デバッガー

Window → PadPlay → Debugger(または Host の Inspector の Debug の節の Open Debugger)。再生するまでは何も出ません。

上の帯 — ホスト、動いているかとそのポート、プレイヤーの数、新しいプレイヤーを受け付けているか、Join URI(参加 URI)と Copy(カメラでコードを読めない時に、スマホのアプリに貼り付けます)、QR の切り替え。

Players — ホストが始まってから参加したプレイヤー枠ごとに 1 行:

  • Device — スマホの機種と OS。
  • State — Connecting(参加した、まだ入力が流れていない)、Ready、Reconnecting(切れた。枠は Resume Hold Seconds の間取っておく)、Gone(抜けた。理由は括弧の中)。
  • RTT ms — PadPlay Link の往復の時間: パケットが返す時刻の印から測った、直近の往復の中央値(ClockSync.RoundTripMs)。
  • Clock ms — スマホの時計 − PC の時計(ClockSync.OffsetMs)。
  • Touch / Gyro / Btn Hz — スマホからの 1 秒あたりの入力の更新。PadPlay Link はパケットごとに状態を丸ごと送るので、数えているのはパケットではなく変化です: Touch = 押している指が動いた回数(押した・離したは数えない)、Gyro = 新しい姿勢の標本、Btn = ボタンとスティックの変化。Touch と Btn は、何も動かない・変わらない間は 0 です。(off) = 届いているが、モジュールのチェックが外れているのでホストが捨てている。
  • Last in — 最後に何かの入力が届いてからの秒数。
  • Video — エンコーダーの今の解像度とフレームレート(ネットワークが遅いと下がります)と、映像のパケットの実測のビットレート(FEC 込み。送る側の統計から 1 秒ごと。H.264 か JPEG)。最後の欄は 1 フレームのエンコードの時間(PadPlayVideoStats.EncodeMsPerFrame)です: そのプレイヤーに送った最近の約 10 フレームについて、描き終えてからエンコードが終わるまでの時間の平均(H.264 は色の変換とエンコーダー、JPEG は GPU からの読み戻しと JPEG のエンコーダー。待ち時間も含みます)。測れない時は — で、マウスを重ねると理由が出ます(そのプレイヤーにまだ 1 フレームも送っていない、またはエンコーダーが時間を返していない)。
  • Rot — スマホの画面の回転(度)。

選んだプレイヤーの詳細(最初の列の P1、P2、… をクリック):

  • Buttons — ゲームが読む 32 個のボタン(そのプレイヤーの PadPlayPad、デバイスがオフなら ButtonsReceived の値):0〜13 は Gamepad のボタン(A/South … 右スティックの押し込み)、14〜31 は custom14〜custom31 です。押しているボタンは、Input Debugger とまったく同じく、押している間プレイヤーの色で描きます。グリッドの下の Min lit ms(= Settings.Preview.ButtonHighlightMs、既定 0)を使うと、押したボタンをその時間、薄い色で光らせたままにできます。各マスの小さな数は 再生を始めてから押された回数 です(見出しには合計が出ます)。ボタンを 10 回タップしたら 10 になるはずです。少なければ、押下がゲームに届く前に失われています。数は合っているのに光ったのが見えなかったなら、描画が遅かっただけです。再生中でこの窓が見えている間は、毎フレーム描き直します。
  • Sticks — 左右のスティックの値(−1〜1、y は上が +)。
  • Attitude — スマホの形の箱(画面の面はプレイヤーの色)と、オイラー角と角速度。プレイヤーに PadPlayPad があれば校正後の pad.attitude、無ければスマホの生の姿勢を出します。
  • Touches — スマホの映像の領域の上の指(0〜1、y = 0 が上)と、その ID。
  • Recenter (yaw / full) — そのプレイヤーのパッドの正面を合わせ直します(pad.Recenter(...)。Recentered が出ます)。Test haptics — host.SetHaptics で 0.3 秒振動させます。Disconnect — host.Kick(slot)(枠は取っておきません)。

Events — ホストの記録: ホストの開始・停止、参加、再開、準備完了(映像が変わった後にもう一度)、退出、枠の解放、レイアウトの送信、振動の強さの変化(同じ値の繰り返しは記録しません)、校正の送信、画面の回転、断った参加(JoinRejected: bad_token、full、version)。種類・文字・選んだプレイヤーで絞り込めます。Pause で一覧を止めます(ホストは記録を続けます)。Clear で空にします。ホストは最後の 512 件を取っておきます。

3. デバッグ表示(ビルドしたゲームで)

どれかの GameObject に Add Component → PadPlay → Debug Overlay(または Host の Inspector の Add Debug Overlay)。プレイヤーの数と、プレイヤーごとの状態・スマホの機種・往復の時間、準備完了のプレイヤーから 1 秒以上何も届かない時の警告、そして(ボタンが押されてからは)光っているボタンと押された回数(buttons: South (12 presses)。デバッガーと同じく少なくとも Button Highlight Ms の間光ります)を小さな箱に描きます。毎フレーム作り直します。IMGUI を使っています(Canvas も EventSystem も使いません)。

  • Host(既定 シーンから見つける)
  • Toggle Key(既定 F3) — 表示・非表示を切り替える Input System のキー(None = キーなし)。
  • Visible(既定 オン) — 始めから表示する。
  • Corner(既定 TopLeft)
  • Font Size(既定 18) — 画面の高さが 1080 px の時の大きさ。画面に合わせて拡大・縮小します。

4. 同じデータをコードから読む

using System.Collections.Generic;
using PadPlay;
using UnityEngine;

PadPlayDiagnostics diagnostics = host.Diagnostics;
foreach (PadPlayPlayerDiagnostics player in diagnostics.Players)
{
    Debug.Log($"P{player.PlayerSlot + 1} {player.State} {player.Device.Model} " +
              $"gyro {player.AttitudeRateHz:F0} Hz, fingers {player.Touches.Count}, buttons {player.Buttons.Bits:X8}");
}

var events = new List<PadPlayDebugEvent>();
diagnostics.CopyEvents(events);      // oldest first; diagnostics.TotalEventCount tells you when new ones arrived
  • host.Diagnostics — PadPlayDiagnostics: Players、TryGetPlayer(slot, out player)、LastJoinAttempt(JoinAttempt: RemoteAddress、AtMs、Result = Accepted / BadToken(古い QR コード: トークンか鍵が合わない)/ Full / Version、PlayerSlot。null = まだ何もつながっていない)、JoinAttemptCount、EventCount、TotalEventCount、GetEvent(i)、CopyEvents(list)、ClearEvents()、EventCapacity(512)。
  • PadPlayPlayerDiagnostics — PlayerSlot、Device、AppVersion、State、LeftReason、JoinedHostMs、ResumeCount、TouchRateHz、AttitudeRateHz、ButtonsRateHz、LastTouchHostMs、LastAttitudeHostMs、LastButtonsHostMs、LastInputHostMs、Touches、HasAttitude、Attitude、HasButtons、Buttons(最後に受け取った状態)、GameButtonBits(今押されているボタン。ゲームが読む値)、TotalButtonPresses、GetButtonPressCount(id)、GetButtonLastPressedHostMs(id)、GetButtonLastReleasedHostMs(id)、IsButtonLit(id, nowMs, minLitMs)、GetLitButtonBits(nowMs, minLitMs)、HasScreenRotation、ScreenRotationDegrees、HapticStrength、LayoutsSent、PacketsReceived(入力の更新。Hz の列と同じ数え方)。時刻は PadPlayHost.NowMs の時計です(−1 = 一度も無い)。
  • PadPlayDebugEvent — HostMs、PlayerSlot(−1 = ホスト)、Kind(PadPlayDebugEventKind)、Detail。
  • 映像(PadPlayHost の) — VideoStatus(グラフィックス API の経路、エンコーダー、プレイヤーごとのコーデック、または H.264 を使えない理由。人が読むための英語の文)、GetVideoChoice(slot, out PadPlayVideoCodecChoice)(Codec、列挙型の Reason、Detail)、RequestVideoStats(slot, callback)(PadPlayVideoStats。Video の列の数字)。
  • host.Settings.Preview — PadPlayPreviewSettings: Mode(PadPlayPreviewMode)、PlayerDisplays、ShowTouches、ShowButtons、OverlayOpacity、ShowCaption、ButtonHighlightMs(0)、IsActive(isEditor)、GetDisplay(slot)。
  • PadPlayDebugOverlay — Host、Visible、ToggleKey、BuildText()。

入力の数には、チェックを外したモジュールの入力も入っています(届いた後でホストが捨てた物)。そのため、「スマホが何も送っていない」のか「モジュールがオフ」なのかを見分けられます。

5. スマホなしで試す: 仮想スマホ

Window → PadPlay → Virtual Phones(または Host の Inspector の Debug の節の Virtual Phones)は、エディタで再生している間、仮想のスマホをホストにつなぎます。家庭用ゲーム機のコントローラーのシミュレーターのようなものです。どれも スマホのアプリと同じ方法で参加する ので(参加 URI のトークンと鍵、UDP の PadPlay Link: Hello、8 ms ごとの状態、確実に届くメッセージ、映像)、ゲームからは本物のスマホと区別できません。プレイヤー枠、PlayerJoined / PlayerReady、PadPlayPad、uGUI のポインターのイベント、PlayerLeft / PlayerRemoved を受け取ります。本物のスマホも同時に参加できます(例えば本物のスマホが P1、仮想のスマホが P2)。

  1. 再生 して窓を開き、Add phone(スマホを追加)を押します(プレイヤーごとに 1 回。Max Players まで)。
  2. スマホにはそれぞれ、そのプレイヤーの画面(そのプレイヤーに送っている PadPlayView のテクスチャ。View が無いか Video のモジュールがオフの時は、灰色で no video と出ます)が出て、その上にそのプレイヤーのレイアウトの画面のボタンが重なります。
  3. 操作します:
  • タッチ — 画面の上でマウスの左ボタン = 指 1 本(押す・ドラッグ・離す)。映像の領域の外の位置は、スマホと同じく端に収めます。
  • ピンチ — Ctrl + 左ドラッグ(Mac では Cmd)= 指 2 本。2 本目は画面の真ん中に対して対称に動きます(真ん中から離すと広がります)。画面の上で マウスホイール = マウスの位置を中心にした指 2 本が広がり(ホイールを上)、狭まり(ホイールを下)、ホイールを止めて少しすると離れます。窓の各スマホの下に、この操作の説明が出ます。
  • ボタンとスティック — レイアウトのボタンかスティックの上でマウスの左ボタン。同じ Group のボタンは、押したまま滑らせて移れます。
  • キー — 選んだスマホ(最後にクリックした物。プレイヤーの色の枠が付きます)に、この窓にフォーカスがある間だけ効きます。既定: Space = A(South)、左 Shift = B(East)、Q = X(West)、E = Y(North)、Z / C = LB / RB、Return = Start、Tab = Select、矢印 = 十字キー、WASD = 左スティック、IJKL = 右スティック。Keys で変えられます(PC ごとに保存します)。
  • 傾き — Yaw(右に回すと +)、Pitch(下を向くと +)、Roll(左に傾けると +)。スマホの絵が付いた球をドラッグして回します(縁の近くをドラッグするとロール)。角度は球の下に出ます。値は、正面合わせをする前に、ゲームが pad.attitude から読むオイラー角です。Reset tilt(傾きを 0 に)で 0 に戻します(仮想のスマホを正面に向けます。ゲームには伝えません)。Recenter(正面合わせ)は、スマホの隅の長押しと同じ要求を送ります。
  • 振動 — 振動の命令が効いている間、スマホの枠が光ります(明るいほど強い)。host.Pulse は、続けている振動の上に、その長さだけ光ります。
  • Phone Overlay — Phone Overlay / host.SetPhoneOverlay で送った文字と板を、絵の上に固定して描きます(リッチテキストはエディタが描く形で出ます)。
  • Disconnect / Reconnect — Disconnect(切断)は、Wi-Fi が落ちたように黙って接続を切ります。枠は Resume Hold Seconds の間取っておき、Reconnect(再接続)で同じプレイヤーに戻ります(Resumed の PlayerJoined)。
  • Remove — bye で抜けます。枠は空き(PlayerRemoved)、スマホは窓から消えます。

スマホのアプリと同じく、仮想のスマホが送るのは、そのプレイヤーのレイアウトにあるボタンとスティックだけで、ボタンのあるレイアウトを受け取っている間だけです(レイアウトが無いと、キーは何もしません)。画面の回転は知らせないので、ジャイロの部品は傾きの値をそのまま使います。デバッガーでは、参加した端末は PadPlay Virtual Phone(1080 × 2400、横向き)と出ます。

制限: 指は 2 本まで(ピンチだけ)、本物のセンサーのノイズやネットワークの損失は無く、映像は復号しません(窓はホストがこれから送るテクスチャを描くので、エンコードの問題は本物のスマホでしか見えません)。仮想スマホはエディタの中だけにあります。ビルドしたゲームには何も入らず、再生を止めると閉じます。

6. どの問題にどの道具を使うか

  • スマホがいつまでもつながらない — 接続チェック(またはデバッガーの Check のボタン): 最後の節で、PC に何か届いたか(何も届いていない / 古い QR / 満員)が分かります。ほかの節は、Wi-Fi のアドレス、ポート、ファイアウォールを指します。
  • 何も届かない — Windows ファイアウォールが Unity の UDP をブロックしています(PadPlay は UDP ポートを 1 つ使います。TCP だけを許可する規則では足りません)。接続チェック でファイアウォールの規則が分かります。
  • RenewToken() の直後に「古い QR コード」 — 新しいスマホには新しいコードが要ります。参加済みのスマホが古いコードで戻れるのは、host.NetworkSettings.RenewGraceMs(60 秒)の間で、アプリが再開用の秘密の値を残している(入れ直したりデータを消したりしていない)場合だけです。
  • スマホに H.264 ではなく JPEG が届く — host.VideoStatus / GetVideoChoice(slot, out choice): 理由は、ホストの設定、この PC で H.264 を使えない(OpenGL、macOS / Linux、エンコーダーなし)、スマホが求めた(H.264 の復号が遅い)のどれかです。
  • Ready なのに、ゲームが何にも反応しない — スマホを動かし、触り、押しながら、デバッガーの Hz の列を見ます: 数字が出る → モジュールのチェック((off))と自分のコードを確かめます。0 → スマホから何も届いていません(ボタンを送るのは、ボタンのあるレイアウトを受け取った時だけです。Events に LayoutSent があるか見てください)。
  • ボタンが効かない — デバッガーの Buttons のグリッドが光るか? 光る → 自分のバインド(Input Debugger、<PadPlayPad>/custom20…)。光らない → レイアウトかスマホ。
  • タップを取りこぼしているように見える — デバッガーの Buttons の押された回数: N 回タップして比べます。N 回 → ゲームはどの押下も受け取っています(コードの読み方を確かめます。例えば FixedUpdate で isPressed を見ている)。少ない → 途中で押下が失われています(Wi-Fi。Btn Hz)。
  • タッチが違う物に当たる — Display のプレビュー: 点が指の位置にあるか? あれば Touch → Player Targets と PadPlayView.UseAsTouchTarget を確かめます。
  • スマホが黒い、または違う絵が出る — Display のプレビュー: 送っているのと同じテクスチャです。そこでも黒い → ソースのカメラ / RenderTexture。そこでは正しい → 映像のエンコードかネットワーク(デバッガーの Video の列: fps と kbps)。
  • ジャイロが遅れる・飛ぶ — デバッガーの Gyro Hz(120 前後のはずです。PadPlay アプリは姿勢を 1 秒に 120 回送ります)と RTT。Attitude の設定を調整します。
  • あるプレイヤーが何度も切れる — Events: Left / Resumed のくり返しと、その理由(closed、timeout)。
  • 振動しない — Events: HapticSent が出るか? 出ない → Buttons → Allow Haptics / 強さの倍率。出る → スマホ側(マナーモード、振動の設定)。
  • 手元にスマホが無い、2 人目が要る — 仮想スマホ: プレイヤーごとに 1 台足します。
  • Input System の疑問(アクション、PlayerInput、ペアリング) — Unity の Input Debugger: スマホはそれぞれ PadPlayPad のデバイス(Gamepad)です。
