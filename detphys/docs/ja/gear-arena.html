サンプル: 歯車アリーナ（回る歯車の中の押し合い）

回る歯車の中で、凹形状の物を押し合う対戦です。Unity と Godot の両方にあり、互いに対戦できます。

  • 動く凹形状を近似せずに判定: 内歯の歯車（凹形状、隙間が 2 つ）が回り、その中で凹形状の物（L・T・U・十字）120 個を 2 本の棒で押し合います。歯車は tick の関数で回るキネマティックの凹形状（3. コンセプト の「動く凹形状」）で、ロールバックしても状態を持ちません。
  • 入力遅延 0: 既定は入力遅延 0 tick。相手の入力は予測し、外れたらロールバックして再計算します。
  • エンジンをまたぐ対戦: ルールは C# で 1 つ書き、同じファイルを Unity（取り込んだサンプルの GearArena/Runtime/Shared）と Godot（samples/gear_arena/shared）に置いています。PC の Unity と Android の Godot の間でも、確定 tick のハッシュが全部一致します。
  • desync したらすぐ原因が出て元に戻る: 「わざとずらす」で状態を 1 ULP ずらすと、desync デバッガーが desync した tick・ボディ・フィールドを両方の端末に出し、自動で再同期します。

遊び方: 隙間から落ちた物が下の線を越えると、落ちた側の相手の得点になります（左 = P1 の側に落ちたら P2 の得点）。30 秒（1800 tick）で多く落とした方の勝ちです。

#動かす

UnityGodot
開くサンプルを取り込み（Package Manager > In Project > DetPhys > Samples）、Scenes/SampleMenu.unity を開いて「歯車アリーナ」を選ぶ（または Scenes/GearArena.unity を Play）engines/godot/DetPhysSample を開いて F5 → メニューの「歯車アリーナ」（res://samples/gear_arena/gear_arena.tscn。C# なので Godot（.NET））
1 台で 2 人メニューの「Two players on this device」（この端末で 2 人）同じ
2 台片方を「Host（待ち受け）」、もう片方を「Guest（つなぐ）」にして相手の IP を入れる。ポートは 47700同じ（Unity とも Godot ともつながる）
2 台（ルームコード）「ルームを作る」「ルームに入る」（リレー・EOS）。ルームで対戦する同じ
Windows のプレイヤーScenes/GearArena.unity（またはメニューと 4 つのサンプル全部）をビルドに入れて Windows のプレイヤーを作る書き出しの設定の Windows / Android

操作: P1 = WASD で移動・Q E で棒を回す（ゲームパッドは左スティック・LB RB）。この端末で 2 人の P2 = 矢印・N M。タッチは左側をドラッグで移動、右下のボタンで回す。PC は「つなぐ（Guest）」側にすると、Windows のファイアウォールの許可が要りません。どちらがホスト（desync の時に正とする側）でもよいです。

画面の左上:

表示中身
注入する遅れ（スライダー 0〜150 ms）自分が送るパケットを遅らせる（揺れは遅れの 1/5）。確定した結果は変わらず、ロールバックが深くなるだけ
入力の遅延今の入力の遅延 [tick]（既定 0）
ランプ緑 = 確定 tick のハッシュが相手と一致している、赤 = desync を見つけて再同期している、灰 = まだ照合していない
ロールバック直前の advance で再計算した tick 数と、1 秒の最大（メーター）
相手相手のエンジンと端末（例 Godot 4.7.2 (.NET, Android)）。トランスポートの包みが別のデータグラムで送る（シミュレーションには入らない）
わざとずらす（1 ULP）自分の状態（最後に作った動くボディ = P2 の棒の x）を 1 ULP ずらす → 下に desync デバッガーの報告 → 自動で再同期
凸の組を見る歯車と物を、Box2D に渡している凸多角形の線で描く（形を近似していないことが見える）
経路（ルームの時だけ、パネルの下）相手までの経路（DIRECT / RELAYED）とルームコード。リレーの時はリレーとの往復時間も（ルームで対戦する）

起動の引数（自動の対戦・テスト用。Unity は -detphys "..."、Godot は -- detphys=game=gear;...、Android は Godot の --esa command_line_params "--,detphys=game=gear;..."）: peer=0|1・listen=<port>・connect=<ip>:<port>・mode=local・auto=1（自動の入力）・ticks=<n>・delay=<min>:<max>・loss=<‰>・dup=<‰>・inputdelay=<n>・nudge=<t>/<t>（ゲストを tick t でずらす）・convex=1・objects=<n>（100〜150 など。両方で同じに）・gap=<区画>・spin=<mrad/s>・lang=en|ja・quit=1。自動の入力で既定の設定なら、どちらのエンジンも基準のハッシュと比べ、ログの [DetPhysGear] SUMMARY OK|FAIL に結果を出します。

#ルームで対戦する

相手の IP を入れる LAN の UDP の代わりに、ルームコードでつなぐこともできます。同じ Wi-Fi にいない相手（家の回線とモバイル回線など）とも対戦できます。つなぎ方は「リレー」と「EOS」の 2 つで、メニューにそれぞれ「ルームを作る」「ルームに入る」のボタンがあります。どちらでも試合の中身は LAN と同じで、Unity と Godot、PC と Android の組み合わせでも対戦できます。

リレーEOS
つながり方自前のリレー（detphys_relay）を通る。両方の端末が同じリレーを使うEpic Online Services の P2P。直接つながらない時は EOS のリレーを通る
要る準備リレーを立てる（下の「リレーの準備」）EOS SDK のファイルと detphys_eos.ini を置く（下の「EOS の準備」）
ルームを作る（ホスト・P1）「リレー」に host か host:port（ポートの既定は 40400）を入れて「ルームを作る（リレー）」「ルームを作る（EOS）」
ルームに入る（ゲスト・P2）同じリレーを入れ、「ルームコード」に 6 桁を入れて「ルームに入る（リレー）」「ルームコード」に 6 桁を入れて「ルームに入る（EOS）」
ホストより先に入ろうとした時ルームが無いので「ルームを使えませんでした（not_found）」と出る。ホストがルームを作ってから入る60 秒まで 1 秒ごとに入り直す
試合中の経路の行経路 RELAYED・ルーム 123456・リレーとの往復時間 17 ms経路 DIRECT・ルーム 123456（EOS）（往復時間は出さない）

流れ:

  1. ホストの端末でルームを作ると、試合の画面の真ん中に 6 桁のルームコードが出て、相手を待ちます。このコードを相手に伝えます。
  2. ゲストの端末でルームコードを入れて入ります。入るまでの画面の「やめる」（Unity でサンプルを選ぶメニューを通さずに開いた時は「メニュー」）で、メニューに戻ります。
  3. 相手が入ると試合が始まり、ルームコードの表示が消えます。経路の行は、画面の左上のパネルの下に出ます。
  • ルームコードは 6 桁（5 桁＋チェックディジット）です。打ち間違いは通信の前に見つけて「ルームコードが正しくありません」と出します。
  • 経路は自分の側から見た相手までのつながり方です。DIRECT = 直接、RELAYED = リレーを通る。リレーのルームはいつも RELAYED です。EOS で片方でも RELAYED なら、間に EOS のリレーが入っています。どの経路でも確定 tick のハッシュは同じです。
  • EOS のトランスポートはリレーまでの往復時間を測らないので、EOS の時は経路の行に往復時間を出しません。
  • ルームの名前の区分（bucket）は既定で detphys-sample/gear です。両方で同じにしてください（違うと相手のルームが見つかりません）。

#リレーの準備

  • detphys_relay を、両方の端末から届く所（VPS など。試すだけなら同じ LAN の PC）に立て、UDP のポート（既定 40400）の受信を開けます。置き方は 8. トランスポートとルームコード。
  • 両方の端末の「リレー」に、同じ host か host:port を入れます。

#EOS の準備

  • EOS SDK は同梱していません。Epic の開発者ポータルから取り、Windows は EOSSDK-Win64-Shipping.dll、Android は eossdk-StaticSTDC-release.aar を置きます（Unity は Assets/Plugins/x86_64・Assets/Plugins/Android、Godot は addons/detphys/bin/windows・addons/detphys/eos/android。Godot の Android はプロジェクトの設定で DetPhys のプラグインを有効にし、Gradle ビルドで書き出します）。詳しくは Unity・Godot から使う。
  • ポータルの値を書いた detphys_eos.ini（[eos] の ProductName・ProductVersion・ProductId・SandboxId・DeploymentId・ClientId・ClientSecret）を置きます。PC は実行ファイルのフォルダか、Unity は Application.persistentDataPath・Godot は user://（エディタで動かす時はこちら）、Android はアプリの外部のファイルのフォルダ（/sdcard/Android/data/<パッケージ>/files/）です。
  • detphys_eos.ini はゲームの配布物やバージョン管理に入れないでください（クライアントのシークレットが入っています）。試す端末にだけ置きます。
  • EOS のルームは 2 台の端末で試します。同じ PC の 2 つのプロセスは同じ EOS のユーザーになるので、つながりません。
  • ファイルが無い時は、メニューに「EOS を使えません: …」と理由が出ます。LAN とリレーのルームはそのまま使えます。

起動の引数（ルーム）: relay=<host>[:<port>] か eos=<ini のパス、ini のあるフォルダ、または 1>（1 = 決まった場所を探す）を付けると LAN の UDP の代わりにルームを使います。room=<ルームコード> か peer=1 を付けた側が入り、付けない側がルームを作ります。ほかに roomseed=<n>（テスト用。両方に同じ n を付けると決まったルームコードを使い、ゲストはルームができるまで入り直します）・bucket=<名前>・localport=<n>（リレーの時の自分のポート）・eosrelay=allow|force|never（EOS のリレーの使い方。EOS P2P）。auto=1 か roomseed= の時は、リレーのゲストもルームができるまで 30 秒入り直します。
