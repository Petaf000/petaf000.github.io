#3D のセッション（バージョン 8）

ターンの流れ・照合・再同期・つなぎ直し・ホストの再起動・ゲストの毎ターンの状態保存は 2D と同じで、ワールドが 3D（detphys3d.h）になります。設定の world と meshes は使わず（mesh_count は 0）、凸包は begin_match の中で detphys3d_world_add_hull で両方のピアで同じ順に登録します。送る状態（再同期・途中参加）は detphys3d_world_transfer_* です。3D のキネマティックの表（キネマティック）は detphys3d_kinematic.h の detphys_turn_create_rule3d_kinematic で渡します（2D の detphys_turn_create_rule_kinematic の表は 3D には渡せません）。動いているキネマティックがあると落ち着いた（settled）にならないので、after_tick で tick 数などでターンを終えます。desync デバッガー（detphys_turn_set_debug）は 3D でも使えます（detphys_debug_abi_version() が 3 以上。記録は 3D の形式で、報告のフィールドは 3D のフィールド。5. desync への対処）。

関数説明
detphys_turn_create_rule3d3D のルールとワールドの設定（detphys3d_world_desc、NULL なら既定値）でセッションを作る。ワールドは試合ごとに作り直す使い方: コンセプト › 3D
detphys_turn_world3d今の 3D のワールド（読むだけ）。3D のセッションでは detphys_turn_world は NULL
構造体説明
detphys_turn_rule3d3D のルール（detphys_turn_rule と同じ並びで、コールバックが detphys_rule_ctx3d を受け取る。80 B）
detphys_rule_ctx3dコールバックに渡す値（detphys_rule_ctx と同じ並びで、world だけが detphys3d_world*）

#設定の照合が合わない相手（バージョン 9）

設定・ルール・形・凸包・キネマティックの表・コアのバージョンのどれかが違う相手とはつながりません（照合のタグが合わないパケットは捨てます）。バージョン 9（rt はバージョン 7）からは、捨てる時に数えて、相手とタグの中身（部分ごとのハッシュ）を送り合うので、どの部分が違うかが分かります。読み出しは detphys_turn_get_tag_info（rt は detphys_rt_get_tag_info）で、どちらも同じ構造体 detphys_tag_info に入ります。タグの値そのもの・今ある構造体・通信はバージョン 8（rt は 6）と同じです。読み方と直し方は 5. desync への対処 にあります。

フィールド（detphys_tag_info、136 B）中身
struct_sizesizeof(detphys_tag_info) を入れて渡す
flagsSEEN 0x01（合わないタグを受け取った）・REMOTE_KNOWN 0x02（相手の中身が届いた）・PEER_KNOWS 0x04（相手が自分の中身を受け取った）・ACTIVE 0x08（まだつながっていない）
local_tag・remote_tag自分のタグ・最後に合わなかった相手のタグ（rt の通信に載るのは下 32 bit で、中身が届く前の rt の remote_tag はその 32 bit。ターン制で session_id だけ違う時は 0）
mismatch_packetsタグが合わずに捨てたパケットの数
diff_parts違う部分（DETPHYS_TAG_PART_* の OR。REMOTE_KNOWN の時だけ。0 なら部分は全部同じで、タグの全体だけが違う）
dimensions・remote_dimensions2 か 3（相手の分は REMOTE_KNOWN の時だけ。それ以外は 0）
local_version・remote_version照合のバージョン × 65536 ＋ 通信のバージョン（rt は 3 と 3、ターン制は 6 と 4）
local_shape_count・remote_shape_count形の数（2D: 登録した形 / 3D: 凸包）
first_shape_diff最初に違う形の番号（先頭から DETPHYS_TAG_MAX_SHAPES = 64 個を比べる。数だけ違えば短い方の数。−1 = 違わない・分からない）
local_parts[8]・remote_parts[8]部分ごとのハッシュ（[i] が 1 << i の部分。32 bit で、ビルド・端末によらない。5 より後ろは 0）
info_sent・info_received自分の中身を送った・相手の中身を受け取った回数（ふつうは片側 1〜2 回）
部分（DETPHYS_TAG_PART_*）detphys_tag_part_name中身
VERSION（0x01）versionコアの照合と通信のバージョン、2D / 3D
CONFIG（0x02）configsession_id・tick の速さ・サブステップ・重力・3D の接触の調整・ターン制の最初の手番と 1 ターンの tick の上限
RULE（0x04）rulerule_id・入力と状態ワード数・params
SHAPES（0x08）shapes2D: 登録した形（.dnshape）の checksum / 3D: begin で登録した凸包の checksum と頂点数
KINEMATIC（0x10）kinematicキネマティックの表（渡したか・flags・begin の後の中身）

DETPHYS_TAG_PART_COUNT は 5 で、知らない値の名前は "unknown" です。印: rt は detphys_rt_frame.flags の DETPHYS_RT_FRAME_TAG_MISMATCH（0x200）、ターン制は flags の DETPHYS_TAG_INFO_ACTIVE。どちらの読み出しも、いつ呼んでもよく（毎フレームでよい）、0 = 成功、負 = NULL・struct_size が違う、です。
