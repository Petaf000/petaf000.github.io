#Unity（パッケージ 1.0.0、DetPhys 名前空間）

  • ワールド（detphys.h）: DetPhysWorld・DetPhysWorldSettings・DetPhysHashChain・DetPhysHash
  • ボディの読み出し（detphys_body.h）: DetPhysWorldView（ReadBodies・GetShapes・ReadMesh）・DetPhysBodyView
  • ターン制（detphys_turn.h）: DetPhysTurnSession・DetPhysTurnSettings・DetPhysStackRules（ToParams）・DetPhysStack（RuleId）・DetPhysTurnSession.Create・DetPhysTurnRule（C# のルール）・DetPhysTurnContext・DetPhysRuleWorld
  • リアルタイム（detphys_rt.h）: DetPhysRtSession・DetPhysRtSettings・DetPhysRtDriver・DetPhysRtRule（C# のルール）
  • 組み込みの押し合い（detphys_rt.h バージョン 5）: DetPhysRtSession.CreatePush・DetPhysPushSettings・DetPhysPushField・DetPhysPush（QuantizeMove・GetLayout）・DetPhysPushLayout
  • 動く凹形状（detphys_kinematic.h）: DetPhysKinematic・DetPhysMotion・IDetPhysMotionFunction
  • 設定の照合が合わない相手（detphys_turn.h バージョン 9・detphys_rt.h バージョン 7）: DetPhysRtSession.TryGetTagInfo・DetPhysTurnSession.TryGetTagInfo（古いコアなら false）・DetPhysTagInfo（Active・RemoteKnown・PeerKnows・DiffParts・DiffText() など。整数だけ）・DetPhysTag（PartName・PartNames・RtSupported / TurnSupported・定数 Part* / Info*）・DetPhysRtFrameFlags.TagMismatch（0x200）と DetPhysRtFrame.TagMismatch
  • トランスポート（detphys_udp.h など）: DetPhysUdpLink・DetPhysLoopback・DetPhysFaultyLink
  • トランスポートのインターフェース・ルームコード（detphys_link.h）・自前のリレー（detphys_relay.h）: DetPhysLink（CreateRelay・CreateHub・CreateUdp・CreateLoopback・Host・Join・Poll・Info・Endpoint・Close・TryParseHostPort）・DetPhysLinkInfo（State・Role・Path・Reason・RoomCode・RttMs・PathText など）・DetPhysLinkHub（テスト用のロビー、DetPhysLinkHubSettings）・DetPhysRoomCode（Make・Parse）・DetPhysRoomOpener（ルームを作る / 入る → 役が決まるまで。先に来たゲストの入り直し）・DetPhysLinkResult・DetPhysLinkState・DetPhysLinkPath・DetPhysLinkReason
  • EOS P2P のトランスポート（detphys_eos.h バージョン 2。別のライブラリ detphys_eos）: DetPhysEos（CreateLink・IsAvailable・UnavailableReason・SdkVersion・LastError・PrepareAndroid・Shutdown）・DetPhysEosSettings（ポータルの値・Relay・Load / TryLoad〔ini の [eos]〕・Find・Missing）・DetPhysEosRelay・DetPhysLink.CreateEos。Android の Gradle の設定はエディタのスクリプト DetPhysEosAndroidGradle が足します（「8. トランスポートとルームコード」の EOS の節）
  • 3D のワールド（detphys3d.h バージョン 2）: DetPhysWorld3D（Step・Hash・EngineHash・AddHull・AddBody・AddShape・ApplyForce など・WriteSnapshot / RestoreSnapshot・WriteTransfer / RestoreTransfer）・DetPhysWorld3DSettings・DetPhysWorld3DView（読むだけ: ReadBodies・ReadTransforms・GetShapes・ReadHull・Stats）・DetPhysRuleWorld3D（ルールの中のワールド）・DetPhysBody3DDesc・DetPhysShape3DDesc（Box・Sphere・Capsule・Hull・At）・DetPhysBody3DView（Position・Rotation）・DetPhysHull3DInfo・DetPhysHull3DMesh（ToUnityMesh）・DetPhysQuat（One = 2^30・From・FromFloats）・DetPhysShape3DKind・DetPhysBody3DFlags
  • 3D のセッション（detphys_rt.h バージョン 6・detphys_turn.h バージョン 8）: DetPhysRtSession.Create3D・DetPhysRtSettings.Default3D（輪は full）・DetPhysRtRule3D（C# のルール）・DetPhysRtContext3D・World3D・ResyncInfo（DetPhysRtResyncInfo）／DetPhysTurnSession.Create3D・DetPhysTurnRule3D・DetPhysTurnContext3D・DetPhysTurnTick・DetPhysTurnEndReason・SetCheckpointKind・World3D。どちらも Is3D・Rule3D
  • 3D の動く凹形状（detphys3d_kinematic.h バージョン 1）: DetPhysKinematic3D（Add・Bind・Step・Check・TryPoseAt・Stats）・DetPhysMotion3D（Spin・PingPong・Orbit・Points）・IDetPhysMotion3DFunction・DetPhysMotion3DPoint・DetPhysKinematic3DPose。ルールの UsesKinematic => true で、セッションが表を持つ（DetPhysRtContext3D.Kinematic・DetPhysTurnContext3D.Kinematic・DetPhysRtSession.Kinematic3D）。分割の設定は 2D と同じ DetPhysKinematicSettings
  • desync デバッガー（detphys_debug.h バージョン 3、2D・3D）: セッション: SetDebug（DetPhysDebugSettings.On）・DebugReportCount・TryGetDebugReport（DetPhysDesyncReport: 最初に desync した tick・ボディ・フィールド・両方の値・ULP・原因）・DebugBundle（DNDB）・DebugStats（rt・ターン制、2D・3D とも）。自分の輪: DetPhysDebugRecorder（Record・Record3D・Export）・DetPhysDebug（Compare・TryGetFileInfo・WriteFile・FieldName・CauseName）・DetPhysDesyncStatus・DetPhysDesyncCause
  • マッチコンポーネント（MonoBehaviour）: DetPhysRtMatch（2D のリアルタイム）・DetPhysRtMatch3D（3D のリアルタイム）・DetPhysTurnMatch（2D のターン制、組み込みの積み上げか自分の DetPhysTurnRule）・DetPhysTurnMatch3D（3D のターン制、自分の DetPhysTurnRule3D）。GameObject に付けてインスペクターで設定すると、Start で始まり Update で進みます
    • つなぎ方（共通）: connection（DetPhysMatchConnection。kind = Local〔この端末で 2 人〕・Udp（peer・listen・address・port）・Relay（relay・host・roomCode・bucket・joinRetrySeconds）・Eos（eosConfig・eosRelay）・Manual〔コードから〕、試すための遅れ・取りこぼし simulate*）・startAutomatically・stepInUpdate・StartMatch・StartWithLink・StartWithEndpoint・StartRoom・Stop・Step / StepAt・Clock・IsRunning・InLobby・IsPeerConnected・LocalPeer・RoomCode・LinkInfo・Error。UnityEvent: onConnected・onPeerLost・onError・onRoomCode・onRoomReady・onSettingsMismatch（違う所、例 rule）
    • リアルタイム: rule（DetPhysRuleSource.BuiltIn = 組み込みの押し合い / CSharp = Rule か RuleFactory）・push（2D は DetPhysPushSettings、3D は DetPhysPush3DSettings）・shapes（2D の形）・sessionId・inputDelay・maxPrediction・automaticInputDelay・desyncDebugger・workers・kinematic・maxTicksPerFrame・endAtTick・InputSource（(peer, tick) → 入力の整数）か LocalInput・AdjustSettings・Session・ConfirmedTick・RolledBack・StateReplaced。UnityEvent: onTickConfirmed（tick・ハッシュ・フラグ。両方のピアで同じ）・onDesync・onResynced・onRejoined・onInputDelayChanged・onDesyncReport（desync デバッガーの報告の文）・onMatchEnded
    • ターン制: rule（2D。DetPhysRuleSource.BuiltIn = 組み込みの積み上げ / CSharp = Rule か RuleFactory）・rules・shapes（2D）・Rule / RuleFactory・world（3D）・firstMover・maxTicksPerTurn・peerTimeoutMs・ticksPerFrame・playbackSpeed・desyncDebugger・InputSource（(peer, turn) → 手。null なら次のフレームにまた聞く）か Submit・State・IsLocalTurn・Results。UnityEvent: onLocalTurn・onTurnFinished（ターン・ハッシュ・フラグ）・onMatchOver・onDesync・onDesyncReport・onStateChanged
    • 描画: views（DetPhysViewSettings: syncTransforms〔毎フレーム Transform に写す〕・bodies〔ボディの番号順の Transform〕・createViews〔Transform の無いボディに箱・球・凸包などの簡単な見た目を作る〕・material〔空なら既定の material。組み込み・URP・HDRP とも〕・colorByShape〔既定の material の色をボディの種類と形で分ける〕・skipStatic）・ViewOf・ViewCount。2D は XY 平面（z 軸まわりの回転）、3D は Unity と同じ軸です
  • 組み込みの 3D の押し合い（detphys_rt.h バージョン 8）: DetPhysRtSession.CreatePush3D・IsBuiltInPush3D・Push3DSettings・DetPhysPush3DSettings（seed・turntable・tableSpinMradS・boxCount / sphereCount / hullCount・predictButtonsReleased）・DetPhysPush3D（Input・QuantizeAxis・Params・Fingerprint・GetLayout・AutoInputs・IsAvailable）・DetPhysPush3DLayout
  • Shape Baker（detphys_bake.h バージョン 1。エディタだけ、DetPhys.Editor）: 窓 Window > DetPhys > Shape Baker（DetPhysShapeBakerWindow）、DetPhysShapeBaker（Bake〔Texture2D・Sprite・どちらでも〕・BakePng・BakeAlpha・Save〔.dnshape.bytes のアセット〕・DefaultAssetPath）、DetPhysBakeSettings（pixelsPerMeter・useSpritePixelsPerUnit・alphaThreshold・simplifyPixels・method・maxVertices など）、DetPhysBakeMethod（Steiner・HertelMehlhorn）、DetPhysBakeResult（Succeeded・Error・Data・Shape・Stats・Outline）。実行時は DetPhysShapeFile（Parse・TryParse・PieceCount・PiecesMeters・BoundsMeters）で .dnshape を読めます
  • 乱数: DetPhysRandom（splitmix64）
  • C ABI そのまま: DetPhys.Native.DetPhysNative（押し合いは DetPhysNativePush、3D は DetPhysNative3D.cs、desync デバッガーは DetPhysNativeDebug.cs）
  • 2D のターン制のルールも C# で書けます。DetPhysTurnRule を継いで、InputWords・StateWords・RuleId・Params（設定の照合に入るので、ルールの値は全部ここに入れる）・UsesKinematic を決め、BeginMatch（試合の初め。ワールドは空で、形は登録済み）・ApplyInput（手番の入力をワールドに入れる）と、要るものだけ CheckInput（HasCheckInput）・AfterTick（HasAfterTick。DetPhysTurnTick を返す。既定は全部が眠ったらターンの終わり）・EndTurn（HasEndTurn。次の手番を返し、matchOver で試合を終える。既定は交代）を書きます。DetPhysTurnSession.Create(settings, rule, meshes, localPeer, endpoint, kinematic = null) に渡すと、あとは組み込みの積み上げと同じ（Poll・Submit・TryGetResult・World）です。コールバックが受け取る DetPhysTurnContext の World（DetPhysRuleWorld: AddBody・AddShape・ApplyImpulse・TryGetBody・TryGetMeshInfo・MeshCount・BodyCount など）・GetState / SetState・Mover・Turn・Match・MatchTurn・Tick・Settled・Kinematic（UsesKinematic => true の時、セッションが持つ DetPhysKinematic。動く足場は眠らないので、AfterTick で tick 数を見てターンを終えます）を使います。セッションの Rule・Kinematic で読めます。マッチコンポーネントでは DetPhysTurnMatch の rule = CSharp と Rule / RuleFactory で使えます。サンプル「積み上げ対戦」の Assets/Samples/DetPhys/1.0.0/DetPhys Samples/StackVersus/Runtime/CSharpStackRule.cs は、組み込みの積み上げを C# で書いたルールです。Params に DetPhysStackRules.ToParams()、RuleId に DetPhysStack.RuleId を返し、同じ式・同じ順番で計算するので、組み込みのルールを使う相手とも、Godot・Unreal で同じルールを書いた相手ともつながり、毎ターンのハッシュが同じになります。
  • 3D のルールは C# で書けます（DetPhysRtRule3D・DetPhysTurnRule3D。決まりは 2D の DetPhysRtRule と同じ: 整数だけ・状態は状態ワードに・凸包は Begin で両方のピアで同じ順に登録）。サンプル「3D の押し合い」のルール（Assets/Samples/DetPhys/1.0.0/DetPhys Samples/Push3D/Runtime/Shared/Push3DRule.cs）は、コアの組み込みの 3D の押し合い（detphys_rt_create_push3d、バージョン 8）と同じ params・rule id（回る台あり / なしとも）なので、コアのルールを使う相手（Godot のサンプルなど）ともつながります。コアのルールは DetPhysRtSession.CreatePush3D（DetPhysPush3DSettings）か、DetPhysRtMatch3D の rule = BuiltIn で使えます。
  • 描画: Box3D も Unity も y が上なので、DetPhysBody3DView.Position・Rotation をそのまま使えます（Box3D は右手系・Unity は左手系なので、絵は右手系の世界の鏡像になりますが、全部同じように映るので気になりません。凸包の三角形の向きは DetPhysHull3DMesh.ToUnityMesh が Unity に合わせます）。
  • サンプルは自動の入力で動かした時に、確定したハッシュをサンプルごとの Resources のフォルダに入っている基準のハッシュと比べます。2D・3D のワールド・セッション・動く凹形状が同じハッシュになることを、どの端末でも確かめられます。
  • C# で書いた自分のトランスポート（detphys_link_create に実装の表を渡す形）はまだ包んでいません（今は C ABI のトランスポートを使う）。

#Godot（アドオン addons/detphys、層のバージョン 7）

  • ワールド: GDScript は DetPhysWorld・DetPhysWorldSettings・DetPhys（ハッシュの 16 進・鎖）。C# は DetPhysWorld・DetPhysWorldSettings・DetPhysHash
  • ボディの読み出し: GDScript は DetPhysWorldReader（read_bodies・read_body_info・get_body_shapes・get_mesh_polygons。セッションもこれを継ぐ）。C# は Unity と同じ宣言
  • ターン制: GDScript は DetPhysTurnSession（create_stack）・DetPhysTurnSettings・DetPhysStackRules・Node DetPhysStackMatch。C# は DetPhysTurnSession
  • リアルタイム・組み込みの押し合い: GDScript は DetPhysRtSession（create_push・get_layout・kinematic_check）・DetPhysRtSettings・DetPhysPushRules（動くステージ field も）・Node DetPhysRtMatch。C# は DetPhysRtSession.CreatePush・DetPhysPush
  • 設定の照合が合わない相手: GDScript は DetPhysRtSession.get_tag_info()・DetPhysTurnSession.get_tag_info()（整数の Dictionary。flags・diff_parts など、local_parts / remote_parts は 8 個の PackedInt64Array）・static tag_part_name(part)・tag_part_names(parts, separator)・定数 DETPHYS_TAG_PART_*・DETPHYS_TAG_INFO_*・DETPHYS_RT_FRAME_TAG_MISMATCH（と DETPHYS_RT_FRAME_DEBUG）・Node のシグナル tag_mismatch(info)（DetPhysRtMatch・DetPhysStackMatch。info に known_after_ms・parts_text。advance_once を自分で回す時は check_tag()）。C# は TryGetTagInfo（rt・ターン制。DetPhysTagInfoNative）・DetPhysTag（PartName・PartNames）
  • トランスポート: GDScript は DetPhysLink（udp_listen・udp_connect・set_faults）・DetPhysLoopback。C# は DetPhysUdpLink・DetPhysLoopback
  • トランスポートのインターフェース・ルームコード・自前のリレー（detphys_link.h・detphys_relay.h）: GDScript は DetPhysLink（static relay(host, port, local_port)・host_room(bucket, code, entropy, timeout_ms)・join_room(code, bucket, timeout_ms)・poll・get_state・get_role・get_path・get_room_code・get_info〔名前つきの Dictionary〕・get_link_error・close・static room_code_make・room_code_parse・room_code_check・state_name・reason_name・path_name・定数 DETPHYS_LINK_*・DETPHYS_RELAY_*。set_faults もそのまま使える）・DetPhysLinkHub（create・create_link・pump）。Node の DetPhysRtMatch・DetPhysStackMatch は毎フレーム link.poll() を呼ぶ。C# は DetPhysLink（CreateRelay・Host・Join・Poll・Info・Transport）・DetPhysLinkHub・DetPhysRoomCode・DetPhysRoomOpener（Unity と同じ。ルームを作る / 入る、役が決まるまで待つ。先に来たゲストは入り直す。FailResult は DetPhysNative.LinkError* の数）
  • EOS P2P のトランスポート（detphys_eos.h バージョン 2）: GDScript は DetPhysLink（static eos(settings)・eos_available()・eos_sdk_version()・eos_error()。detphys_eos は使う時に読み込む）と、補助のスクリプト addons/detphys/eos/detphys_eos.gd（load_ini・find_ini・create_link・prepare_android・available・error）。Android の書き出しはエディタのプラグイン「DetPhys」が EOS SDK の aar と Gradle の設定を足します。C# は Unity と同じ DetPhysEos（CreateLink・IsAvailable・UnavailableReason・SdkVersion・LastError・PrepareAndroid・AndroidExternalFilesDir・Shutdown）・DetPhysEosSettings（Load / TryLoad〔res://・user:// も可〕・Find・Missing）・DetPhysEosRelay・宣言は DetPhysNativeEos.cs（GDScript と C# は同じ detphys_eos を使う）
  • 3D・組み込みの 3D の押し合い（detphys_rt.h バージョン 8・detphys3d.h・detphys3d_kinematic.h。層のバージョン 3）: GDScript は DetPhysRtSession.create_push3d(settings, rules, local_peer, link, world = null)・DetPhysRtSettings.default_3d()（snapshot FULL）・DetPhysPush3DRules（Resource。desc と 1 対 1: box_count・sphere_count・hull_count・spawn_max・field〔FIELD_NONE / FIELD_TURNTABLE〕・seed・table_spin_mrad_s ほか。to_params・fingerprint・get_layout・static auto_inputs(seed, peer, ticks)・定数 BUTTON_*・TAG_*・INPUT_WORDS）・DetPhysWorld3DSettings（tick_hz・substeps・重力 xyz・worker_count）。入力は毎 tick 3 語 [移動 x, 移動 z, ボタン]。読み出し（描画用）: is_3d・get_world3d_tick / _hash・get_body3d_count・get_world3d_stats・read_transforms3d(first)（7 float: 位置 m・四元数 x, y, z, w）・read_bodies3d()（8 int: id・種類・flags・tag・形の数・最初の形・凸包）・get_body3d(id)・get_body3d_shapes(id)（Vector3 / Quaternion）・get_hull3d_count・get_hull3d(hull)・get_hull3d_arrays(hull)（そのまま ArrayMesh.add_surface_from_arrays に渡せる）。回る台の表は has_kinematic・get_kinematic_stats・kinematic_check（2D と同じ名前）。C# は DetPhysRtSession.CreatePush3D（Is3D・World3D・ReadTransforms3D・ResyncInfo・KinematicCheck）・DetPhysPush3D（Desc・Params・Fingerprint・Layout・AutoInputs）・宣言は DetPhysNativePush3D.cs
  • 再同期で送る状態・desync デバッガー（detphys_debug.h バージョン 3。2D・3D のセッションとも）: GDScript は DetPhysRtSession.get_resync_info()（registry_rebuilds・hull_replacements・last_bytes など。3D は形の登録簿と凸包の表も送る）・set_debug(enabled, ticks_before = 30, max_reports = 4, timeout_ms = 10000)・get_debug_count・get_debug_report(index)（status・first_tick・body・field_name・ulp・cause_name・text〔Unity の DetPhysDesyncReport と同じ 1 行〕ほか）・get_debug_bundle(index)（DNDB。tools/desync で見直せる）・get_debug_stats・static debug_field_name・debug_cause_name・rt_abi_version・world3d_abi_version・debug_abi_version。C# は ResyncInfo・Unity と同じ desync デバッガー（SetDebug〔DetPhysDebugSettings.On〕・DebugReportCount・TryGetDebugReport〔DetPhysDesyncReport〕・DebugBundle・DebugStats。リアルタイム・ターン制の両方）と DetPhysDebugRecorder（Record3D・Export）・DetPhysDebug（Compare・FieldName・CauseName）。テスト用の DebugNudgeAt
  • 3D・自分で書くルール（C#。detphys_rt.h バージョン 6・detphys_turn.h バージョン 8・detphys3d.h・detphys3d_kinematic.h）: Unity と同じ名前・同じ作りです。DetPhysRtRule3D（リアルタイム）か DetPhysTurnRule3D（ターン制）を継いで書き、DetPhysRtSession.Create3D(rule, localPeer, transport, owner, world = null, sessionId = 0x36, inputDelay = 0, maxPrediction = 10, snapshot = Full, recordAllHashes = true, kinematic = null)・DetPhysTurnSession.Create3D(rule, localPeer, transport, owner, world = null, sessionId = 0x36, maxTicksPerTurn = 600, peerTimeoutMs = -1, firstMover = 0, kinematic = null) に渡します（transport は DetPhysUdpLink.Transport・DetPhysLink.Transport・DetPhysLoopback.Side(n)、owner はそれを持つオブジェクト）。コールバックが受け取る DetPhysRtContext3D / DetPhysTurnContext3D の World（DetPhysRuleWorld3D: AddHull・AddBody・AddShape・ApplyForce・ApplyImpulse・TryGetBody など）・GetState / SetState・Tick・Kinematic（ルールの UsesKinematic => true の時、セッションが持つ DetPhysKinematic3D。動く凹形状を Begin で足す: Add・DetPhysMotion3D.Spin / PingPong / Orbit / Points・IDetPhysMotion3DFunction）を使います。速さは DetPhysFixed.FloorMilli で整数にします。セッションの読み出し: Is3D・Rule3D・World3D（DetPhysWorld3DView: ReadBodies・ReadTransforms・GetShapes・ReadHull・Stats・Hash）・ReadTransforms3D・Kinematic3D・ターン制の SetCheckpointKind。ワールドだけを直に回す時は DetPhysWorld3D（Edit でルールと同じ呼び出し・WriteSnapshot / RestoreSnapshot・WriteTransfer / RestoreTransfer）と DetPhysKinematic3D（Step・Check）。描画には DetPhysBody3DView.Position・Rotation（Godot の Vector3・Quaternion）・DetPhysHull3DMesh.ToArrayMesh()（Godot の表の向きに並べ替えた ArrayMesh）・DetPhysQuat.From(Quaternion)（入力の量子化）。宣言は Unity と同じ DetPhysNative3D.cs・DetPhysNativeKinematic.cs・DetPhysNativeDebug.cs

    • サンプルのルール（DetPhysSample の DetPhysSampleRules3D.h）: UDetPhysSamplePush3DRule（3D の押し合いを C++ で書いたもの。組み込みのルールと params・rule_id が同じなので、組み込みのルールのピアともつながります）・UDetPhysSampleStack3DRule（3D の積み上げ、ターン制）・UDetPhysSampleSpinTableRule（回る八角の台＝キネマティックの表で動かす凹形状）
  • desync デバッガー（セッションの API）: SetDebug・GetDesyncReportCount・GetDesyncReport・DebugNudgeAt（テスト用）・FDetPhysDebugSettings・FDetPhysDesyncReport
  • 設定の照合が合わない相手: UDetPhysTurnSession::GetTagInfo・UDetPhysRtSession::GetTagInfo（古いコアなら false）・FDetPhysTagInfo（整数だけ。C++ は IsActive() など）・UDetPhysLibrary::TagPartName・TagPartNames・FDetPhysRtFrame.Flags の 512（DETPHYS_RT_FRAME_TAG_MISMATCH）
  • トランスポート（detphys_udp.h・ループバック）: UDetPhysLink（UdpListen・UdpConnect・SetFaults〔テスト用〕・GetLocalPort）・UDetPhysLoopback（CreateLoopback・GetSide・Pump）
  • トランスポートのインターフェース・ルームコード（detphys_link.h）・自前のリレー（detphys_relay.h）: UDetPhysLink（static CreateRelay(Host, Port, LocalPort)・HostRoom(Bucket, Code, Entropy, TimeoutMs)・JoinRoom(Code, Bucket, TimeoutMs)・Poll・GetState・GetRole〔0 / 1、まだなら -1〕・GetPath・GetRoomCode・GetInfo・GetInfoText・GetLinkError・Close〔ルームを出る〕・IsRoomLink・static RoomCodeMake・RoomCodeParse・RoomCodeCheck・StateName・ReasonName・PathName・SplitHostPort・IsRoomApiAvailable。SetFaults もそのまま使える）・FDetPhysLinkInfo・EDetPhysLinkState・EDetPhysLinkPath・EDetPhysLinkReason・UDetPhysLinkHub（テスト用のロビー: CreateHub・CreateLink・Pump・GetRoomCount）・UDetPhysRoomOpener（OpenRelayRoom・OpenHubRoom・C++ の Open: ルームを作る / 入る → 役が決まるまで。先に来たゲストの入り直し付き。Poll・GetRole・GetLink・GetAttempts・GetFailResult・GetFailReason）
  • EOS P2P のトランスポート（detphys_eos.h バージョン 2。別のライブラリ detphys_eos、Windows x64）: UDetPhysEos（IsEosAvailable・GetEosError・GetEosSdkVersion・GetEosLocation・LoadEosSettings・FindEosSettingsFile・CreateEosLink(Outer, Settings)・OpenEosRoom(Outer, Settings, bHost, Code, Bucket, Entropy, RetryForMs, RetryEveryMs, TimeoutMs)・DescribeEosSettings・ParseEosRelay・ShutdownEos）・FDetPhysEosSettings（ProductId・SandboxId・DeploymentId・ClientId・ClientSecret〔Transient〕・ProductName・ProductVersion・DisplayName・CacheDir・Relay〔EDetPhysEosRelay: Allow / Force / Never〕・LoginTimeoutMs・LogLevel・bNewDeviceId〔テスト用〕）。作った link は UDetPhysLink（GetKind() は "eos"）で、Close でその場で片付きます。detphys_eos.dll は使う時に読み込むので、無くてもプラグインは動きます。Unreal の Online Subsystem EOS とは別のものです
  • 対戦の ActorComponent と Delegate（Godot の DetPhysRtMatch・DetPhysStackMatch に当たる）: UDetPhysRtMatchComponent（Settings・Rules・LocalInput〔C++ は InputSource〕・StepFrame / StepFrameAt・GetSession・WasRolledBack・WasReplaced。Delegate: OnTickConfirmed・OnDesync・OnResynced・OnRejoined・OnInputDelayChanged）・UDetPhysStackMatchComponent（Settings・Rules・TicksPerFrame・Speed・Submit・StepTicks。Delegate: OnLocalTurn・OnTurnFinished・OnMatchFinished・OnWorldReplaced）。どちらも StartWithLink(LocalPeer, Link)・HostRelayRoom / JoinRelayRoom・StartRoom(UDetPhysRoomOpener)・Stop・Shapes / ShapeFiles・RoomBucket・bAutoStep、共通の Delegate OnConnected・OnPeerLost・OnFailed・OnTagMismatch・OnLinkStateChanged・OnRoomReady
    • 2D の自分のルール: UDetPhysRtMatchComponent・UDetPhysStackMatchComponent の CustomRule（自分の UDetPhysRtRule / UDetPhysTurnRule。空なら組み込みのルールを Rules の値で）。自分のルールの時、OnLocalTurn の Shape はルールの ShapeAt の答え、OnMatchFinished の Winner は -1 です（勝ち負けは結果の State の語をルールが決めます）
    • 3D: UDetPhysRtMatch3DComponent（World・Rule〔自分の UDetPhysRtRule3D。空なら組み込みの 3D の押し合いを Rules3D の値で〕。Settings は FULL の snapshot から始まります）・UDetPhysTurnMatch3DComponent（World・Rule〔自分の UDetPhysTurnRule3D、必須〕）。進め方・入力・Delegate・つなぎ方は 2D のコンポーネントと同じです（OnLocalTurn の Shape と OnMatchFinished の Winner は -1。勝ち負けは結果の State の語をルールが決めます）。描画は GetSession() の *3D の関数で
  • 形・入力の量子化: UDetPhysLibrary（LoadShapeFile / LoadShapeFiles・ShapesFingerprint・QuantizeMove・QuantizeMm・QuantizeMrad・MakePushInput・自動の手 AutoStackInput / AutoPushInputs・NowUs）・FDetPhysShapeData
  • ほかの全部: C++ からモジュール DetPhysCore の C ABI を直接呼ぶ（ヘッダーの写しは Source/ThirdParty/DetPhysCore/include）
  • 上の API は全部 Blueprint から呼べます（設定・結果は整数だけの USTRUCT）。セッションを直に使う時は、毎フレームの Poll / Advance を使う側が回します。マッチコンポーネントを Actor に付ければ、Tick で回して起きたことを Delegate（Blueprint の「イベントにつなぐ」）で知らせます。
  • ルームの link（リレー・hub）は毎フレーム Poll を呼びます（リレーの PING・時間切れがこの中で回る）。コンポーネントは自分で呼びます。役（GetRole）が決まる前に送った物は捨てられます（セッションが再送する）。
  • UDetPhysRtMatchComponent の OnTagMismatch の後もセッションは待ち続けます（やめるかはゲームが決める。サンプルは表示して Stop）。UDetPhysStackMatchComponent は、設定のハッシュが違う相手ならコアが ERROR にするので、OnTagMismatch の直後に OnFailed も出ます。
  • 3D の押し合いのセッションは、同じ設定の Unity・Godot の 3D の押し合いのピアとつながり、確定した tick のハッシュも同じです。C++ / Blueprint で書いた自分のトランスポート（detphys_link_create に実装の表を渡す形）を包む API は（予定）です。どれも、C++ からはコアの C ABI で今も使えます。
