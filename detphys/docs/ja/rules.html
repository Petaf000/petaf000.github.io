決定論を守るためのルール（ゲームのコード）

DetPhys のコアは、どの端末でも同じ結果を出します。ずれるのは、たいていゲームの側のコードが、端末ごとに違う値をシミュレーションに入れた時です。次の決まりを守ってください。守れているかは、desync した時に desync デバッガー が「入力のずれ・ルールの状態のずれ・作り方のずれ・物理のずれ」に分けて示します。

#1. 入力は整数にしてから渡す

  • マウスの位置・スティックの値・タッチの位置などのエンジンの float は、入力を作る端末で 1 回だけ整数（mm・mrad・−100〜100 など）にしてから渡します。届くのは整数なので、両方の端末で同じ値になります。
  • 例（Unity）: DetPhysStack.MetersToMm(x)・DetPhysStack.RadiansToMrad(angle)・DetPhysPush.QuantizeMove(axis)。Godot: DetPhysRtMatch.quantize_move(axis)。
  • ボタンは、押した瞬間を取りこぼさないよう、受け付けられる（ADVANCED か DELAY_WAIT が返る）まで覚えておきます。

#2. float をシミュレーションに入れない

  • コアの関数は、長さ mm・角度 mrad・速さ mm/s・力 mN・材質 ×1000 の整数だけを受け取ります。わざと float の入口を作っていません。
  • Time.deltaTime などのフレームの時間を、シミュレーションに入れません。tick の長さは tick_hz で決まっています（Unity は DetPhysRtDriver が単調な時計で tick を進めます）。
  • ボディの読み出し（detphys_body_view・3D の detphys3d_body_view）の float（位置・角度・四元数・速度）は描画用です。
  • 3D の向きは整数の四元数で渡します（エンジンの float の四元数を DETPHYS3D_QUAT_ONE 倍して丸める。入力を作る端末で 1 回だけ）。オイラー角から四元数を作る三角関数の計算は、シミュレーションの外（入力を作る所）で済ませます。

#3. ルールは整数だけで書く

  • ルールの判定には、読み出しの整数のフィールド（x_mm・y_mm・angle_mrad、3D は x_mm・y_mm・z_mm。全ターゲットで同じ値）を使います。float を使うなら、1 回だけ整数にします（Unity は DetPhysFixed.FloorMilli）。
  • C / C++ でルールを書いて float を使うなら、コアと同じビルド設定（MSVC は /fp:precise、clang / gcc は -ffp-contract=off -fno-fast-math、/fp:fast・-ffast-math・-Ofast は使わない）にします。三角関数（std::sin など）は端末で値が違うことがあるので使いません。整数だけで書くのがいちばん安全です。
  • C#（Unity）のルールの中では float の計算をしません（Mono と IL2CPP、端末の CPU で結果が変わりえます）。

#4. 副作用のある呼び出しを、関数の引数に並べない

make_box(rng_next(&r), rng_next(&r));   // だめ: 引数を評価する順番はコンパイラで違う
int32_t w = rng_next(&r);               // よい: 1 文に 1 回
int32_t h = rng_next(&r);
make_box(w, h);

C / C++ では、引数を評価する順番が決まっていません。実際に、Android の clang だけ箱の幅と高さが入れ替わったことがあります。乱数のように呼ぶたびに値が変わる関数は、1 文に 1 回だけ呼びます。

#5. 乱数は seed 付きの自前のものだけ

  • UnityEngine.Random・System.Random・rand()・Godot の randi() などを、結果に使いません。実装や初期値が端末・ランタイムで違うことがあります。
  • 使うのは、seed を決めた自前の乱数です（Unity・Godot は DetPhysRandom〔splitmix64〕）。seed は試合を始める前に両方で同じ値にします（ホストが決め、つなぐ前にロビーなどで渡す）。
  • 積み上げの「次の形」は、ルールが seed・試合の番号・ターンの番号だけから決めます（状態を持たないので、ロールバック・再同期でも同じ形）。

#6. コレクションを回す順番に頼らない

  • Dictionary・HashSet・unordered_map などを回した順番で結果を作りません。順番がハッシュの値やメモリの場所で決まり、端末で変わります。
  • 回すのは、ID の順（ボディの ID は作った順の通し番号）や配列の順です。並べ替えるなら、同じ値どうしの順番も決まる鍵（ID など）で並べます。
  • ポインタの値・オブジェクトのハッシュ・スレッドの終わる順番を、順番や結果に使いません。

#7. 端末ごとに違うものを結果に使わない

  • 時計・フレームの数・スレッド ID・ポインタ・ファイル・端末の情報・ctx->local_peer（自分のピア番号）・ctx->resimulating（再計算の途中か）は、結果に使いません（ログ・音・表示のためだけに使います）。
  • ルールのコールバックの中で、セッションの関数（detphys_turn_*・detphys_rt_*）を呼びません。使ってよいのは ctx の値・ctx->world に detphys_body.h の関数（3D のルールは detphys3d.h の関数）・自分の params と状態ワードだけです。

#8. ゲームの状態は、ワールドと状態ワードにだけ置く（リアルタイム）

  • コールバックはロールバックのたびに同じ tick で何度も呼ばれます。ロールバックで戻るのはワールドと状態ワードだけです。
  • ルールのオブジェクトのフィールドや static な変数に、点数・タイマー・クールダウンなどを持たないでください（ロールバックで戻らず、ずれます）。
  • 状態ワードは 0〜64 個の int32 です（state_words）。

#9. 両方のピアで、設定・形・形の順番をそろえる

  • session id・ルールの設定（params）・形（.dnshape）とその登録の順番・ワールドの設定（tick の速さ・サブステップ・重力）は、両方で同じにします。違うピアどうしはつながりません（間違って対戦が始まることはありません）。
  • params は固定幅の整数だけで作ります（構造体の詰め物や、ポインタを入れない）。
  • 3D では、凸包（detphys3d_world_add_hull）を begin / begin_match の中で、両方のピアで同じ点・同じ順に登録します（凸包の中身は設定の照合に入ります）。予測の間だけ作る形があってもかまいません（再同期で送る状態が登録簿ごと運びます）が、凸包は試合の初めにそろえておくのがいちばん安全です。
  • ワーカーの数は、ピアごとに違ってもかまいません（ハッシュは変わりません）。

#10. 動く凹形状で物を挟まない

  • キネマティックのボディは止まりません。動く形が物の山を床や壁へ押し付けると、挟まれた物がめり込みます（挟まれ）。
  • 置き方:
    • 下りてくる歯車・U は、物の山より上で動かす（山に届かないように）。
    • 床すれすれを横に掃く足場にしない。横に動いて山を押す所は、押す速さを約 3 m/s 未満にする（Box2D が押し出せる速さ）。
    • 動く形が動く範囲に、逃げ場のない所（動く形と床・壁の間で物が閉じ込められる所）を作らない。
  • 3D で回る台（歯車・回転台）の上に物を載せたままにするなら、止める縁・仕切りを付けます（載せた物は外へゆっくり滑ります。3. コンセプト）。
  • サンプル（組み込みの押し合いの「動くステージ」）は、この置き方にして 1800 tick の自動対戦ですり抜け 0 です。挟まれたことを知らせる機能は（予定。売る前の見直しで決めます）。

#11. 上から速く落ちてくる物には bullet を付ける

  • 回る歯車などの上に、上から速く落ちてくる小さな物は、DETPHYS_BODY_FLAG_BULLET（Unity は body の flags）を付けると、めり込みが減ります（歯車の上で 28 mm → 5.5 mm）。
  • 動く形そのものが速くてすり抜ける時は、bullet ではなく分割（3. コンセプトの max_subticks・subtick_move_mm）で防ぎます。

#12. 動く足場の上の物は眠らない — ターン制は tick 数でターンを終える

  • 動いているキネマティックの上に乗った物は眠りません。ターン制で「落ち着いたら（全部眠ったら）ターンを終える」ルールにすると、上限の tick（max_ticks_per_turn、既定 900）まで終わりません。
  • 動く足場を使うターン制のゲームは、after_tick で ctx->tick（このターンで進めた tick 数）を見て、決めた tick 数でターンを終えます。
  • 3D（detphys_turn_create_rule3d_kinematic）も同じです。動いているキネマティックは起きているボディに数えるので、落ち着いた（settled）になりません。

#13. キネマティックの表を変えるのは begin の中だけ

  • キネマティックの表（add / bind / unbind / clear）はロールバックで戻らないので、変えるのはルールの begin（ターン制は begin_match）の中だけです。
  • 試合の途中で動きを変えたい時（スイッチで歯車が回り出すなど）は、動きそのものを tick の関数にします: POINTS で止まる区間を作る、CALLBACK で tick から決める。ゲームの状態（状態ワード）を動きのコールバックに渡す形は（予定）です。
  • CALLBACK は整数だけで計算し、同じ tick には必ず同じ値を返します（ロールバックで何度も呼ばれます）。
  • 3D の表（detphys3d_kinematic_add / bind / unbind / clear）も同じです。3D の CALLBACK は位置 [µm] と整数の四元数を返し、続けて回すなら前の tick と同じ側の四元数を返します（tick の間の回転は短い方の向きにとります）。

#14. 1 つのワールド・セッションは 1 つのスレッドから使う

コアは、1 つのワールド（とセッション）を同時に複数のスレッドから呼ぶことを想定していません。ワーカーはコアが自分で使います。

#確かめ方

  • 1 台の中の 2 人（ループバック）に、テスト用のトランスポートで遅れ・取りこぼしを入れて長く回し、確定した tick のハッシュが両方で同じか見ます。
  • テスト用の関数 detphys_rt_debug_nudge_at / detphys_turn_debug_nudge_at で、わざと 1 ULP ずらして、照合と再同期が働くか確かめられます（製品の遊びには使いません）。
  • desync デバッガーを ON にして PC と Android で回し、報告が出ないことを見ます（5. desync への対処）。
