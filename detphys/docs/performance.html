Performance

The most expensive part of rollback is "when a prediction was wrong, go back N ticks and simulate N ticks again". DetPhys sets its budgets by whether that fits in one frame. The number of bodies and the prediction window N are settings. Use the numbers below to choose the bodies, shapes and N for your game.

#Budgets (fit one frame in 4 ms)

DeviceBudget
Mid-range PC60 Hz, 200 concave dynamic bodies, N = 10 (re-simulate 10 ticks in one frame) within 4 ms
Mobile (Galaxy S9 class)60 baked concave bodies with N = 10, or 100 bodies with N = 6, within 4 ms
  • Devices: PC = Core i7-12700F / Windows 11 / power plan "High performance"; Galaxy S9 = SC-03K / Snapdragon 845 / Android 10.
  • "One frame" = restore N ticks back → re-simulate N ticks (taking a dyn snapshot into the ring on each) → advance one tick, averaged over 300 frames, with every body awake: the worst case.
  • In real matches mispredictions are rarer and roll back fewer ticks, so the average is a fraction of this (see "Real sessions" below).

  • Bodies that fit N = 10 in 4 ms on the S9: about 124 hand-made compounds, about 70 baked steiner shapes, about 60 baked hm shapes. For 100 bodies, N ≈ 6.3–6.7.

  • Taking snapshots only on confirmed ticks gives 2.98 ms (steiner) and 3.45 ms (hm) for 200 baked bodies on the PC (4 workers).

#Engine layer cost

Creating a scene of 116 bodies, running 600 ticks and hashing: Unity Editor 14–16 ms (2022.3 also 14.5–15.3 ms), S9 APK 54–58 ms; Godot (headless) 15–17 ms, S9 55–75 ms; Unreal (UE 5.8.4 editor, -nullrhi) 14.7 ms. The hash is the same in every engine.

#Tuning

KnobEffect
Body count, convex polygon countThe biggest effect. A larger baker epsilon_px gives fewer polygons
Prediction window N (max_prediction)Smaller means a lighter worst frame; too small means more waiting with distant peers
Input delay, automatic input delayFewer mispredictions (traded against the feel of zero delay)
Workers (worker_count)Helps with about 200 concave bodies; with few or simple shapes 1 worker is faster. The hash does not change
Snapshot kinddyn (default) is faster for real time. Raise snapshot_base_slots if shapes change often
Hash check interval (hash_interval)Every tick by default; hashing costs little
Splitting of moving concave shapes (max_subticks, subtick_move_mm)A split tick costs that many steps. Slower motions or fewer splits are lighter (traded against the tunneling speed). In 3D the fastest point is measured with the shapes' bounding radius, so large spinning platforms split more
Desync debuggerZero when off (default). 5–20 µs per tick when on (3D with about 70 bodies: 15–19 µs on a PC, about 175 µs on an S9)
