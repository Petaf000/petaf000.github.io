#3D sessions (version 8)

The turn flow, hash checks, resync, rejoin, host restart and the guest's per-turn checkpoint are the same as in 2D; the world is 3D (detphys3d.h). The config's world and meshes are not used (mesh_count must be 0); register convex hulls in begin_match with detphys3d_world_add_hull, in the same order on both peers. State sent to another peer (resync, joining) uses detphys3d_world_transfer_*. Pass a 3D kinematic table with detphys_turn_create_rule3d_kinematic in detphys3d_kinematic.h (the 2D table of detphys_turn_create_rule_kinematic cannot be used in 3D). A moving kinematic body keeps the world from settling, so end turns in after_tick by tick count or similar. The desync debugger (detphys_turn_set_debug) works in 3D too (when detphys_debug_abi_version() is 3 or later; recordings use the 3D format and reports the 3D fields; see 5. Troubleshooting desyncs).

#Peers whose config check does not match (version 9)

Peers whose settings, rule, shapes, hulls, kinematic tables or core version differ do not connect (packets whose config check tag does not match are dropped). Since version 9 (rt: version 7) the session counts those packets and exchanges the tag contents (one hash per part) with that peer, so you can tell which part differs. Read it with detphys_turn_get_tag_info (rt: detphys_rt_get_tag_info); both fill the same struct, detphys_tag_info. The tag values themselves, the existing structs and the protocol are the same as in version 8 (rt: 6). How to read it and what to fix is in 5. Troubleshooting desyncs.

Field (detphys_tag_info, 136 B)Contents
struct_sizeSet to sizeof(detphys_tag_info)
flagsSEEN 0x01 (a mismatching tag arrived), REMOTE_KNOWN 0x02 (the peer's contents arrived), PEER_KNOWS 0x04 (the peer got ours), ACTIVE 0x08 (not connected yet)
local_tag, remote_tagOur tag and the last mismatching peer tag (rt sends only the low 32 bits; before the contents arrive, rt's remote_tag is those 32 bits. Turn-based: 0 when only the session_id differs)
mismatch_packetsNumber of packets dropped because the tag did not match
diff_partsParts that differ (OR of DETPHYS_TAG_PART_*; only with REMOTE_KNOWN. 0 means all parts are equal and only the whole tag differs)
dimensions, remote_dimensions2 or 3 (the peer's only with REMOTE_KNOWN, otherwise 0)
local_version, remote_versionCheck version × 65536 + protocol version (rt: 3 and 3, turn-based: 6 and 4)
local_shape_count, remote_shape_countNumber of shapes (2D: registered shapes / 3D: hulls)
first_shape_diffIndex of the first differing shape (the first DETPHYS_TAG_MAX_SHAPES = 64 are compared; if only the counts differ, the smaller count; −1 = none or unknown)
local_parts[8], remote_parts[8]Hash per part ([i] is part 1 << i; 32 bits, independent of build and device; entries after 5 are 0)
info_sent, info_receivedHow many times we sent our contents / received the peer's (usually 1–2 per side)
Part (DETPHYS_TAG_PART_*)detphys_tag_part_nameContents
VERSION (0x01)versionThe core's check and protocol versions, 2D / 3D
CONFIG (0x02)configsession_id, tick rate, substeps, gravity, 3D contact tuning, turn-based first mover and tick limit per turn
RULE (0x04)rulerule_id, input and state word counts, params
SHAPES (0x08)shapes2D: checksums of the registered shapes (.dnshape) / 3D: checksums and vertex counts of the hulls registered in begin
KINEMATIC (0x10)kinematicThe kinematic table (whether one was passed, flags, contents after begin)

DETPHYS_TAG_PART_COUNT is 5; unknown values are named "unknown". Flags: rt uses DETPHYS_RT_FRAME_TAG_MISMATCH (0x200) in detphys_rt_frame.flags; turn-based sessions use DETPHYS_TAG_INFO_ACTIVE in flags. Both reads can be called at any time (every frame is fine) and return 0 on success, negative for NULL or a wrong struct_size.
