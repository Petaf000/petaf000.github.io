detphys3d.h3D world, bodies, convex hulls, snapshots, transfers (version 2)

The physics base is Box3D. It follows the 2D style (detphys.h, detphys_body.h) and reuses the 2D errors (DETPHYS_ERR_*), worker job types, snapshot kinds and detphys_snapshot_info / detphys_snapshot_stats. Lengths are mm, speeds mm/s, angular speeds mrad/s, forces mN, torques mN·m, materials × 1000, all integers. Orientations are integer quaternions (qx, qy, qz, qw; any length, the core normalizes them; pass a float quaternion multiplied by DETPHYS3D_QUAT_ONE [2^30] and rounded; 0, 0, 0, 0 = no rotation), so no trigonometry is used.

  • A full snapshot can be restored into another world that created the same shapes in the same order, but if the shape registry order differs it returns DETPHYS_ERR_FORMAT (the world is unchanged). To send state to another peer, use a transfer (sessions do this automatically).
  • Restoring a full snapshot with detphys_world_snapshot_restore / detphys3d_world_snapshot_restore always starts a new shape version (shape_version in detphys_snapshot_stats), even for an image taken by the same world, because an image from a world in another process cannot be told apart. The result and the hash are unchanged. If your own rollback ring mixes full and dyn snapshots, the first dyn after restoring a full one takes a new base, which costs about one full write. The core sessions (real-time and turn-based) only restore their own images and do not pay this.
  • Images and transfers are the same bytes on x64 and arm64 (iOS and 32-bit are not checked yet).
  • Not available yet: joints, sensors, contact events, ray queries.
  • The desync debugger can record 3D worlds (detphys_debug_record3d in detphys_debug.h above).
  • 3D moving concave shapes are in detphys3d_kinematic.h, next.
