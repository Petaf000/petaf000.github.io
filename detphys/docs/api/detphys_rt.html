#Built-in rule: push (version 5)

A real-time rule where two players (circles) push boxes and concave shapes with a 2-word input [move −100..100, buttons (1 = jump, 2 = dash)]. The callbacks live inside the core (C++), so an engine only creates the session. Unity's DetPhysRtSession.CreatePush and Godot's DetPhysRtSession.create_push call it too. With the same settings, every engine and device produces the same confirmed-tick hashes, so they connect to each other. A moving field (field) adds a spinning gear (DETPHYS_RULE_PUSH_FIELD_GEAR), a sliding platform (PLATFORM) and a lift (LIFT) made of concave shapes; the session creates and owns their kinematic table.

#3D sessions (version 6)

The tick flow, prediction, rollback, hash checks, resync, rejoin and automatic delay are the same as in 2D; the world is 3D (detphys3d.h). Differences:

  • World settings are a detphys3d_world_desc. The config's world, meshes, worker_count and snapshot_base_slots are not used (mesh_count must be 0); register convex hulls in begin, in the same order on both peers (their contents are part of the config check).
  • Full snapshots are recommended for the state ring (detphys_rt_config_default3d sets FULL). The checked hash is detphys3d_world_hash plus the state words.
  • Resync and rejoin send a transfer (detphys3d_world_transfer_*, which also carries the shape registry and the hull table), so the receiver can restore even when its registry drifted during prediction.
  • The desync debugger (detphys_rt_set_debug) works in 3D too (when detphys_debug_abi_version() is 3 or later; recordings use the 3D format and reports the 3D fields; see 5. Troubleshooting desyncs).
  • Pass a 3D kinematic table with detphys_rt_create3d_kinematic in detphys3d_kinematic.h (see the detphys3d_kinematic.h section below).

#Built-in rule: 3D push (version 8)

A 3D real-time rule where two players (spheres) push boxes, spheres and convex hulls (6 kinds made from the seed) inside a floor with four walls, with a 3-word input [move x, move z (−100..100), buttons (1 = jump, 2 = dash, 4 = drop a box)]. As with the 2D push rule, the callbacks live inside the core (C++), so an engine only creates the session. The params and rule id are the same as the C# rule of Unity's "3D push" sample, so with the same settings the confirmed-tick hashes are the same and those peers connect. With the turntable (field = DETPHYS_RULE_PUSH3D_FIELD_TURNTABLE) a concave table (a 16-sided disc with three low walls) spins as a function of the tick; the session creates and owns its 3D kinematic table (read it with detphys_rt_kinematic3d).

detphys_rt_create_push3dCreates a 3D push session (the simplest entry point; NULL world settings = defaults; with the turntable it also creates the table and destroys it with detphys_rt_destroy). NULL on failureUsage: Quick start › 3D push (Box3D, real time, zero input delay)
