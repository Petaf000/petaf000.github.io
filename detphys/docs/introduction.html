Overview

#What DetPhys is

Physics that gives bit-identical results for the same settings and the same inputs on every device and in every engine, and netcode built on it (turn-based and real-time rollback). Windows and Android, Unity, Godot and Unreal can run the same match with the same values.

  • Peers send inputs only: 32–48 bytes per tick one way in real time.
  • Every tick (every turn in turn-based play) the state hash is compared with the other peer. A desync is found at once and repaired from the host's state.
  • When peers desync, the desync debugger shows which tick, which body, which value and how many ULPs apart, and whether the cause is the input or the physics.
  • Concave shapes (gears, U shapes, combs, creature silhouettes) are baked from images into sets of convex polygons and used without approximation.
  • Moving concave shapes (spinning gears, sliding platforms, lifts) move as functions of the tick. A rollback rebuilds them bit for bit.
  • Both 2D (Box2D v3) and 3D (Box3D) worlds run in the same sessions.
  • The core is C++ exposed through a C ABI. The Unity, Godot and Unreal layers are thin layers over the same prebuilt core (detphys_core).

#What kind of game it suits

  • Stacking battles where players take turns dropping shapes onto a pile (turn-based)
  • Action games where players push and throw things, and platform fighters (real time, zero input delay)
  • Action games on spinning gears and moving platforms (moving concave shapes)

#What it does

FeatureContents
Deterministic 2D physicsA world on Box2D v3.2.0. All inputs are integers. A state hash every tick
Deterministic 3D physicsA world on Box3D (detphys3d.h). Boxes, spheres, capsules and convex hulls. Orientations are integer quaternions
Turn-based sessionsTwo players take turns. On a desync the host's state is sent (resync). Rejoins and host restarts continue the match. 2D and 3D. Built-in rule: stacking
Real-time sessionsRollback with zero input delay by default. Prediction window N (default 10). Automatic delay (off by default). Resync and rejoin. 2D and 3D. Rules in C, C++, C# or GDScript
Built-in push ruleA real-time rule where two players push boxes and concave shapes (2D detphys_rt_create_push, 3D detphys_rt_create_push3d). An optional moving field: a spinning gear, a sliding platform, a lift. 2D works across all three engines, 3D between Unity and Godot
Moving concave shapesFive motions: spin, ping-pong, orbit, points and callback. Only fast ticks are split, so nothing tunnels through. 2D (detphys_kinematic.h) and 3D (detphys3d_kinematic.h)
Concave shape bakerIn the editor (Unity: Window > DetPhys > Shape Baker; Godot: the DetPhys Shapes dock; Unreal: right-click a texture > Bake DetPhys Shape): images to sets of convex polygons (.dnshape, integer mm), the same bytes in every editor. Decomposition: Steiner (default) or Hertel-Mehlhorn

LAN UDP, a relay you run on your own server (detphys_relay) and an in-process loopback come with it. EOS P2P (Epic Online Services; the EOS SDK comes from Epic) on Windows and Android in Unity and Godot, and on Windows in Unreal
Workers1–64 (default 1). The hash does not change with the count. Your engine's job system can be plugged in
  • A session has two players (peers 0 and 1).
  • Over the internet, play through EOS P2P (EOS P2P; no server of your own) or a relay on your own server (8. Transports and room codes). Any other transport plugs into detphys_transport.

#Not included in this version

These are planned; no version is promised yet.

  • Steam transport. On Steam, plug your own transport into detphys_transport, or use EOS P2P or your own relay.
  • EOS P2P on iOS (Unity and Godot) and EOS P2P on Android in Unreal. LAN UDP and your own relay work there.
  • Unreal on iOS, and the engine layers on macOS. The Unity package includes a macOS library, but it has not been tested in the Unity Editor or in Players on Mac yet.
  • Unreal: the desync debugger in 3D, and Blueprint nodes for every feature. Some features are used from C++ through the core's C ABI there (What each engine offers).
  • wasm.

#What it does not do

  • No physics engine written from scratch. The physics is Box2D v3 / Box3D.
  • No triangle tests between freely moving concave meshes. Concave shapes are sets of convex polygons; moving concave shapes are kinematic, following a motion you define.
  • No servers run for you. It is P2P: one side listens, the other connects. Over the internet, use EOS P2P, your own relay or another transport.
  • No art or audio assets. Sample shapes are drawn procedurally.

#About 3D

3D (Box3D) covers worlds (detphys3d.h), turn-based sessions (detphys_turn_create_rule3d), real-time sessions (detphys_rt_create3d), moving concave shapes (detphys3d_kinematic.h) and the desync debugger. Every tick is identical on five PC builds and a Galaxy S9, and matches between a PC and an S9 (with loss, nudges, rejoins and host restarts) matched too. See 3. Concepts for how to use it and detphys3d.h in 7. API reference for the functions.

  • Bodies resting on a spinning platform in 3D slowly slide outward (a property of Box3D's contacts; see 3. Concepts).
  • The state sent on a resync is 190–260 KB for 115 bodies.
